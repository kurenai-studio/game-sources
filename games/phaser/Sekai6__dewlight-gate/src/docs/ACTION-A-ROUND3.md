## 架构

```text
游戏状态 / ActorInput（模拟时间、动作实例、速度、支撑平台）
  ↓
移动基础层 → 战斗覆盖层 → 受击反应层
  ↓                 各层独立 Animator / age / weight / mask
身体伸缩限制 → 仿射层级计算 → 刚性武器约束
  ↓
支撑约束（整体骨盆修正 → 双腿 IK → 脚掌滚动）
  ↓
装饰跟随（披风、灯、冠叶、翅膀）
  ↓
最终 WorldPose → 固定尺寸局部 Canvas → 游戏 Canvas / WebGPU 后处理
```

### 核心接口与过渡

- `core.ts` 的 `AnimationLayer` 独立持有播放器、时间、权重、开关与遮罩。`ActionActor.draw` 保留原接入接口，固定按基础、战斗、反应顺序合成，再处理支撑和跟随。
- 移动中的地面挥剑使用上身遮罩，下身继续走跑。稳定攻击实例与移动状态分离，腾空和落地不会重新触发挥剑。受击立即清除战斗层权重，恢复期间继续基础层。
- `TransitionProfile` 分别指定平移、旋转、缩放与透明度的惯性衰减时长。旧的 `Clip.transition` 仍兼容，作为四种通道的默认时长。
- 惯性偏移使用有限区间五次多项式，匹配切换时的位置与速度，结束时偏移、速度与加速度归零。连续打断从当前输出重新求偏移，不缓存某个旧动作的固定起点。
- 普通旋转沿最短弧；标记 `unwrapped` 的剑轨保留连续转动方向，不强行折回 ±π。
- `PoseBuffer` 复用固定形状的姿态对象；`CompiledClip` 缓存有效骨骼与通道轨道，`worldPose` 原位写入已有最终姿态。首次加载片段会建立缓存，逐帧采样不再创建整份姿态。
- 各层只消费 `ActorInput.clock`。相同时钟不推进动作、弹簧、脚步和拖尾；时间回退、传送、重生通过统一 `reset` 清除播放实例、惯性、脚锚与轨迹。

### 角色结构与动作

`RigDefinition` 描述每个物种的比例、关节位置、腿长、步幅、膝盖方向及分层素材，共用采样和渲染器。

| 角色 | 本轮重点 |
| --- | --- |
| 灯剑旅者 | 横甩斩与上挑分开塑形，反向蓄势、肩胯错峰、空中团身展开；剑轨在原 85 ms 命中点发力；按下降速度分配落地压缩 |
| 苔影 | 较低髋部、后足压缩、身体伸展扑出、前足承接与逐步恢复 |
| 玻璃蛾 | 独立腹部和前后翅，收翼后仰、俯冲展开、制动回摆与受击侧翻 |
| 露冠守卫 | 独立长根足与宽肩，持续冲锋、举身下挥、接触压缩及较慢恢复；冠叶延迟回弹 |

- 走跑共享以实际地面位移累计的步态相位，排除腾空、传送与冲刺。敌人以实际位移反推速度。支撑点随移动平台位移更新。
- 停步先完成摆动脚落地，转身保留世界支撑锚点；骨盆统一调整后求解双腿，避免腿根分离。
- 肩、肘、膝、踝增加重叠遮盖。肩肘遮盖使用布料折面并放在相邻肢体之后，避免明显的机械球关节。
- 躯干、髋与头的最终局部伸缩限制在 85%–115%。完整仿射矩阵保留非等比缩放后的关节连接；剑柄跟随腕部，剑身使用单位正交矩阵保持刚性。
- Canvas 合成面仍按最大边界预分配（普通角色 512×512、守卫 1024×1024），持续播放不扩张；Atlas 启动时生成并缓存。
- 局部 Canvas 在首次绘制时缓存固定部件顺序，每个部件直接设置绝对仿射矩阵，省去重复的 `save/translate/rotate/restore` 与逐帧展开部件数组。
- 刀光由真实剑尖和握柄轨迹组成，速度控制明暗与线宽。切换动作、攻击实例、受伤或单步超过 65 ms 时断开历史，避免低帧率产生横跨无关姿态的大片光面。
- 减少动态保留肢体表达、收翼动作与预警，移除额外残影、粒子和装饰弹性；不新增命中停顿或镜头震动。

完整游戏套件也覆盖真实输入通关、Boss、技能、资源去重、刷新续玩、多窗口与高分屏。原生 WebGPU 测试实际执行提交、绘制、跨地区、缩放和设备丢失回退；本机该项通过，未记为跳过。

### 性能方法

`scripts/action-a-round3-performance.mjs` 顺序启动独立 Chromium，分别访问改造前的 5177 和当前的 5173；1440×900、dream 画质，预热 2 秒，每场景采集 360 个 rAF。主控、苔影、玻璃蛾和守卫使用相同的三秒动作输入循环，完整世界模拟与绘制保持运行。

- 主线程处理：Phaser `prestep` 到 `postrender`，不包含等候下一帧的空闲时间。
- 动作计算：`ActionActor.draw` 调用耗时，包含采样、层合成、约束和动作装饰。
- 绘制：`prerender` 到 `postrender`，包含角色局部合成和场景 Canvas 绘制。
- 帧间隔：独立 rAF 采样，报告 P95，不能等同于 CPU 处理时间。
- 分配：另开 2 秒 CDP 堆采样，包含期间被回收的对象；报告采样估算字节，不冒充精确分配总量。`PoseBuffer` 构造计数另行记录，区分姿态缓冲与其余短生命周期对象。
- 稳定性：对照纹理与显示对象数量；跨花园长时间探索另有浏览器回归。固定合成画布与角色部件不随动作创建。

结果与环境限制见 `performance.json`。这是同机无录像负载的自动化比较，并非所有显卡或显示器的性能保证。最终视觉风格仍需用户确认。

一次定稿复测中，苔影场景为 4.9 → 5.4 ms，增幅 10.2%，未满足预算。该次原始结果保留为 `performance-before-canvas-optimization.json`；随后减少 Canvas 状态切换，再以同样流程复测，最终结果以 `performance.json` 为准。

### 最终性能结果

| 场景 | 主线程 P95：基线 → 当前 | 增幅 | 帧间隔 P95：基线 → 当前 | 动作 P95：基线 → 当前 | 绘制 P95：基线 → 当前 |
| --- | --- | --- | --- | --- | --- |
| 主控跑跳战斗 | 4.9 → 5.1 ms | +4.1% | 33.4 → 33.4 ms | 0.3 → 0.3 ms | 4.1 → 4.1 ms |
| 苔影 | 4.8 → 5.1 ms | +6.3% | 33.4 → 33.4 ms | 0.3 → 0.4 ms | 3.8 → 3.9 ms |
| 玻璃蛾 | 4.5 → 4.6 ms | +2.2% | 33.3 → 33.3 ms | 0.3 → 0.3 ms | 3.7 → 3.7 ms |
| 露冠守卫 | 5.6 → 6.0 ms | +7.1% | 33.4 → 33.4 ms | 0.3 → 0.3 ms | 4.6 → 4.9 ms |

四场景均满足主线程 P95 ≤+10%、帧间隔 P95 ≤+5%。该无头浏览器环境的 rAF 约为 30 Hz，不能由此推断桌面显示器只能运行 30 fps。

每个当前版本场景记录到 437 个已构造姿态缓冲，采样期间新增均为 0；纹理及显示对象前后相等。ACTION-A 调用栈归属的两秒分配估算分别为：主控 5.60 → 4.48 MB、苔影 3.89 → 3.64 MB、玻璃蛾 5.16 → 4.74 MB、守卫 5.61 → 4.03 MB。这些是堆采样估算，包含其余短期对象，不表示模块已经零分配。
