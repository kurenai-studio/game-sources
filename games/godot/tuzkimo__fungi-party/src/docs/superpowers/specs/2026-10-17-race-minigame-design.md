# 障碍赛跑（第二款小游戏）设计文档

日期：2026-10-17
状态：已实现（2026-10-18，见 docs/perf-log.md 的 v3 一节）
父文档：`docs/superpowers/specs/2026-10-17-fungi-party-design.md`（v3 的第一款新小游戏）

## 1. 这是什么

森林里办一场赛跑。四个菌子从同一条直道起跑，跑到 220m 外的终点；路上有固定障碍、矮栏和横穿赛道的森林小动物，走的时候**绕开**。先到终点的人赢，名次换蘑菇币。

它是 v3「体力 + 一天」的第二个可玩内容：v3 的体力预算按「一天能玩几局」反推，局数得靠多个小游戏撑着，这一个和「上课偷吃大赛」凑成两种完全不同的节奏（一个坐着按，一个跑着躲）。

## 2. 目标 / 非目标 / 反目标

**目标**
- 15 秒能讲清规则，3 局之内能明显变强（因为学会了读障碍）。
- 好玩的部分是「边跑边找缝」，不是「手速」。
- 一局 30~45 秒，比偷吃那局（90 秒）短，适合穿插着玩。

**非目标（这一版不做）**
- 弯道、多圈、跳跃平台、地形起伏。
- 跑者之间互相碰撞或推挤。
- 「打滑」这类第二种惩罚。全场唯一惩罚就是撞击。
- 道具、加速带、香蕉皮。
- 难度分层与体力消耗（属于 v3 后半段）。
- 音效。
- 排行榜存档、多人联机。

**反目标（做成了算失败）**
- 侧面进来的动物在撞上你之前一直不在画面里，玩家觉得「凭什么撞我」。
- 撞了之后镜头抖动或弹开太久，玩家丢了前方视野。
- 一局超过 60 秒。
- 障碍排得太密，怎么走都得挨一下——那就不是技巧，是运气。

## 3. 约束

- Godot 4.7.2、Mobile 渲染器；教室那套「纯逻辑模型 + 无头测试 + 自包含单场景」的写法照搬（模型不碰节点，能 `new()` 直接测）。
- 可调数字全部进 `game/config.gd` 的 `const`。
- 浮层、字体、按钮统一用 `game/ui/ui_style.gd`；POI 面板与 3-2-1 倒数沿用偷吃那局的实现方式。
- 障碍与小动物用内置 mesh 拼（球 / 胶囊 / 方块 + 描边材质），单个动物的部件数不超过蘑菇本体。
- 场景内不 `get_first_node_in_group`；森林侧的起跑线 POI 用每帧惰性查找。

## 4. 已经定下的（不留给 builder 决定）

**场景与视角**
- 单独场景 `game/minigame/race.tscn`，一条 **220m 直道、9m 宽**，两侧矮护栏（玩家撞不出赛道）。
- 第三人称镜头在脑后，**锁死朝前、不可旋转**，只跟随位置。冲刺或撞击时不做镜头抖动。
- 无弯道，无地形起伏，地面平整。

**玩家操作**
- 单指摇杆自由走 + 右下角两个按钮：跳、冲刺。
- 基础速度 6 m/s（现有跑速），撞了不会掉速，只有弹开+停顿。
- 跳：沿用现有跳跃（高约 1.5m），可以跨过矮栏。
- 冲刺：12 m/s 持续 0.3 秒，CD 3 秒，CD 期间按钮显示冷却。（冲刺撞到障碍照样弹开。）

**每局都不一样（硬要求）**
- 每局开局掷一次新种子（`randi()`），**不许写死、不许沿用上一局**；「再来一局」= 重新加载场景、重新掷。
- 由这个种子决定：每组障碍的位置/类型/缝在哪一侧、动物的出场顺序与时刻与从哪侧进、三个人机的抖动与冲刺/跳跃时机。
- 固定不变的是规则：赛道 220m×9m、障碍 70/20/10 的比例、速度与冷却、名次币。
- 验收方式：连续跑两局，截图/日志里的障碍布局与动物时刻必须不同（v2 就栽过「每局种子固定」这个坑，这次当头等验收项）。

**障碍**
- 比例约为 **70% 高障碍**（≥1.4m，跳不过去，只能绕）、**20% 矮栏**（0.6m，能跳过也能绕）、**10% 空档**（留出冲刺位）。
- 沿赛道每 12~18m 一组，同一组的横向位置留出一条能走过去的缝。
- 排布按每局随机种子生成，每局不同。
- 动物的横穿是**一条按种子生成的固定时间表**（相对起跑时间），不是按玩家距离触发：四个跑者面对的是同一批动物，才算同一条赛道。因此跑得慢的玩家会少遇到几只——这是可接受的（也是天然的追赶缓冲）。

**横穿赛道的小动物**
三种，都从赛道一侧横移进入、停在赛道上 1~2 秒、再横向离开：
- **胖甲虫**（基础款）：压扁的球当背壳 + 触角 + 短腿，慢速横移，停下时肚子一鼓一鼓。
- **屎壳郎推粪球**：前面一个比它大两倍的球，虫子在后面顶。**挡路的是球**，移动很慢。
- **松鼠**：横穿时丢下松果，松果留在原地变成一个小障碍（唯一会「留尾巴」的）。
- 三种都是高个子，跳不过去；只能等它走或从它身侧绕。
- **进场预警**：动物本体进入赛道前 1 秒，赛道上先出现它的影子（贴地的深色椭圆），影子从哪边来就说明它从哪边来。
- 动物的横穿时段必须离最近的那组障碍**至少 8m**（纵向），否则它可能正好堵在唯一的那条缝里，让这一组变成必撞——这是生成器要保证的硬约束。
- 松鼠丢下的松果：矮的（0.6m，可跳可绕）、**整局留在原地**，人机也要绕它。这是全场唯一会新增的障碍。

**玩家的物理**
- 玩家是真实的 `CharacterBody3D`：障碍、护栏、动物都是 `StaticBody3D`，跳起来靠真实高度跨过矮栏。
- 撞击判定 = `move_and_slide()` 之后读碰撞法线，撞到带 hazard 标记的物体就沿法线弹开 1.5m 并冻结输入 0.6 秒（不是靠物理反弹）。
- 复用 `Movement` 的加减速数学与 `MushroomMesh` 外观；**不复用** `Player` / `CamRig`（那个带环绕相机与森林手感），赛跑有自己的一套控制脚本。

**撞击**
- 撞到障碍或动物：沿来向弹开约 1.5m，随后 0.6 秒不能移动。只有这一种惩罚。
- 人机撞了也照样弹开。撞击次数会记进结算。

**四个人机**
- 三个对手各有一种性格，跑同一条赛道：
  - **贴边型**：贴着内边缘跑，路线最短，离障碍最近，撞得最多。
  - **稳中型**：走赛道中线，绕得早，速度稳定。
  - **冲动型**：频繁冲刺、爱跳，撞了也不改。
- 人机用纯逻辑模型驱动（每帧算横向目标位置与纵向前进），不依赖物理刚体；撞击判定与人机共用同一套障碍位置数据。
- 人机的横向策略里带一点随机抖动，不能看起来像在轨道上滑行。

**结算与货币**
- 玩家冲线立即结算；名次 = 已冲线顺序，未冲线的按当前进度排。
- 超时 120 秒强制结算，按进度排名（防止玩家原地不动卡住）。
- 蘑菇币：第 1/2/3/4 名 = 70 / 50 / 35 / 20，减去 5 × 撞击次数，最低 0。公式与偷吃那局一样写成纯静态函数并单测。
- 结算面板与偷吃那局同款：标题「第 N 名」、口数换成「用时 X 秒 / 撞了 Y 次 / +Z 蘑菇币」、两个按钮「再来一局」「回森林」。

**镜头跟随**
- 固定俯角与距离，**水平方向跟住玩家**（玩家横向移动时画面跟着平移），不做旋转、不做抖动。

**场内 HUD**
- 顶部一条横向前进条：全长 220m，四个小点（玩家一颗显眼的颜色）同时显示，一眼看出自己第几、还差多远。
- 右下角冲刺按钮带冷却环；跳按钮不带。
- 左侧一行小字：用时。冲线后不显示。

**进入方式**
- 森林里加一个起跑线 POI（一道拱门 + 地面起跑线）。走近弹出浮层：标题「森林赛跑」、三行玩法、「开始比赛」按钮。点按钮进场景。
- 进场景后 3-2-1 倒数，倒数期间不计时、不能移动。倒数结束才算起跑。

## 5. builder check 之后补的六条（都是我的 call）

设计文档写完后请一个没参与讨论的 builder 读了一遍，提出六个「不问就只好猜」的点，逐条定如下：

1. **动物的时机**：按种子的固定时间表，不按玩家距离触发（公平优先，慢的人少遇几只）。→ 见「障碍」一节。
2. **玩家的物理**：玩家走真实物理，人机走纯逻辑模型，两者共用同一份由种子生成的障碍数据。→ 见「玩家的物理」一节。
3. **动物不能堵住缝**：横穿时段离最近的障碍组至少 8m，写进生成器约束。→ 见「小动物」一节。
4. **场内 HUD 之前确实漏了**：补前进条 + 名次 + 用时 + 冲刺冷却环。→ 见「场内 HUD」一节。
5. **松果**：矮的、可跳过、整局留存、人机也要绕。→ 见「小动物」一节。
6. **镜头**：水平跟住玩家，固定角度，不转不抖。→ 见「镜头跟随」一节。

## 6. 留给 builder 决定

- 场景节点结构、赛道/护栏/拱门的具体尺寸与配色。
- 三种动物的几何拼法与部件数（只需「丑萌、圆、有描边、一眼能认出」）。
- 障碍的种子排布算法（只要保证每组留缝、组间距 12~18m）。
- 人机横向目标位置的具体数学（贴边偏移量、抖动频率、冲刺/跳跃触发概率）。
- 玩家与人机的数据流是共用一个 `racer` 模型实例还是各自一份。
- 冲刺与跳的人机观感细节（冲刺残影、跳跃落地压缩等）。
- 测试怎么拆（纯模型：进度、名次、撞击、币；场景层只靠截图与真机走查）。
