# Car Crash Simulator — дизайн-спека

Дата: 2026-10-29
Движок: Godot 4.7.2 stable (`G:\Godot_v4.7.2-stable_win64.exe`)
Язык: GDScript, без внешних ассетов и аддонов.
Запуск: из редактора Godot (импорт проекта → F5). Экспорт в .exe — вне scope v1.

## 1. Цель

3D песочница-автосимулятор аварий в духе BeamNG.drive: мягкая деформация кузова при
авариях, три машины, три карты, HUD, слоу-мо, свободная камера. Первая играбельная
версия (v1).

Критерий успеха: игрок выбирает машину и карту, разгоняется, врезается, видит
правдоподобное смятие кузова, счёт удара в км/ч, дым/огонь/искры; restarts одной
клавишей; управление с клавиатуры и геймпада.

## 2. Архитектура проекта

```
res://
  project.godot              # Godot 4.7, Forward+ рендер, input map
  scenes/
    main_menu.tscn           # выбор машины + карты, кнопка Start
    game.tscn                # корневой рантайм: карта + машины + HUD + game_manager
    maps/
      arena.tscn             # Арена
      town.tscn              # Городок
      speedway.tscn          # Трасса
    cars/
      car_base.tscn          # шаблон: chassis (RigidBody3D) + shell + wheels + effects
  scripts/
    autoload/
      GameContext.gd         # singleton: выбранная машина/карта, настройки, респаун-события
      TimeScale.gd           # singleton: слоу-мо (Engine.time_scale) с авто-возвратом
    core/
      vehicle_controller.gd  # аркадная модель вождения на раме
      soft_shell.gd          # verlet-клетка кузова: точки, пружины, разрыв, рендер
      shell_builder.gd       # генерация клетки из параметрического кузова (чистая функция)
      vehicle_params.gd      # Resource: параметры рамы + кузова (3 пресета)
      damage_model.gd        # зоны/HP по порванным пружинам, пороги эффектов
      camera_rig.gd          # преследование / капот / свободная орбита, тряска
      effects_director.gd    # искры, дым, огонь, осколки стёкол — подписка на события удара
      game_manager.gd        # спавн, респаун, счётчики ударов, пауза/меню
      input_router.gd        # единый слой ввода: клавиатура + геймпад
    tests/
      smoke.gd               # headless-смоук: грузит scenes, гоняет N кадров, NaN/bounds-ассерты
      crash_scenario.gd      # headless-сценарий: машина едет в стену, ассерт деформации
  resources/
    cars/sedan.tres, pickup.tres, sport.tres
```

Поток данных: `main_menu` → GameContext (выбор) → `game.tscn` собирает карту+машину →
`vehicle_controller` двигает раму → `soft_shell` симулирует клетку и порождает события
`spring_burst(zone)`, `impact(point, normal, speed_kmh)` → `damage_model`/
`effects_director`/`camera_rig`/`game_manager` потребляют события. HUD читает состояние
из game_manager и машины напрямую. Никаких циклических зависимостей: effects не знает
про soft_shell, только про сигналы.

## 3. Рама: аркадная физика

- `RigidBody3D` + `BoxShape3D` (габарит кузова минус колёса), центр масс занижен.
- `custom_integrate_forces` на каждом физика-кадре:
  - продольная сила: кривая мощности `power_band` (пик оборотов), газ/тормоз с
    максимальным замедлением `brake_decel`;
  - направление: скорость поворачивает к `heading` с `steering_response`; `heading`
    меняется от руля: `steer_deg * speed_factor(v)`, `speed_factor` падает к нулю к
    `max_speed` — на высоких скоростях руль «дубеет»;
  - ручник (Space / геймпад A) обнуляет продольную тягу задних колёс → управляемый
    дрифт;
  - гравитация стандартная; контакт с землёй — обычный Godot-коллайдер, плюс лучи под 4
    колёсами для визуального подвеса и отрыва (airborne flag → блокировка тяги).
- Колёса — простые цилиндры, поворачиваются передние, вращаются все; подвес =
  визуальное смещение колёс по лучу.

Параметры рамы в `vehicle_params.gd` (см. §8 пресеты).

## 4. Кузов: verlet-клетка (ключевая механика)

**Генерация (`shell_builder.gd`).** Кузов = параметрическая форма из 2 боксов
(нижняя половина + кабина, смещение/высота/скос капота и крыши). Каждый бокс
сэмплируется сеткой `nx × ny × nz` точек на поверхности. Удаление внутренних/
дублирующихся точек, привязка к рёбрам. Пружины:
- структурные: соседние точки по осям сетки (жёсткость `k_struct`);
- диагональные: по каждой грани ячейки (`k_shear`);
- анкеры: каждая точка к ближайшей «опорной» точке рамы, жёстко (`k_anchor`) —
  в покое кузов держит форму;
- базовые рёбра жёсткости: точки капота/крыши/багажника связаны с дальней стороной
  кузова (`k_bend`) — сопротивляются складыванию в банан.

Ориентир: ~300–420 точек на машину, ~4–5к пружин (см. §10 бюджет).

**Симуляция (`soft_shell.gd`).** Клетка живёт в мировом пространстве (не child-transform
рамы): точки имеют `pos/prev`, интеграция verlet с substeps (2 подшага на физика-кадр
при 60 Hz) и `relax_iters=3` релаксацией ограничений пружин. Демпфирование 0.99.
Разрыв пружины: если `|len - rest| / rest > break_strain` или `len < collapse_strain` —
пружина удаляется, сигнал `spring_burst(zone_of_spring)`. Анкерные пружины рвутся по
своему более высокому порогу (кузов отрывается от рамы, но вмятина уже в профиле).

**Столкновение с миром.** Пол: точки ниже `y=0 plane` выталкиваются на плоскость карты.
Препятствия: рама `RigidBody3D` c `contact_report`; на каждом физика-кадре для каждого
контакта берём точку и нормаль удара, и все точки клетки в радиусе
`impact_radius ≈ 0.8–1.2 m` проецируются на сторону нормали (`pos = pos + n * penetration`,
с откатом `prev` для сохранения импульса → пружины реально перерастягиваются и рвутся).
Статичные толстые стены дают penetration из формы препятствия, лучей достаточно для
тонких объектов (отбойники): тонкие коллайдеры дополняются raycast из предыдущей позиции
точки.

**Рендер.** `ImmediateMesh`/`ArrayMesh` обновляется каждый кадр: вершины = точки клетки,
треангуляция из сохранённой связности; нормали через кросс-продукты граней; материал —
металлик с per-zone тонировкой повреждений (потемнение). Стёкла — отдельные полигоны
внутри той же сетки, при разрыве соседних пружин скрываются (осколки-частицы).
Производительность: пересборка mesh ~400 вершин — тривиально.

Зоны: x<front_break → front; x>rear → rear; |z| side split по нормали; roof = точки
кабины верхнего пояса.

**Стабильность (главный риск).** Лечение: substeps, релаксация ограничений, срез
максимальной скорости точек (`max_point_speed`), запрет растяжения более `2*rest_len`
(мгновенный разрыв вместо взрыва),NaN guard в смоуке.

## 5. Урон, эффекты, слоу-мо

`damage_model.gd`: зона = доля порванных пружин зоны (структ.+анкеров) → HP 100→0.
Пороги:
- `impact > 15 км/ч` → искры (GPUParticles, 1-shot, ориентация по нормали);
- `impact > 40` → тряска камеры (амплитуда ∝ скорости), звук-заглушка не в scope v1 (визуал);
- `impact > 60` → авто слоу-мо 0.3× на 1.2 реальных секунды + индикатор «удар X км/ч»;
- HP<60 → лёгкий дым из передней зоны; HP<25 → огонь + густой дым; HP=0 по любой зоне →
  «TOTALLED», дым+огонь перманентно до респауна;
- порваны анкеры крыши → гнущиеся/падающие точки крыши (это уже «складывание»).

`TimeScale.gd`: Engine.time_scale меняем только отсюда, с авто-возвратом к 1.0 по
`create_timer` (real time), ручной Shift удерживает 0.3× пока нажат. Физика Godot
масштабируется time_scale корректно (custom_integrate тоже), verlet использует
physics delta.

## 7. Карты и HUD/управление

**Арена**: бетонный пол 200×200 m, периметр — толстые стены 8 m; внутри: бетонные
столбы, отбойники (тонкие, raycast-обработка), рампа 25° (жёлтая), фонарный столб,
краш-боксы. Чистый полигон.
**Городок**: сетка 4×4 кварталов 30×30 m, здания = серые боксы разной высоты,
перекрёстки, столбы, припаркованные «боксы-машины» (статические объекты).
Ограничения скорости на карте — только антураж, не enforcement.
**Трасса**: прямая 600 m с разметкой, стартовая рампа-горка, отбойники по бокам,
на съезде — бетонный блок «стена» для лобового теста на 150+ км/ч; зона респауна на старте.

**HUD**: спидометр км/ч (число+дуга), полоса HP по зонам (5 сегментов), large-индикатор
последнего удара «CRASH @ X км/ч» с фадом, строка TOTALLED, подсказки клавиш в углу,
mini-меню (Esc → пауза). Шрифт — дефолтный Godot, моноширинный акцент для цифр.

**Управление** (input_router, actions в project.godot):
| действие | клавиши | геймпад |
|---|---|---|
| руль | A/D, ←/→ | левый стик X |
| газ / тормоз | W / S | RT / LT |
| ручник (дрифт) | Space | A |
| слоу-мо (hold) | Shift | B |
| камера (cycle: chase→hood→orbit) | C | X |
| респаун | R | Y |
| пауза/меню | Esc | Start |

## 8. Ошибки и крайние случаи

- NaN/взрыв клетки: guard — при детекте не-числа точки ресетятся на покоящиеся
  позиции относительно рамы; событие логируется.
- Машина вылетела за карту (< -50 y или > 400 m от центра) → авто-респаун с
  уведомлением «вылет — рестарт».
- Респаун: рама телепортируется на spawn point с обнулением скоростей, клетка
  пересоздаётся из `shell_builder` (полный сброс повреждений), HP=100.
- Выезд из машины не предусмотрен (v1: машина или камера).
- game_manager ловит `impact` и складывает счётчик + топ-удар сессии; при
  time_scale=0.3 индикаторы не должны «тикать» быстрее — все UI-таймеры в real-time.
- Геймпад отключён mid-game: Godot input map деградирует на клавиатуру без кода.

## 9. Тестирование

1. `tests/smoke.gd` (headless, `--quit-after` цикл): сцена game грузится для каждой
   комбинации карта×машина (9), 600 физика-кадров, ассерты: нет NaN в точках, все
   точки в bounds кузов+2 m до первого удара, `spring_burst` не срабатывает при
   спокойной езде по ровному.
2. `tests/crash_scenario.gd`: седан разгоняется scripted-input в стену арены,
   ассерт: ≥12 порванных пружин front-зоны, HP front < 80, рама остановилась;
   рендер `--write-movie` → проверка покадрово (вмятина видима).
3. Живой прогон в редакторе игроком: вождение, все 3 машины × 3 карты, геймпад.

Границы приёмки v1: звук отсутствует; AI-трафик отсутствует; несколько машин в мире
— одна играбельная (AI-машины как static boxes могут быть в городе, но не физика
движения).

## 10. Бюджет и метрики

- Физика-кадр: 3 машины×~400 точек×~5к пружин×(2 substep×3 iter) ≈ 6 млн spring-ops —
  GDScript может не потянуть на 60 Hz → mitigation: cell update выполняется на
  физика-кадре с одним проходом + relaxation по активным точкам (не всем) — точки в
  «покоя» состоянии (все пружины целы, клетка следует профилю рамы) не интегрируются:
  «sleep-оптимизация». После удара спят только удалённые от повреждения районы.
  Целевой метрик: >55 fps на 1 активной машине + 1 повреждённой; смоук-тест
  логирует ms на кадр симуляции, > 8 ms = red flag.
- Если sleep-версия всё равно медленна: снизить nx/nz сэмплинга (уменьшение точек) —
  качество вмятин vs fps решается вживую.
