# Setup Screen and Collection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The app opens on a setup screen where the player picks a picture from a bundled, generated collection, a style and a valid piece count over a live cut preview, starts or resumes a game, and returns from the board with Home or back; one script builds and installs the APK.

**Architecture:** A headless tool renders six abstract pictures and a manifest. A pure-where-possible `Collection` validates the manifest and loads textures. `Board` takes its puzzle, collection and resume flag from the caller and emits `home_requested`. `SetupScreen` (the main scene) owns the choices, a settle-timer preview through `CutPreview`, and the scene changes in both directions.

**Tech Stack:** Godot 4.7.2, GDScript, Mobile renderer, bash for the build script. Tests are plain headless scripts extending `BaseTest` or `BoardTest`.

**Spec:** `docs/superpowers/specs/2026-11-03-setup-collection-design.md`. Also read `INTENT.md`, `AGENTS.md` and `docs/visual-design.md`.

## Global Constraints

- Godot 4.7.2, GDScript, Mobile renderer. Android only. Package name `io.github.aaryash_shakya.pieceful`, do not change it.
- No new dependencies, plugins, autoloads or network calls.
- Manifest licences are exactly `"CC0-1.0"`, `"public-domain"`, `"CC-BY-4.0"`. Generated art: credit `"Aaryash Shakya, generated by tools/make_collection.gd"`, licence `"CC-BY-4.0"`, `"generated": true`.
- Resource existence is checked with `ResourceLoader.exists`, never `FileAccess.file_exists`: the APK holds only imported textures.
- The slider value is an index into `CutGenerator.valid_counts(width, height, 12, 400)`. No cut is generated while the slider is dragged; generation runs once when the 0.15 s settle timer fires.
- Warnings: `Collection: could not use` (whole manifest), `Collection: skipping picture` (one entry), `SetupScreen: could not resume` (save set aside). The board's existing `Board: could not use the save at` stays.
- Tests never touch `user://save/`. Board tests use `BoardTest.TEST_SAVE_PATH`; setup tests use `"user://test_setup/current.json"`. Tests read the bundled art only in `tests/test_collection_art.gd`; everything else uses `res://tests/fixtures/collection/manifest.json` or the `test-gradient` picture.
- Run `godot --headless --import` after adding any file with a new `class_name` or any new asset, then `timeout 300 godot --headless --script tests/<name>.gd`. A passing run prints `0 failure(s)` and exits 0.
- Match the surrounding code style, sparse comments that explain why. Conventional commits, one per task; include the `.uid` and `.import` files Godot creates.

## Review Focus

- A picture change to a shape where the current count is not valid (54 on a square picture): the count becomes the nearest valid one, ties to the smaller, and the slider index points at it (Task 5, `_test_picture_change_keeps_nearest`).
- Start or Resume pressed twice, or back pressed twice on the board: exactly one board, exactly one new setup screen (Task 6, `_test_start_twice_launches_once`; Task 4, `_test_go_home_runs_once`).
- A save file the setup screen cannot resume (corrupt, `test-gradient`, a picture whose size changed): no Resume card, the file is moved to `current.bad.json` with one warning, and Start then writes a fresh save (Task 6, `_test_unresumable_save_is_set_aside`).
- Resume of a save the board rejects deeper down (cut checksum drift): the board starts the same picture, style and count with the new seed, not the test gradient (Task 3, `_test_rejected_resume_falls_back`).
- A manifest picture whose texture has a different size from the manifest, and an empty collection: the picture is dropped with one warning and the next one is chosen; with none left the screen says "No pictures found" and Start is disabled (Task 5, `_test_broken_picture_is_dropped`, `_test_empty_collection`).

  - `const LONG_EDGE := 2048`, `const THUMB_LONG_EDGE := 256`, `const WEBP_QUALITY := 0.8`, `const CREDIT := "Aaryash Shakya, generated by tools/make_collection.gd"`, `const LICENCE := "CC-BY-4.0"`.
  - `const SPECS: Array[Dictionary]`, in this order, each `{"slug", "title", "aspect": Vector2i, "motif", "seed"}`: `ember-rings` "Ember Rings" `Vector2i(3, 2)` `"rings"`; `stained-glass` "Stained Glass" `Vector2i(2, 3)` `"cells"`; `tide-stripes` "Tide Stripes" `Vector2i(1, 1)` `"stripes"`; `confetti-field` "Confetti Field" `Vector2i(4, 3)` `"confetti"`; `prism-mosaic` "Prism Mosaic" `Vector2i(16, 9)` `"mosaic"`; `woven-plaid` "Woven Plaid" `Vector2i(9, 16)` `"plaid"`. Seeds are fixed distinct ints of the builder's choice.
  - `static func size_for(aspect: Vector2i, long_edge: int) -> Vector2i`: the long side is `long_edge`, the short `roundi(long_edge * short / float(long))`. 3:2 at 2048 is `Vector2i(2048, 1365)`, 16:9 is `Vector2i(2048, 1152)`, 9:16 is `Vector2i(1152, 2048)`.
  - `static func render(spec: Dictionary, size: Vector2i) -> Image`: `FORMAT_RGB8`, the spec's three layers (palette of six seeded hues, the motif with at least the region counts in the spec's table text, `FastNoiseLite` grain with `seed = spec.seed`, features about `size long edge / 170` px, brightness up to about 8%). All randomness from `SeededRng.new(spec.seed)`; positions and sizes as fractions of the long edge. Build pixels into a `PackedByteArray` and `Image.create_from_data`, not `set_pixel`, for speed.
  - `static func manifest(collection_id: String, title: String, long_edge: int) -> Dictionary`: the spec's manifest shape, one entry per spec in order, `id` `"<collection_id>-<slug>"`, `file` `"<slug>.webp"`, `width`/`height` from `size_for`.
- Produces `tools/make_collection.gd`, `extends SceneTree`: reads `OS.get_cmdline_user_args()` for `--out` (default `"res://assets/collections/abstract"`), `--id` (`"abstract"`), `--title` (`"Abstract"`), `--long-edge` (`2048`). For each spec: `render`, `save_webp("<out>/<slug>.webp", true, WEBP_QUALITY)`; the thumbnail is a copy resized with `Image.INTERPOLATE_LANCZOS` to long edge `mini(THUMB_LONG_EDGE, long_edge / 2)`, saved to `<out>/thumbs/<slug>.webp` the same way. Then `manifest.json` as `JSON.stringify(manifest(...), "\t", true)` plus a newline. Prints each path; on any error prints it with `printerr` and `quit(1)`; else `quit(0)`. Creates the folders.

## Owner checks

These need the phone or a person, so they are not task steps. Run them after Task 7.

1. **The pictures:** open the six files in `assets/collections/abstract/`. Each should look rich enough to solve: distinct regions, varied colour, texture everywhere. Say which to replace; the manifest makes that a file swap.
2. **Desktop:** `godot --path .` opens the setup screen. Drag the slider end to end: the count changes smoothly and the lines update once you stop. Switch between a landscape and a portrait picture: the count stays near where it was. Start, lock a few pieces, press Home: the Resume card shows that picture and count; Resume gives the same board.
3. **Phone install:** `tools/build_apk.sh` with the phone plugged in installs the app; the setup screen shows all six thumbnails (this confirms the manifest and pictures are in the APK).
4. **Phone, slider at 400:** with the frame-rate counter on, drag the slider fast and lift at the far right on the 16:9 picture: no stutter while dragging, and say whether lifting causes a visible hitch (if so, preview generation moves to a thread).
5. **Phone, back:** on the board, Back goes to the setup screen with the Resume card; Back again closes the app; reopening shows the Resume card.
6. **Phone, picture quality:** start a 400-piece game on each of two pictures and zoom in fully: edges and colours look clean (if blotchy, the import moves to VRAM compression). Note the APK size from `ls -l build/pieceful-debug.apk`.
7. **Phone, old save:** on the first launch of this build, the old `test-gradient` save is moved to `files/save/current.bad.json` (`adb shell run-as io.github.aaryash_shakya.pieceful ls files/save`) and no Resume card shows.
8. **Start without asking:** decide whether Start should ask before replacing a saved game.
9. **Phone, picture strip:** a sideways swipe on the strip reaches tiles 5 and 6, and a swipe never selects a tile.
10. **Phone, short screen:** on a short phone, a vertical swipe that starts on the strip or on the preview scrolls the page.
11. **Phone, slider grab:** the slider is easy to grab with a thumb, and releasing it at 400 pieces causes no visible hitch.
12. **Phone, tile tap:** say whether tapping a tile hitches while the 2048 px picture decodes.
13. **Phone, rapid Start:** tapping Start several times fast opens one board; Home returns to one setup screen.
14. **Phone, finished puzzle:** finish a puzzle, press Home: no Resume card shows.
15. **Phone, notch:** on a tall phone, Home, Tidy and the frame-rate counter sit clear of the notch and status bar.
16. **Phone, reinstall:** `tools/build_apk.sh` over an installed build keeps the app's save (the Resume card still shows afterwards).
