# 从第一手牌理解代码

## 一手牌怎么走

`start_hand()` 先确定庄家和盲注位置，洗牌，再绕桌逐张发两轮底牌。双人桌的庄家兼小盲，翻牌前先行动；翻牌后由大盲先行动。每个街道发公共牌前烧一张牌。

`act()` 接收座位、操作和加注总额，先检查是否轮到该玩家、操作是否有效，再扣筹码。每个仍能行动的玩家都回应后，才进入下一街道；不能仅靠“投入相同”判断结束，否则会漏掉大盲的加注机会。

四个下注阶段依次为翻牌前、翻牌（三张）、转牌（一张）、河牌（一张）。一人未弃牌时直接结算；至少两人仍在且河牌结束时摊牌。全押后若再无可争夺的新下注，就自动发完剩余公共牌。

## 三种筹码数为什么要分开

每个座位都保留 `stack`（剩余筹码）、`street_bet`（本轮投入）和 `total_bet`（整手投入）。

例如小盲已投入 5，点击“加注到 30”时再扣 25。翻牌后 `street_bet` 清零，整手投入仍然留在 `total_bet`，供最后分池使用。每次合法操作后，桌上所有剩余筹码加底池都应该等于开局筹码总和。

## 最小加注和短码全押

盲注 5/10 时，第一次最小加注到 20。如果某人加注到 30，加注幅度为 20，下一次最少加到 50，而不是机械地翻倍到 60。

筹码不够最小幅度时可以全押，但不足额的加注不会自动恢复已经行动过的玩家的加注权。多人桌连续出现几个短码全押时，程序按该玩家上次行动后的累计增量判断是否重新开放加注。

## 主池、边池与平局

假设三人分别全押 50、100、200，最后一位超出 100 的部分无人跟注，会退回 100。主池为 50 × 3 = 150，三人都有资格争夺；边池为 50 × 2 = 100，只由后两人争夺。

弃牌者投入仍在底池，但失去赢取资格。程序会合并争夺者完全相同的投入层，避免把弃牌筹码误拆为多个分池。平局分别平分每个实际底池，多出的整数筹码按庄家左侧开始的座位顺序发给平局者。

`evaluator.gd` 穷举七张牌中的 21 种五张组合，比较牌型及踢脚。A2345 按 5 高顺子处理；可完全使用五张公共牌；花色不打破平局。

下注、双人行动顺序及分池参照 [Poker TDA 官方规则](https://www.pokertda.com/view-poker-tda-rules/)。本项目是自动发牌的离线练习桌，不模拟真人赛事中的错发牌、裁判判罚、换桌或完整锦标赛盲注管理。

## 电脑为什么看不到你的牌

电脑只接收 `view_for(自己的座位)` 生成的深拷贝：自己的底牌、公共牌、公开筹码和操作，以及合法操作集合。该视图没有未来牌堆、烧牌或对手底牌，也无法通过修改它改变真实游戏状态。

电脑策略根据起手牌或已成牌型以及跟注压力粗略决策，加入少量随机性。它不是求解器。1.0 的“建议”入口另外提供随机范围下的胜率估算和启发式操作建议，规则讲解保留在“更多 → 本手行动记录”；两者均不宣称最优策略。

## 记录与复盘

每次行动以事件保存。完整一手结束后，JSON 写入 `user://hands`，包含初始筹码、盲注、庄家、起始牌堆、事件和结算。测试从磁盘读回 JSON，依次重放操作，并比对结算结果。

JSON 会把数字解析成浮点数，加载边界需要把牌编号、座位和金额转换回整数。当前测试覆盖这个过程。完整牌堆仅用于牌后记录，不通过电脑信息接口提供。

1.0 复盘界面可以从开始逐步重放，也可以按街道或自己的决策点跳转。建议重新生成该时刻的信息白名单，不能利用后续发出的牌或最终胜负。详细实现见 [复盘与建议设计](review.md)。

## 2–9 人选桌与布局

规则层从一开始用座位数组，支持 2–9 个座位；行动循环跳过弃牌、全押和空座位。当前通过 2–9 人随机规则模拟，另外跑过 2、6、9 人的电脑连续牌局。

启动时先显示选桌面板。快捷按钮支持 2、6、9 人，下拉框支持 2–9 人全部人数，均包含你自己。可以选择每人 50、100、200 BB 的初始筹码。重启后可恢复上次牌桌，已有完整历史不受新开桌影响。

你固定在下方，其余座位沿牌桌按顺序排列。金色边框是行动者，绿色边框是赢家，弃牌或出局座位变暗。底牌到摊牌时才公开；红桃和方块用浅红色，黑桃和梅花用浅色。紧凑座位里用 T 表示 10。较宽视口自动放大座位文字与面板。

游戏中点击“换桌”会暂停电脑定时器，修改人数并不立即影响当前桌。点击“返回原桌”继续原手，点击“重置筹码，开始…人桌”才创建新桌。被替换的未完成牌局不作为完整记录保存。已完成的历史记录保留。

每个电脑有独立的随机状态，轮流采用均衡、稳健、积极的倾向，策略会考虑当前未弃牌人数，但仍属于简单规则策略。

当前多人连续牌局采用移动庄家并跳过空座位的简化练习规则；缩减到双人时防止上一手的大盲重复下大盲。若要做多人锦标赛，需要另行实现死庄、淘汰衔接和盲注升级规则，不应宣称当前已是完整比赛管理器。

## 下注快捷操作

- 顶部“筹码 / BB”切换整桌、记录及输入的显示单位，真实筹码仍按整数保存。盲注固定 5/10，因此 2.5 BB = 25 筹码。切换不会改变已选金额。
- “最小”、2 / 2.5 / 3 / 4 BB、±1 BB 与滑条只选金额，之后还需点击下注/加注按钮。
- 1/3、1/2、满池按跟注后的底池计算加注幅度。例如底池 100，当前下注为 20、你需要跟 20，半池加注到 20 + (100 + 20) × 0.5 = 80。
- 所有档位会限制到合法范围；小于最小加注则提高到最小值，超出筹码则限制为全押。界面同时显示本轮总额与还需投入的筹码。加注权未重新开放时，快捷按钮也会禁用。
- 本桌最小筹码是 1，BB 输入可精确到 0.1 BB。系统同步 SpinBox 的数值与显示文字，避免快速切换单位时重新读取旧金额。

可以暂停牌局、选慢速/标准/快速电脑节奏，或开启“弃牌后快进”。下一手始终由你主动点击，便于先看结算。你输光或全桌只剩一人有筹码时，可按所选初始深度“补码重开本桌”。

1.1 将速度、弃牌快进和显示偏好集中到“设置”。先编辑草稿，点击“应用设置”后才更新牌桌；取消或返回键会丢弃修改。切换单位前保留输入框中刚输入的金额。偏好以临时文件加重命名的方式保存，旧设置自动获得新增选项的默认值。

全押保护默认开启，覆盖全押按钮、跟注耗尽筹码和加注至全部筹码三条入口。确认页展示额外投入与本轮总额；取消不修改牌局。重开牌桌始终确认，取消换桌也会取消临时人数/筹码深度。快捷键和电脑定时器在最上层页面打开时被统一阻断。

手机和电脑均为竖屏，从“更多 → 本手行动记录”查看讲解与记录。桌面快捷键为 F 弃牌、空格过牌/跟注、R 聚焦金额、P 暂停，在金额输入框内打字不会触发这些操作。

桌型、筹码深度、显示单位和电脑速度保存在 `user://preferences.cfg`，下一次启动时复用。用户可随时在选桌面板调整。

## 测试

运行 `tools/check.ps1`：资源导入、规则用例与 270 手模拟、原有 UI 集成、2–9 人选桌和电脑对战集成、完整牌局启动检查。多人 UI 测试运行 24 手，检查座位不重叠、不覆盖公共牌、筹码守恒、BB/筹码转换、底池快捷按钮、暂停、取消换桌和真实电脑定时器。测试同时覆盖 JSON 保存与重放。

截图工具参数：`-- --capture-test --players=9 --capture-state=flop`，或 `--capture-state=complete`。`--lobby` 捕获选桌页；手机和电脑默认使用相同的竖屏布局。输出在 `.local/`，可配合 Godot 的 `--resolution 1600x720` 检查宽窗口下居中的竖屏区域。Android 真机测试仍需要连接并授权设备。


## 1.2 手机竖屏

Android 默认竖屏。底部“加注”先打开面板，再选择 BB / 筹码和下注档位，点加注或全押才行动。收起与返回都不提交。

“更多”包含设置、换桌、历史、行动记录；多人桌可点座位看详情。完整历史牌局在竖屏以卡片呈现，点开即可复盘。复盘的牌桌与分析分为两个页签，保留当前步骤。电脑可用 `tools/run.ps1` 体验。真机验收暂缓。


## 1.2.1 统一方向

只维护竖屏交互。电脑默认 450×850，无需启动参数；放大窗口保留居中的竖屏游戏区域。所有弹层、设置与复盘都在这个区域内，调整窗口不关闭加注面板、不提交金额、不重置牌局或复盘步骤。方向切换按钮和仅用于横屏的侧栏开关已移除。

## 逐个配置电脑（1.6.0）

开桌页进入“对手 / 设置”，先点电脑座位，再分别选择“决策能力”和“行动风格”。“跟随默认难度”的座位会随对局页默认难度一起改变；指定入门、标准或进阶的座位保持独立。三个风格为均衡、偏被动、偏激进，激进不表示更强。多人桌可以混合配置，单独指定的座位在换人数后仍保留。

对局中点电脑座位 → 配置这位对手，也可从更多 → 设置 → 对手进入。应用后从下一次电脑决策生效，取消丢弃草稿。牌局历史记录配置变化点；从历史决策重打时使用当时的配置。当前桌和训练进度保存配置，恢复默认难度继承关系不会丢失。旧版没有配置元数据的历史使用当前设置。

“查看实测牌力与适用范围”包含本版本固定评测结果。BB/100 是平均每 100 手赚取的大盲数；95% 区间跨过 0 时，不能判定该对比有稳定优势。这些数据只来自注明的电脑阵容，不代表真人桌胜率。

## 训练室（2.1.2）

训练室由三部分组成：`scripts/ui/training.gd` 只负责外框和返回；`training_hub.gd` 是首页（开始按钮、四个主题掌握度、本组总结、练习记录）；`training_case.gd` 负责单题流程（作答 → 分析 → 结论卡 → 下一题，或用自己的选择打完这手）。

挑题、评级和复习都是 `scripts/poker/training_store.gd` 里的纯函数，只从已有的作答记录推算，不增加存储字段：

- `grade()`：把教练比较结果归为好的选择（与建议一致、参考混合打法）、可以接受（边缘决策、低频选择、金额不同）、偏离建议（不同选择）；下注尺寸不在求解范围时不评分。
- `review_due()`：出现过偏离的局面会在之后的练习中再出现；连续两次不偏离、且第二次在不同日期，才移出复习。
- `pick()`：每组最多先放两道到期复习题，再放没练过的局面（自己的牌局优先于内置局面，掌握度低的主题优先），最后补最久没练的局面。传入主题时只在该主题内挑选。
- `topic_name()`：把旧名称“加注尺度、跟注犹豫、诈唬判断”归入新的四个主题。

打完这手固定用 `Practice` 的 sampled 模式重新发未知牌，结果单独存为分支，不进入真实对局历史。测试见 `tests/training_test.gd`。
