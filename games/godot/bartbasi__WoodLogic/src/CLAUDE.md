# WoodLogic: rules for anyone working on it

WoodLogic is a free, open source screw puzzle for phones, made by Play, Inc. and designed by
Bart Basi. Godot 4.7.2, GDScript, Mobile renderer, portrait, Android first. The full kickoff
brief is PROMPT.md. Bart is the owner and approves every hard stop and playtest gate. Ask
before changing anything here, or LICENSE, NOTICE or other public material.

## Ground rules (not up for debate; if one blocks good work, ask Bart)

1. **Free, forever.** No ads, purchases, paid unlocks, store, rating prompts, or anything
   that interrupts play to ask for something. The only money link is Buy me a coffee.
2. **Nothing leaves the phone.** No internet, analytics, crash reporting, accounts, cloud
   saves or third-party SDKs. No network APIs in code (HTTPRequest, HTTPClient, StreamPeer,
   WebSocket, PacketPeer, UDP/TCP and the like). The Android build asks for no permissions.
   Progress lives in `user://` on the phone.
3. **Everything is made in code.** Every visual and sound is generated by our own code:
   shaders, `_draw()`, meshes or images built at runtime, audio synthesized into buffers. No
   image, audio, font or model files from anywhere. Only what ships inside Godot (such as its
   default font) is allowed. docs/ASSETS.md lists every visual and sound and how it is made.
4. **Original.** Study the reference games' mechanics from their public store descriptions
   only. Never copy their names, art, layouts, UI, text or sounds, and never download their
   screenshots, videos or files.
5. **Every level is solvable.** The game never shows a level its solver has not solved.
6. **Plain writing.** No em dashes and no double hyphens in any prose: docs, UI text, code
   comments, commit messages, store text. Write like a person.
7. **Keep it simple.** Nothing beyond the brief. Ideas for more go in docs/LATER.md.

**Logic and physics are kept apart.** The rules run on a pure logic model (`src/logic/`, no
Node dependencies). A swinging plank's rest angle comes from geometry, not simulation. Physics
and animation are for looks only and never decide a rule.

## How the team works

1. docs/ARCHITECTURE.md is the contract: the logic API, every signal, the data formats, the
   renderer interfaces and how themes are read. Build against it. If you need it changed, ask
   the lead; never change another area's code.
2. **Edit only the files you own** (table below). If two areas need one file, the lead splits
   it or makes the integration edit.
3. **Only the lead commits**, after tests pass and the code-reviewer approves. Agents use git
   read-only (status, diff, log, show).
4. Every agent brief states the task, the files it may touch, the docs to read, and the proof
   that it is done (a test, a screenshot, a command's output).
5. Extra scope goes to docs/LATER.md as a suggestion for Bart. Agents put ideas in their
   report and the lead adds them.
6. Priority for every decision and fix: security and bugs, then fun and readability, then
   polish.
7. When agents disagree, the lead writes it down for Bart instead of settling it silently.
8. Usage is limited: at most three agents at once, at most two of them on Opus. Follow up on
   the same work by resuming the agent (SendMessage), not by starting a fresh one.
9. The lead posts a short status at the end of each phase: done, verified, next, blocking.
10. Never install software without asking Bart. Nobody sets the CLAUDE_CODE_EFFORT_LEVEL
    environment variable: it overrides every agent's own effort setting.

## Running things

Godot lives in `C:\Tools\Godot` (`Godot_v4.7.2-stable_win64_console.exe` for the command line,
`Godot_v4.7.2-stable_win64.exe` for a window). Android SDK: `C:\Android\Sdk`. JDK 17.

- Tests: `bash tools/test.sh` (all) or `bash tools/test.sh <text>` (tests whose file path or
  name contains the text). Suites are `tests/<area>/test_*.gd` extending `TestCase`; each
  `test_*` method runs on a fresh instance. Exit code 1 on any failure or logged error, and
  on a filter that matches no test. Add nodes with `add_node()` so they are freed after the
  test.
- New or renamed scripts need an import before a `class_name` resolves:
  `C:/Tools/Godot/Godot_v4.7.2-stable_win64_console.exe --headless --path . --import`
  (tools/test.sh does this first).
- Play: `C:/Tools/Godot/Godot_v4.7.2-stable_win64.exe --path .`
- Headless runs use a dummy renderer that draws nothing. Screenshots need a windowed run.
- GDScript is statically typed: an untyped declaration is an error (project setting).
- Layout is in design units. The base viewport is 360 x 640 and stretches (`canvas_items`,
  `expand`) to fill the screen. On phones the width sets the scale, so one unit is at least
  one dp on any phone 360 dp or wider, and a 48 unit touch target is at least 48 dp.
