### Task 2 — deterministic destination allocation

**Files:** new allocation helper and `test_groups.gd`; simulation, existing simulation/movement tests.

**Interfaces:** `DestinationAllocation.assign(navigation: RefCounted, units: Array[Dictionary], target: Vector2, unavailable: Array[Vector2i]) -> Dictionary` is static/pure. Input units need `id` and `position`; output maps each ID to `Vector2` goal or `null`. Copy/sort inputs; never mutate them. Simulation constructor adds optional `size` after `blocked_cells` and forwards it.

Algorithm: sort IDs ascending. Only units sharing target's connected component can receive slots. If target is no longer walkable when queued command applies, all its effective members fail allocation. Enumerate that component once; exclude unavailable cells; put target cell first if available, then sort remaining candidates by squared center-distance to exact target, then y, then x. This preserves exact single-unit targets on cell boundaries. Assign first remaining cell per eligible ID, skipping cells containing any other input unit's current position (its own cell is allowed). This conservative rule prevents a failed/stationary member being covered by another member's destination. If assigned cell is target cell, use exact clicked target; otherwise use cell center. Ineligible/excess units get null. A one-unit order on free target preserves M1 exact-target semantics. Grid edges and obstacles naturally clip candidates; do not search indefinitely or cross components to fill quota. Build a cell-to-ID lookup once; no nested unit scan per candidate.

Each entity adds `destination: null | [float,float]`. Keep `order.target` as original clicked group anchor. Destination persists after arrival to reserve its cell; release on replacement/failure. All units' current cells also exclude destinations for other units at allocation time, including moving units; use cell-to-set-of-IDs because travel overlap is allowed. These temporary exclusions are recomputed per allocation, not stored reservations. Moving through other units is allowed. Spawn rejects a cell already occupied or reserved, consuming no ID. This ensures authored starts are distinct; it does not add travel collision.

Tick application: determine final due command per entity using existing command ordering. Release destinations for all replaced entities first. Process effective command subsets in canonical command order, sorted IDs within each subset. For each subset, unavailable cells comprise all other reservations plus all other units' current positions, excluding members of this subset (helper handles their positions). Assign destinations and reserve successes before next subset. Earlier command's superseded IDs must not consume slots. Failed allocation clears order/route/destination, sets `blocked`, keeps position. Successful order routes to assigned destination. Group commands can partially succeed; HUD shows blocked count. An unreachable clicked target yields blocked members, not fallback goals on wrong side of wall.
