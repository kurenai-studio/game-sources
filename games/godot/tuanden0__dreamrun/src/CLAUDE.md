# Dreamrun

2D atmospheric puzzle-platformer (Godot 4.7.2, GDScript). Source of truth for scope: `PROMPT.md`. Design: `docs/GDD.md`. Plan, status and per-step checks: `docs/PLAN.md` (read it first to resume work).

## Commands
- Godot path: set `GODOT` if `godot` is not on PATH (scoop shim: `~/scoop/shims/godot`).
- Import (needed on a fresh checkout, `.godot/` is not committed): `godot --headless --path game --import`
- Test one file while iterating: `TEST_ONLY=room_bugs tools/test.sh`. The whole run takes under a minute (`--fixed-fps 60` steps the game without waiting for the clock) and is cut off after `TEST_TIMEOUT` s (default 480).
- Test (one target): `tools/test.sh` — runs `res://tests/run_all.gd`, exits 1 on a failed check, an unloadable test script, or `SCRIPT ERROR` in the output.
- Run editor: `godot --path game --editor`. Run game: `godot --path game` (it resumes from the save; `godot --path game -- --new-game` forgets the save and starts over). The game runs `levels/chapter1.tscn`; `scenes/test_room.tscn` is the bots' playground.
- Frame times at 1080p (windowed): `godot --path game --resolution 1920x1080 --script ../tools/fps.gd`.
- Animation contact sheet (scenarios land, climb, rope, push, run): `godot --path game --resolution 1280x720 --script ../tools/filmstrip.gd -- out.png land`, then look at the PNG.
- Screenshot for visual checks (opens a window briefly): `godot --path game --resolution 1280x720 --script ../tools/screenshot.gd -- out.png 150`, then look at the PNG.

## Rules
- GDScript: typed variables, signals over polling, one script per node responsibility, no allocation in `_physics_process`.
- Gameplay scripts reference nodes by name/signals, never by art specifics. Controller emits `state_changed(state: StringName)`; visuals live under a child named `Visual` that only listens.
- Visual realism: no world object ships as a plain rectangle or other primitive. Solids, props and anything that collides or casts shadow use an organic, irregular outline (`SolidProp`: one outline drives the visible polygon, collision and light occluder). Trees, rocks, ground and platforms must read as real objects at game scale. Lights use soft shadows (`shadow_filter` PCF13); hard shadow wedges read as screen noise. Before reporting any visual change, take a screenshot and look at it.
- Playtest before reporting: every new gameplay feature gets a bot in `tests/test_playtest.gd` that plays it like a player, including the wrong way (press the key from the wrong place, push into a wall, let go mid-air), recorded by `FlightRecorder` (teleports, non-ballistic flight, falling through the floor, missing landings). The random-mashing bot runs in `test_room`, so new objects go into `test_room.tscn`. Bots must use the real objects and settings of `test_room.tscn`, never a copy configured differently (a rope bot with a custom start angle missed that the real rope swung on its own). A bug found by the user becomes a bot scenario first, then the fix. Animation is checked with the filmstrip tool, not assumed. `tests/test_player_sim.gd` plays the whole `test_room` like a person (goal, late reactions, hops, tries the use key and crates, walks away, stop-and-go over every stretch of ground) under `FlightRecorder`, which also flags being stuck: a direction held on open ground for 45 frames without moving. Run it after any change to physics, collision, ground or player scenes.
- Tests: `game/tests/test_*.gd` extend `res://tests/test_case.gd`; methods named `test_*`, use `check(cond, msg)`. No GUT/gdUnit (no plugins without asking).
- Sound is generated by `tools/gen_audio.sh` (ffmpeg); rerun it to rebuild `game/assets/audio/`. A recording can replace a file under the same name. The save lives in `user://dreamrun_save.json`; tests point `DREAMRUN_SAVE` elsewhere (`run_all.gd`), so a test must never use `SaveGame.FILE`.
- Assets: no file in `game/assets/` without a row in `ASSETS.md` (enforced by `test_assets_ledger.gd`). Download to `game/assets/_incoming/<name>` first; never run scripts from archives.
- No commit/push unless asked. Ask before: paid assets/plugins, stack change, scope expansion.
