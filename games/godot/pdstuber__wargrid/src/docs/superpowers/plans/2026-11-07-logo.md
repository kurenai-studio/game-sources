# Wargrid Logo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Godot's robot with Wargrid's pixel-art emblem everywhere a person sees the game.

**Architecture:** A 32×32 master PNG is the only source. A headless Godot script derives the larger sizes by nearest-neighbour scaling, and every PNG is committed. Project settings, the shipping export presets and the web image point at the derived files.

**Tech Stack:** Godot 4.7.2 (typed GDScript), the existing headless test runner, `web/Dockerfile`.

**Spec:** `docs/superpowers/specs/2026-11-07-logo-design.md`

## Global Constraints

- Emblem: concept B "Grid crest" exactly as approved; the pixel map is `crest` in the mockup generator's `maps.json`, with palette `N 26364a, K 1d1a16, L e2cc94, T c4a568, G a88b55, B 376eac, h 6f9fd6, R b04a3a`.
- All scaling is nearest-neighbour (`Image.INTERPOLATE_NEAREST`, value 0); integer factors only (×16 for 512).
- Card colour: `Color("4d4d4d")` (Godot's default clear colour, which the game uses).
- og description, verbatim: `Isometric real-time strategy game. Play it in your browser.`
- Logo licence: GPL-3.0-or-later, like the code.
- Branch: `r1-release`, so the logo ships with 0.6.0. Commits and pushes need the user's approval.

## Review Focus

1. The web export's favicon and touch icon still come out as Godot's, because the exporter takes another path. Task 2 Step 5 exports Web and checks `index.icon.png` against `game/icon.png`.
2. The Windows export fails, or keeps Godot's icon, once `modify_resources=true` is set. Task 2 Step 5 exports Windows locally; the next rc proves the Linux runner.
3. `og.png` is missing from the deployed site, so link previews show no image. Task 2 adds `curl -fsSI https://wargrid.pdstuber.dev/og.png` to the release's web deploy step.
4. The boot splash blurs or fills the screen. Settings are pinned by test; the look needs one visible check, batched with the next playtest.
5. Link-preview caches (WhatsApp) keep showing the robot. Not testable; record as expected.

### Task 1: Master emblem, derived sizes and their test

**Files:**
- Create: `game/art/logo-32.png`, `tools/logo_sizes.gd`, `game/icon.png`, `web/og.png`, `docs/images/social.png`, `game/tests/test_logo.gd` (plus the `.import`/`.uid` files Godot writes)
- Modify: `game/tests/run_tests.gd` (append `preload("res://tests/test_logo.gd")` to `SUITES`)

**Interfaces:**
- Produces:
  - `game/icon.png` (512×512 RGBA, transparent corners).
  - `web/og.png` (512×512, opaque on the card colour).
  - `docs/images/social.png` (1280×640, emblem at 512 px centred at x 384, y 64, on the card colour).
  - Tool usage: `godot --headless --script "$PWD/tools/logo_sizes.gd" -- "$PWD"` from the repo root.

- [ ] **Step 1: Write the master.** A throwaway scratch script (not committed) writes `game/art/logo-32.png` from the `crest` map: 32×32 RGBA8, `.` transparent. Check: `sips -g pixelWidth -g pixelHeight -g hasAlpha game/art/logo-32.png` gives 32, 32, yes.
- [ ] **Step 2: Write the failing test** in `game/tests/test_logo.gd` (suite style of `test_map.gd`; `cases()` returns `[test_icon_is_master_times_16]`):

```gdscript
func test_icon_is_master_times_16(runner) -> bool:
	var master: Image = load("res://art/logo-32.png").get_image()
	var icon: Image = load("res://icon.png").get_image()
	runner.check(master.get_size() == Vector2i(32, 32) and icon.get_size() == Vector2i(512, 512), "LG1 sizes 32 and 512")
	var same: bool = true
	for y in 512:
		for x in 512:
			same = same and icon.get_pixel(x, y) == master.get_pixel(x / 16, y / 16)
	runner.check(same, "LG1 icon is the master scaled x16 nearest-neighbour")
	return true
```

- [ ] **Step 3: Run** `sh tools/run_tests.sh` into a file. Expected: FAIL, because `res://icon.png` doesn't exist yet.
- [ ] **Step 4: Implement `tools/logo_sizes.gd`** (`extends SceneTree`; `_initialize()` reads one user arg, the repo root). It loads the master with `Image.load_from_file`, writes the three Produces files with `resize(..., Image.INTERPOLATE_NEAREST)`, and fills plus `blend_rect` the card colour for the two opaque ones. It must `quit(1)` with a `printerr` usage line on a missing argument or a failed load or save, and `quit(0)` otherwise.
- [ ] **Step 5: Run the tool**, then `godot --headless --path game --import`. Expected: three files with the sizes above (`sips -g pixelWidth -g pixelHeight`).
- [ ] **Step 6: Run** `sh tools/run_tests.sh`, `sh tools/run_lint.sh` and `sh tools/run_warnings.sh`. Expected: `TESTS PASSED`, with the case count one higher than before; lint and warnings pass.
