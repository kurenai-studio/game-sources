# 烫手炸弹（第三款小游戏）设计文档

日期：2026-10-18
状态：待实现
父文档：`docs/superpowers/specs/2026-10-17-fungi-party-design.md`

## 1. 这是什么

森林深处有一圈石头围着的篝火（蘑菇圈）。四个菌子坐在圈上，中间那颗炸弹被点着后飞到一个人手里。**引信看不见，只能看火花**。拿在手上的人可以往左扔，也可以往右扔；没人扔，它就炸在手里。

一局就是三轮：炸死一个，重新点燃，剩一个活着的人赢。名次换蘑菇币。

它是 v3 的第三个可玩内容，节奏跟前面两款完全不同：偷吃是「等时机」，赛跑是「跑和躲」，这个是**坐着不动的心跳**——唯一操作就是两个按钮，玩的是「敢抱多久」。

## 2. 目标 / 非目标 / 反目标

**目标**
- 15 秒讲清规则：炸弹烧完谁拿谁死，往左往右扔，剩一个赢。
- 3 局之内能明显变强：学会读火花（大概还剩多少）、学会读人（对面那朵快扔了）。
- 不做深度策略。玩家的全部决策只有两个：「还抱不抱」和「往哪边扔」。
- 一局 30~40 秒（3 秒倒数 + 三轮引信 23~38 秒 + 传递耗时），和赛跑（30~45 秒）差不多，比偷吃（90 秒）短。90 秒是硬天花板，结构上到不了。
  （2026-10-18 试玩后调长：原来 20~35 秒的一局实测只有 23 秒左右，手感太赶。）

**非目标（这一版不做）**
- 数字倒计时、进度条、任何精确计时（已经定死：看不见）。
- 「传递加速」这类额外系统（讨论中提过，推演后放弃，理由见 4.3）。
- 玩家在场上走动、跑动、捡炸弹。
- 道具、技能、第二条命。
- 联机、排行榜存档、难度分层。
- 设置面板、音量开关。

**反目标（做成了算失败）**
- 玩家炸死后说不出「我贪了半秒」——那就退化成摇骰子。
- 火花三档在真机上看不出来，只能靠猜。
- 一局超过 90 秒。
- 音效刺耳，手机上外放像火灾警报。
- 收到炸弹那 0.3 秒里点了按钮没反应，玩家以为卡了。

## 3. 约束

- Godot 4.7.2、Mobile 渲染器；照搬教室/赛跑那套「纯逻辑模型 + 无头测试 + 自包含单场景」。
- 可调数字全部进 `game/config.gd` 的 `const`。
- 浮层、字体、按钮统一用 `game/ui/ui_style.gd`。
- 美术全部程序化生成（内置 mesh + MultiMesh），**音频也必须程序化生成**——项目里一个音频文件都没有，不引入外部素材。
- 场景是自包含的，节点间直接 `$` 引用；森林侧的面板每帧惰性 `get_first_node_in_group`。
- 全场景没有物理刚体：四个座位是固定的，炸弹位置靠插值，不需要 `CharacterBody3D`。

## 4. 已经定下的（不留给 builder 决定）

### 4.1 场景与视角

- 单独场景 `game/minigame/bomb.tscn`。
- 四个座位在半径 2.2m 的圆上，**玩家固定坐南边**，另外三个是 NPC。从玩家视角：左边是西、右边是东、对面是北。
- 镜头在玩家身后上方，**一次定好朝向，全程不动不转**（`position ≈ (0, 4.0, 6.5)`，看向 `(0, 0.8, 0)`，具体数值 builder 调）。四个人、篝火、飞行的炸弹必须全在画面里。
- 地面是一小块平地 + 一圈石头（MultiMesh）+ 中间的火堆。远处用雾和深色背景挡住，不做大的森林。

### 4.2 炸弹与传递

- 炸弹 = 黑球 + 引信 + 火花，抱着时悬在持有人头顶上方，传递时沿抛物线飞过去。
- 每轮点燃：炸弹从篝火中心飞向**随机一名存活者**（保证开局不是玩家必死或必活）。
- 传递只到**相邻的存活者**。死者从圈上消失（灰掉缩小），传递自动跳过——人少了以后玩家的「左边」可能是对面那个人。
- 引信隐藏。火花给三档提示，玩家能估到「还有一两秒」，估不到 0.2 秒级：

| 剩余时间 | 表现 |
|---|---|
| > 2.6 秒 | 橙色稳燃，嗤嗤声匀速 |
| 1.2 ~ 2.6 秒 | 冒白星，嗤嗤声频率随剩余时间线性加快，屏幕边缘轻微泛红 |
| < 1.2 秒 | 整颗发白，声音尖利，屏幕边缘明显泛红并轻微抖动，震动连成一片 |

- 引信长度每次点燃重掷：4 人 10~16 秒，3 人 8~13 秒，2 人 5~9 秒。（2026-10-18 试玩后整体拉长，见第 2 节。）
- **燃烧速度带 ±15% 的抖动**（火花忽快忽慢），所以玩家能看不能数，计时没用。

### 4.3 判定规则（核心，写死）

- 炸弹在谁手里爆 → 谁死。
- **炸弹在飞行途中爆 → 判扔出去的那个人死。**
- 剩 1 人 → 结束。

第二条是整个游戏成立的前提：没有它，最优解永远是拖到剩 0.3 秒甩给邻居，而邻居刚接住就炸、纯挨刀。有了它，「拖到白热再扔」变成一次拿命换的赌——心跳全在这里。

**已放弃的方案**：每次传递让引信烧得更快。推演后否决：加速伤害的是所有人包括自己，所以「收到就立刻甩」依然是最优，只是给玩家加了个算不过来的变量，换不到任何决策。

### 4.4 玩家操作

- 屏幕左下角「往左扔」、右下角「往右扔」，两个大圆钮（外观复用 `DashButton` 那套画法，但不需要冷却环）。
- 键盘：A / ← 往左，D / → 往右。桌面调试要靠这个。
- 不按 = 抱着。
- 收到炸弹后 **0.3 秒站稳**，期间按了也不算；这 0.3 秒内按下的方向**记下来**，站稳一结束立刻自动扔出去——不让手机连点白按。
- 扔出去到落点 **0.2 秒**。

### 4.5 三个人机

三个性格固定（颜色也固定，玩家得能认人）：

| 颜色 | 性格 | 判断误差 | 估计剩余低于多少就扔 | 备注 |
|---|---|---|---|---|
| 蓝 | 保守型 | ±0.5 秒 | 1.2 秒 | 常扔早了，下家有时间脱手 |
| 红 | 赌徒型 | ±1.2 秒 | 0.5 秒 | 常在白热时扔，也常炸在自己手上 |
| 紫 | 记仇型 | ±0.7 秒 | 0.9 秒 | 只要还活着，优先扔回上一手扔给他的人 |

- **人机每次接住还会掷一个「打算抱多久」**（`BOMB_NPC_HOLD`：蓝 0.6~1.3 秒、红 1.2~2.6 秒、紫 0.8~1.8 秒），抱够就扔，不等引信烧到忍耐线。没有这一条时，引信一长人机就会把炸弹抱 6~10 秒才出手，桌上三个人轮流发呆，玩家整局只看到两三次传递（2026-10-18 试玩发现）。
- 人机往哪边扔：蓝和红**随机挑一边**；紫优先扔回上一手扔给他的人——那个人只要还活着就一定是他的邻居，所以永远合法。
- 随机是刻意的：人机不针对玩家。用种子驱动的随机，四人在场时玩家平均每三次接一次炸弹，既不会出现「三个 AI 联手永远砸你」，也不会整局摸不到炸弹。
- 人机读的是同一个真实剩余时间，各自加上自己的误差；误差**每次接住重掷**。
- 人机抱着时会做犹豫动作（把炸弹举高、腿抖、身体后仰），**抱得越久动作越夸张**。这是玩家「读人」的唯一依据，必须做出来。
- 人机也受相同的 0.3 秒站稳和 0.2 秒飞行限制。

### 4.6 音效与震动

- 全部运行时生成（`AudioStreamWAV` + 自己填 PCM），一个 `game/systems/sfx.gd`。
- 嗤嗤声：滤波白噪声循环，播放速率随剩余时间上升。
- 滴答：只在进入「冒白星」档之后响，间隔从 0.55 秒收紧到 0.12 秒。
- 一次性音：接住 pop、扔出 whoosh、爆炸（低频一轰 + 噪声）、死亡、胜利。
- **作用域：火花和声音是全场共享的**。炸弹是桌面上唯一一个东西，不管在谁手里，玩家都看得见火花、听得见嗤嗤声和滴答，屏幕边缘泛红也跟炸弹状态走。不做「只有持有者听得见」——那等于把桌面上一颗人人可见的炸弹做成私密信息。
- **震动是唯一的例外：只在炸弹在自己手上时震。** 扔出去那一下手上安静下来，是这局唯一能松口气的时刻，也是「抱不抱」的体感锚点。`Input.vibrate_handheld`，跟滴答同节拍，最后一档连成一片，桌面上是空操作。**真机验手感，太烦就放宽间隔。**

### 4.7 名次与蘑菇币

- 名次 = 死亡顺序的倒序：最后一个活着的第 1，倒数第二个死的第 2，最先死的第 4。
- 蘑菇币：第 1/2/3/4 名 = 70 / 50 / 35 / 20，死在第 4 名也拿 20。公式写成纯静态函数并单测。
- **玩家一死立刻结算**，不等剩下三个打完（死在第几名已经定死了，跟赛跑的提前结算一个口径）。
- 结算面板：标题「第 N 名」、一行「撑了 X 秒，+Z 蘑菇币」，下面按死亡顺序列**已经死掉的人**（玩家那行标出来），还活着的写「仍在场上」——玩家第 4 名死的时候另外三人还没分出高下，不编。按钮「再来一局」「回森林」。

### 4.8 进入方式

- 森林里 `(0, 0, 11)`（玩家出生点正后方）加蘑菇圈 POI：一圈石头 + 中间小火堆。节点挂 `add_to_group("bomb_ring")`，对外只回答 `player_inside`，写法与 `StartGate` 一致。
- 走近弹浮层：标题「烫手炸弹」、三行玩法、「开始游戏」。点按钮进场景。
- 进场景后 3-2-1 倒数，**倒数期间引信不点燃、不计时**。倒数结束才点第一颗炸弹。

### 4.9 返回键与暂停

跟赛跑完全一样，不另设计：返回键弹暂停面板（再按一次继续），三个选项「重新开始」「回森林」「退出游戏」。暂停时必须停掉嗤嗤声和滴答。

### 4.10 每局都不一样

- 每局开局掷一次新种子（`randi()`），不许写死、不许沿用上一局。「再来一局」= 重新加载场景、重新掷。
- 由种子决定：每轮引信长度、开局炸弹给谁、三个人机每次的误差、石头的散射。
- 固定不变：座位位置、三个人机的性格与颜色、火花三档的边界、判定规则、名次币。

## 5. builder check 之后补的

设计文档写完后请一个没参与讨论的 builder 读了一遍，提出四个「不问就只好猜」的点，逐条定如下：

1. **人机往哪边扔**：蓝、红随机挑一边；紫优先扔回上一手扔给他的人，否则随机。→ 见 4.5。
2. **声音和火花的作用域**：全场共享（炸弹是桌面上唯一可见的东西），只有震动限定在「炸弹在自己手上」。→ 见 4.6。
3. **玩家提前炸死后的结算**：只列已经死掉的人，其余写「仍在场上」，不替没打完的三个人排名次。→ 见 4.7。
4. **时长对不上**：原文写的 25~35 秒是按玩家每轮都拖到最后一刻算的，实际是 20~35 秒，已改正。引信区间不动。→ 见第 2 节。

## 6. 留给 builder 决定

- 场景节点结构，篝火/石头/蘑菇的具体尺寸与配色，四个座位的朝向。
- 火焰和火花的做法（自发光材质 / GPUParticles / 缩放动画都行，只要三档分得清）。
- 炸弹飞行弧线的数学、接住时的挤压弹动、投掷时的甩臂（不要求手 K 动画，只要求「看得出扔了」）。
- 人机「犹豫动作」的具体实现。
- PCM 生成的具体波形与包络（只要不刺耳、手机上外放听得清）。
- 纯逻辑模型 `BombRound` 的字段划分与 tick 接口。
- 测试怎么拆。

## 7. 验收

- `bash scripts/test.sh` 全绿，新增的纯逻辑测试覆盖：相邻传递、跳过死者、站稳期间不能扔、飞行中爆炸判扔的人、手上爆炸判持有人、剩一人结束、死亡顺序、名次公式、币公式、同种子可复现。
- 真机：一局走完（实测 30~40 秒），火花三档能靠肉眼分辨；爆炸前有明显的「不敢再抱」的瞬间；音效不刺耳；震动跟滴答对得上。
- 震动要在排期最前面先验一次：项目此前没有音频也没有震动代码，`export_presets.cfg` 里也还没有 vibrate 权限，第一次装上很可能没反应。
- 连跑两局，日志里的引信长度与开局持有者必须不同。
- `docs/perf-log.md` 记一行真机帧率。
