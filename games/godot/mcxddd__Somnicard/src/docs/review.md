# 1.3 更新说明

当前使用公开行动后验范围，包含对局/复盘教学开关、可展开范围图及限定河牌 CFR。算法、范围、局限与大模型决策以 [strategy.md](strategy.md) 为准。以下为 1.0 初始实现记录，随机范围描述仅适用于旧版。

# 复盘、胜率与操作建议

## 从记录重建一手牌

完整牌局保存初始筹码、盲注、庄家、起始牌堆、全部公开事件与结算。`history.gd` 先检查 JSON 的结构、数字范围和牌堆唯一性，再创建一个独立的规则引擎，重新执行每个操作。重建后的事件和结算必须与记录一致，否则显示错误。读取失败不会改动原文件或当前牌桌。

重放时，引擎的事件观察器捕获发牌、盲注、操作、换轮、退还与结算快照。每次操作前另存一个决策快照，确保分析的是操作发生前的状态。全押后连续发出的三条街道也各有独立步骤，不会直接跳到结算。

事件快照可能位于规则转换中间，因此不提供行动按钮；只有完整决策快照才提供合法操作。UI 只收到 `view_for(0)` 的公开深拷贝。所有对手底牌在实际摊牌前隐藏，弃牌者底牌始终不公开。

## 已知信息边界

`advisor.gd` 采用字段白名单，只复制你的两张牌、当前公共牌、未弃牌状态、公开筹码、底池、当前下注和合法操作。它不接收保存的牌堆、烧牌、对手底牌、未来事件或结算。缓存键和随机种子也只来自这些字段。

测试会故意修改快照中的隐藏底牌、未来事件与最终胜负，验证估算仍完全相同。已结算且底牌公开的快照不能直接分析，必须回到之前的决策点。

首版不根据下注历史拟合对手范围；公开下注的影响体现为跟注成本、投入分层和仍在争夺的对手人数。随机范围是明确的基线假设，不应误解为真实对手会等概率持有任意两张牌。

## 胜率怎么算

每次模拟从未见过的牌中不放回抽样，补齐公共牌并为每个未弃牌对手抽两张牌。未知的弃牌与烧牌无需读取实际值，它们在随机未知牌的基线模型中被边缘化。1600 次模拟逐帧分批执行，单帧预算约 4.5 毫秒；可以随时切换步骤取消。

`fast_rank.gd` 直接按点数计数、同花与顺子判定五至七张牌分数；规则结算仍使用原先穷举最佳五张的独立实现。测试用 4500 组随机牌及针对性牌型交叉验证两种算法。

- 独赢概率：你的牌严格击败所有未弃牌对手的比例。
- 平局概率：你与至少一个对手并列最好牌的比例。
- 权益：独赢计 1，与 n 人并列最好计 1/n，再求平均。

例如九人共享皇家同花顺公共牌时，独赢概率为 0、平局概率为 100%、权益为 1/9。界面显示的抽样误差是有界样本方差上界推得的保守正态近似，约 ±2.5 个百分点；它不覆盖“对手范围假设错误”的模型偏差。

## 底池赔率与边池

先把你的跟注计入投入，再按贡献金额分层。弃牌者的筹码仍在底池，但不参与获胜比较；超过你投入上限的边池不计入可争夺底池。每次模拟分别计算你能从各层分回多少筹码。

底池赔率门槛 = 本次跟注成本 / 含跟注的可争夺底池。可争夺底池份额是按各层金额加权的模拟权益，有短码全押时可能与对所有对手的整体权益不同。

例：你总共只有 20 筹码、已经投入 10，两个对手各投入 100。再跟 10 后，可争夺的主池为 60；其余 160 是对手的边池。门槛是 10/60，而不是 10/220。

跟注模型净值 = 模拟平均分回金额 − 本次跟注成本。已投入筹码属于沉没成本；这里假定此后不再下注，不包括未来跟注压力、隐含赔率、抽水或整数分池零头，所以不是整手真实收益预测。底池赔率概念可参考 [PokerStars 官方教学](https://www.pokerstars.com/poker/learn/lesson/pot-odds/)。

## 建议的范围

负跟注净值明显超出模拟误差时倾向弃牌；接近临界时明确提示不确定性；可以免费继续且没有明显优势时建议过牌。权益显著较高且允许加注时，给出 3 BB 或半池的教学档位，并限制到合法范围。

这不是策略求解器：没有比较所有下注尺度的最优期望值，也没有建模弃牌率、范围更新与后续博弈。不要仅凭最终输赢评价决策。未来大模型应解释这些结构化指标，不能接管牌型判定或结算。

## 保存和恢复

完整记录采用 schema_version 1，与旧版本格式兼容，新加的时间等元数据不会影响重放。先写临时文件、flush、关闭后重命名，避免正常写入过程留下半个 JSON。损坏文件会单独报错，其他牌局仍可读取。

每次牌局状态改变后，另存 `user://session.json`。恢复会走同样的规则重建和事件校验，保留底牌、牌堆余下顺序、当前行动者、合法操作、筹码、庄家与手数，并先暂停。电脑的随机决策状态会重新初始化，之后的选择可能不同；既有记录和未来发牌顺序不变。只有一个当前牌桌存档，新开桌会替换它。

## BB 与筹码

规则、保存和缓存始终使用整数筹码。显示层统一换算；切换单位不会重新抽样，也不会改变下注金额或已算出的建议。输入框切换前先提交旧单位下的编辑文字，防止将 2.5 BB 误读成 2.5 筹码。
