## v3 森林赛跑（2026-10-18）

- 真机：Redmi 24122RKC7C，赛跑场景 120 FPS（vsync 顶住），DRAW 158~203（阴影 pass 让每块障碍的 draw call 翻倍），VRAM 69MB。TRI 没取到：DebugHUD 只在 `main.tscn` 里，赛跑场景没有；要测就把那 14 行挂上去。
- 障碍组 10~11 组/局（间距 16.5~18m）：为了满足「动物横穿处离障碍组 ≥ 8m」，最小间距从计划的 12m 提到 16.5m，否则禁入区在 12~18m 间距下互相重叠，没有合法横穿点。
- 人机 40 局平均（`RaceRacer` 纯模型跑，不含节点）：稳中型 36.9s / 撞 0.25 次，贴边型 46.3s / 撞 11.4 次，冲动型 34.7s / 撞 0.3 次；全部完赛，无卡死。
- 玩家侧自动驾驶脚本（会瞄准缝、绕松果、CD 好就冲刺，不会跳）一局 36~45s、撞 0~8 次，名次多为第 3。人手玩会跳、会预判动物，理论上靠冲刺能进 34s，与冲动型互有胜负——「三次内能拿一次第一」还需要一次真人试玩确认。
- 真机三局走查**未做**：MIUI 拒绝 `adb shell input`（INJECT_EVENTS permission），触摸只能人肉验。已做的真机验证是：清空 logcat 后从 forest 启动、以及临时把主场景换成 `race.tscn` 跑一局（无输入，玩家原地不动），两边日志都只有赛道布局一行、无 ERROR/警告，截图见 `shots/v3-race.png`。
- 场景往返（森林 → 赛跑 → 森林 → 赛跑 → 森林）用无头脚本连切，无 ERROR、无「previously freed instance」，`再来一局`/`回森林` 两个按钮的信号路径都通。

## v3 烫手炸弹（2026-10-18）

- 桌面（AMD Radeon 780M, Vulkan Forward Mobile）：60 FPS（vsync 顶住，读不出余量），TRI 30.7k、DRAW 111、可见对象 114。比森林/赛跑轻一个量级，真机帧率没理由更差——但**真机帧率本条未取**，等真机走查时补。
- 一局时长（`tools/bomb_balance.gd`，200 局纯模型，不含 3 秒倒数）：平均 20.1 秒，加倒数约 23 秒，落在设计文档的 20~35 秒里；200 局无一超时卡死。
- 玩家胜率（同一批 200 局，玩家座位用两种自动打法）：
  | 打法 | 胜率 | 首个死亡 |
  |---|---|---|
  | 稳妥：收到就扔，从不抱着 | 13.5% | 39/200 |
  | 读火花：拖到剩 0.5 秒才扔 | 44.0% | 17/200 |
  设计文档 4.5 的人机数值（`BOMB_NPC_THROW_AT = [1.2, 0.5, 0.9]`、`BOMB_NPC_ERROR = [0.5, 1.2, 0.7]`）**一个都没改**：按「拖到白热再扔」打，玩家 44% 落在计划要求的 30%~65% 里；「从来不敢抱」只有 13.5%，正好是设计想要的「学会读火花就明显变强」。
- 调参过程中扫了 12 组 `BOMB_NPC_*` 组合：「收到就扔」这种从不抱的打法最高只能到 29%（因为最早把炸弹推出去的人，永远是在 2 人残局里接最后一棒的人），再往上调只能把三个人机的性格全压成同一档，违反设计文档 4.5，所以没调。
- 修掉的一个真 bug：人机之前完全不管自己的 0.3 秒硬直（设计文档 4.5 明确要求人机也受同样限制），导致人机可以在引信剩 0.05 秒时把炸弹瞬间甩给人。加了 `tests/test_bomb_round.gd::test_npc_cannot_throw_during_lock`，修完玩家胜率从 7.0% 回到 13.5%（稳妥打法）。
- 真机走查结论：**未做**（MIUI 拦 adb 注入、触摸只能人肉）。待验：火花三档在手机屏上分不分得开、嗤嗤声/滴答外放刺不刺耳、震动跟滴答对不对得上、暂停时声音停没停、一局实际多长时间。
- 已知噪音：`--quit-after` 强制退出时会有 `WARNING: N ObjectDB instances were leaked at exit`，`--verbose` 看到只剩 `AudioStreamWAV` / `AudioStreamPlaybackWAV`（还在播的流），不是场景泄漏。

### 手感调优（2026-10-18 试玩后）

试玩反馈两条：一局太短；炸弹老是抱在一个手里，最后才扔。

- 引信拉长：4 人 10~16 秒 / 3 人 8~13 秒 / 2 人 5~9 秒（原 6~11 / 5~9 / 3~6）。
- 人机加「每次接住打算抱多久」（`BOMB_NPC_HOLD`，蓝 0.6~1.3 / 红 1.2~2.6 / 紫 0.8~1.8 秒），抱够就扔，不再一直抱着等引信烧到忍耐线。
- 效果（`tools/bomb_balance.gd`，200 局纯模型）：一局从 20.1 秒 → **30.4 秒**（+3 秒倒数 ≈ 33 秒）；传递次数从每局 2~6 次 → **13~18 次**。
- 胜率（200 局）：从不抱 19.5%；读火花且**完美读秒** 94.5%；读火花但估计误差 ±0.4 秒（更接近真人看火花）**33.5%**。前两个数字是同一套规则下的上下限，计划要求的 30~65% 看的是最后那一档。
- 顺带修掉：倒数期间按投掷按钮会被记账，倒数一结束炸弹自己飞出去（试玩反馈「一开始没按就扔了」）。UI 的 `throw_pressed` 现在在倒数/结算期间直接丢弃。

## v3 体力与一天（2026-10-18）

- 新增的渲染开销只有两处：帐篷与饭店两个 POI（合计约 20 个 `BoxMesh` + 两个小球，全是单实例，不走 MultiMesh），以及天上的太阳/月亮（各一个 24×12 球 + 十几个小部件，unshaded、不投阴影、不参与光照）。都比已有的摊位/校门轻。
- 天体每帧只改 `position` / `rotation`，不实例化节点、不加材质；距离固定 120 米，仍在雾和相机远平面里。
- 真机取到一组：`--export-debug` 装到 Redmi 24122RKC7C，出生点默认视角 120 FPS（vsync 顶住）、DRAW 173、TRI 348.1k。对比 v3 三个 POI 时的 86 / 312.8k，涨的是帐篷 + 饭店 + 两个天体。
- **抬头看天时的数字未单独取**：默认视角下太阳在天边、月亮在地平线下，多半被视锥剔掉，所以这 348.1k 未必含天体。要分离出来得人肉把镜头抬到 +22° 再读一次。

## v3 天空（2026-10-18）

- 出生点默认视角（天空不在视锥里）：120 FPS、DRAW 173、TRI 348.1k，和加天空之前**一模一样** —— 云和星星都在视锥外，代价为 0。
- 真机抬头到顶（人肉拖镜头，然后 adb 截屏读数）：
  | 时刻 | FPS | DRAW | TRI |
  |---|---|---|---|
  | 黎明 t=0.28（3 团云在视锥里） | 120 | 被 HUD 挡住未取 | 350.5k |
  | 夜 t=0.86（云已隐，满天星 + 月亮） | 120 | 63 | 73.1k |

  夜里 TRI 掉到 73k 是因为太阳落山后阴影 pass 基本空了，不是天体的功劳。云和星星本身的开销就在 DRAW 那 1~4 个 draw call 和三万面以内。
- 顺带查出来两个真 bug（详见 `docs/superpowers/specs/2026-10-18-v3-sky-design.md` 3.0）：
  `Environment.sky` 被赋成了材质而不是 `Sky` 资源，**天空从 v1 起就没渲染过**；`fog_sky_affect` 默认 1.0 又把天空压成雾色。两条都修了。

## v4 猫头鹰喂食（2026-10-24）

- 只做了桌面（1280×720 窗口）截图核对，**真机 FPS/DRAW/TRI 未取**：这一版还没装机，等第一局真人试玩时补。场景几何量很小（一棵树 5 个 mesh + 猫头鹰 11 个 + 四只蘑菇各 14 个 + 四颗下落物各 4 个，合计不到 100 个 draw call 量级），没有 MultiMesh 需求。
- 构图按截图调过两轮：座位从 ±3.6 收到 ±2.4、镜头从 8.5 拉到 6.2，四朵蘑菇在 720p 下每朵约 90px 高、嘴一眼看得清；猫头鹰放大 1.35 倍并挪到树干前方，否则在手机上只是一团灰。
- 第二版（试玩后返工）：座位上的蘑菇改成直接复用玩家的 `MushroomMesh`，四只蘑菇和角色长得一样，玩家穿皮肤也跟着换；嘴做成「浅粉嘴唇 + 深红口腔」的大洞，张嘴时头往后一扬。第一版是手工搭的球体蘑菇，和角色完全不像。
- 第三版（再返工）：四朵蘑菇改成背对镜头、面向猫头鹰，嘴挪到菌盖顶上朝天后才两全——「面向鸟」和「看得见嘴」在一张固定机位里是互斥的。玩家脚下那圈黄光圈也删了：跟着动画一起起伏，看着像 bug。
- 张嘴的坑：口腔球比嘴唇球小一码、两者同心，暗红的整颗躲在粉球里，屏幕上只是一个粉疙瘩；嘴的 y 坐标按「半个菌盖高」算会陷进盖子里（菌盖是压扁的球，顶面在 mesh 坐标 1.90 而不是 1.35+0.55/2）。两处都是靠截图才发现。
- 出局前倾 0.3 弧度会把贴在菌盖里的五官吞掉（第一版截图上「出局的人没有眼睛」）；现在脸改用 `MushroomMesh` 自带的，不再有这个问题。
- 屎是棕的、树干也是棕的，飞到树前那半秒撞色。树干压暗 + 屎提亮，两头拉开。
- 一局（3 关，45/50/55 秒）在桌面完整跑通：倒数 → 三关 → 结算 → 加币入库，`print` 里有每颗糖/每次出局/结算行。加长加密之后一条线一关约 20~40 次投喂（第一关 14 次以上，第三关比第一关密 1.3 倍以上，`test_density_rises_with_levels` 钉住）。

## v4 皮肤抽卡（0.7.0）

- 桌面 1280×720 实测：穿菇勇者（剑 + 披风 + 角盔）森林里 **FPS 60 / DRAW 97 / TRI 321998**；空身 FPS 60 / DRAW 90 / TRI 307592。

## v5 第二个角色海鲜菇（0.8.0）

- 桌面 1280×720：森林里穿菇勇者（剑 + 披风 + 角盔）**FPS 58~62 / DRAW 110 / TRI 338696**，和 v4 的 322k 同一量级。
- 角色本体（含描边）三角形数：红蘑菇 **7632 / 25 个 MeshInstance**，海鲜菇 **10304 / 33 个**。杆是 28 段 × 24 剖面的旋转体，比红帽多一圈剖面，多出来的 2.7k 面占整场景不到 1%。
- 换体型不增加任何「每帧」开销：两种体型共用同一套材质和零件生成，`build()` 只在换皮肤/换角色时跑一次。教室里每个座位、赛跑人机仍然是红蘑菇，整场景实例数没变。
- 相机、碰撞胶囊（0.45×1.5）、四款小游戏的摆位都没动：海鲜菇只是视觉高（2.10 米 vs 红蘑菇 1.81 米），头顶标记改成按 `top()` 反算。
- **真机 FPS 未取**：上面的数字是桌面窗口，装到 Redmi 24122RKC7C 上要再走一次。
