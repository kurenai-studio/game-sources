# M4.1 Playtest Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task (native, sequential, per `prompt.txt`). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Idle scan, opponent base defence, rally points and three presentation fixes, with the skirmish scenario recalibrated and benchmarks inside unchanged budgets.

**Architecture:** Scan lives in `Combat.plan` (shared, both sides, radius from vision × controller modifier). Base defence is one more rule in `Skirmish.issue_opponent`. Rally is authoritative building state plus a `set_rally` command; spawns get an internal move through `_assign_move`. Presentation reads snapshots only.

**Tech Stack:** Godot 4.7.2, typed GDScript, existing headless suite (`sh tools/run_tests.sh`), `sh tools/run_benchmark.sh`.

**Spec:** [M4.1 design](../specs/2026-11-03-m4.1-playtest-polish-design.md) (approved 2026-11-03). Rules it changes: [M4 design](../specs/2026-11-03-m4-combat-design.md). Pitfalls: [M4 plan](2026-11-03-m4-combat.md) "Code anchors and pitfalls". Run rules: [milestone prompt](../../milestone-prompt.md). Evidence file: `docs/reference/m4.1-verification.md` (Task 0 creates it).

## Global Constraints

- Modifiers `GUARD_OUTER_HUMAN = 2.2`, `GUARD_OUTER_AI = 1.333` (`AIData.ini`); vision infantry `4.0`, tank `6.0` cells (Ranger 100 / Crusader 150 ÷ 25). Only infantry and tank have vision; other kinds `0.0`.
- Scan targets = today's `Combat._targets` (enemy units except collectors, plus enemy buildings); tie-break = today's `_nearest`.
- Controller values exactly `"human"` / `"ai"`; default `"human"`; skirmish P2 is `"ai"`.
- Base-defence radius `10.0` cells from any opponent building footprint (provisional). Decision cadence stays 30 ticks.
- Default rally: 3 cells beyond the footprint edge facing map centre, footprint centre row, clamped to the map (formula in Task 4).
- Budgets 1.67 / 3.3 ms unchanged for gated layouts (`contact`, new `skirmish3v3`); `open`/`dense` report-only with a pinned ceiling by user decision 2026-11-03. Otherwise no budget, tolerance or assertion relaxed. Existing assertions that encode "guard never acquires beyond weapon range" are the only ones allowed to change, each listed with its ruling in the verification file (Task 3).
- No new dependencies, no moods, no map change, no fog. `base.tscn` and `main.tscn` behaviour unchanged.

## Review Focus

1. **Kiting loop:** a target retreating at equal speed inside the radius keeps the chaser following; expected: chaser drops it as soon as distance from the chaser exceeds the radius at a scan (Task 3 test `test_scan_drops_target_leaving_radius`).
2. **Attack-move after a chase:** expected to resume toward the original `combat.goal`, not stop where the fight ended (Task 3 `test_attack_move_resumes_after_chase`).
3. **Rally into a blocked or building cell:** expected nearest reachable free cell; never a stall or a unit inside a footprint (Task 4 `test_rally_blocked_cell_falls_back`).
4. **Producer destroyed with a pending `set_rally`:** expected rejection result, no crash, no orphaned rally (Task 4 `test_set_rally_same_tick_cases`).
5. **Enemy selected, then player presses E/A/S or right-clicks:** expected nothing sent, enemy stays inspected (Task 6 `test_enemy_selection_read_only`).

### Task 4: Rally points

Task: default rally, `set_rally`, rally move on spawn. Owns: `simulation.gd` (`_payload_fields`, `_validate`, `_apply_orders`), `construction.gd` (building record), `production.gd` (spawn, `default_rally`), `test_production.gd`. Invariant: collectors unchanged; queue/refund behaviour unchanged. Boundary: rally on a footprint, out-of-component, blocked.

**Interfaces:**
- Produces: `Production.default_rally(sim: RefCounted, kind: String, origin: Vector2i) -> Array` returning a float cell centre `[x + 0.5, y + 0.5]` where `fp = footprint(kind)`, `y = origin.y + fp.y / 2`, `x = origin.x + fp.x + 2` if `origin.x + fp.x / 2.0 < size.x / 2.0` else `origin.x - 3`, both clamped to `[0, size - 1]`. P1 barracks (12,12) → `[16.5, 13.5]`; P2 barracks (34,12) → `[31.5, 13.5]`.
- Produces: building record field `"rally": Array` (set at creation, every kind; used only by barracks/factory).
- Produces: command `{"type": "set_rally", "building_id": int, "target": [x, y]}`. Validation errors: `"Missing producer"`, `"Invalid owned producer"` (not owner or kind not barracks/factory; unfinished allowed), target via the bounds/finite checks of `_validate_target` (walkability not required). Result recorded like other non-move commands. Applied at due tick in `_apply_orders`; two same-tick `set_rally` for one building: last in `_command_before` order wins.
- Spawn: after `sim.spawn(...)` for infantry/tank, `sim._assign_move([unit], building.rally)` then `sim._set_intent(unit, "move")`.

- [ ] Red `test_default_rally_mirrored`: values above for barracks and factory on both sides; field present in snapshot.
- [ ] Red `test_production_never_stalls`: barracks with default rally produces 12 infantry (old stall at 8) in a fresh skirmish world with credits; every one ends `idle` in `guard` off the perimeter.
- [ ] Red `test_set_rally_applies_to_next_spawn`: set rally, spawned unit's destination near that cell; moving in mode `move` past an enemy 3 cells away does not acquire it; on arrival mode `guard`.
- [ ] Red `test_rally_blocked_cell_falls_back`: rally on own depot footprint → unit's goal is a walkable free cell; no reachable cell (enclosed) → unit stays at spawn cell, `guard`.
- [ ] Red `test_set_rally_same_tick_cases`: against `produce`, `cancel_production`, `cancel_build`, another `set_rally`, an `attack` on the building that destroys it before due (rejection `"Missing producer"`), `remove_object` of the building the same tick, and a spawn completing that tick (new rally applies); validation rejections for enemy building, depot, out-of-map, non-finite.
