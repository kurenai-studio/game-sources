# M5.1 Playtest Findings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task (native, sequential, per `prompt.txt`). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the four friend-match findings:

- Zero Hour's human acquisition rule, plus retaliation.
- Per-unit group orders.
- Click and resume feedback.

The skirmish and netplay pins are recalibrated, and benchmarks stay inside unchanged budgets.

**Architecture:**

- **Acquisition.** Controller-dependent rules live in `Combat.plan`. Humans acquire only within weapon range and do not chase, except for attack-move approaches and the rescan right after an engagement ends. AI-controlled units keep M4.1 unchanged.
- **Retaliation.** A new combat mode `retaliate`, triggered from `Combat.fire` after damage is applied.
- **Group orders.** Missing ids are filtered in `_validate` and `_apply_orders`.
- **Presentation.** Reads snapshots plus client-side hint state only.

**Tech Stack:** Godot 4.7.2, typed GDScript, the headless suite (`sh tools/run_tests.sh`), `sh tools/run_benchmark.sh`, `sh tools/run_netplay.sh`.

## Global Constraints

**Constants, in cells, ticks and modifiers; source values in the evidence file:**

- `GUARD_OUTER_HUMAN = 2.2`, `GUARD_OUTER_AI = 1.333` (existing).
- `GUARD_INNER_HUMAN = 1.8`.
- `RETALIATION_DISTANCE = 8.0`, `RETALIATION_FRIENDS_RADIUS = 4.8`.
- `RETALIATION_TICKS = 300`, `RETURN_SCAN_TICKS = 30`.
- Vision: infantry `4.0`, tank `6.0` (existing).

**Controller:** `Combat.is_ai(sim, owner)` is true only when the player record exists and its `controller == "ai"`. A missing record counts as human.

**Cadence:** stays `REPATH_TICKS = 8`, staggered by unit id, together with the M4.1 `stop` phase rule (user decision, recorded departure).

**Snapshots:** entity `combat` gains exactly two fields:

- `retarget: bool`, default `false`;
- `until: int`, default `0`.

`retaliate` reuses `goal` for `home`. Any further authoritative field needs a design question.

**Assertions:** no budget, tolerance or assertion is relaxed. Only these change:

- Assertions encoding the M4.1 human chase: X1, R3, K1, O1–O5 (`test_combat.gd`) and M1, G2, U1 (`test_combat_navigation.gd`).
- Assertions encoding whole-command rejection of mixed selections: V1 "attack_move unarmed" (`test_combat.gd`) and K3's unarmed attack-move check (`test_skirmish_scene.gd:73`).
- `H1 pinned digest` (`test_state_hash.gd`), only because of the two new fields.
- The two match pins, through Task 7's procedure.
- The BM6 work floor and ceiling, with user approval (Task 8).

Each change is recorded as `test / assertion / old → new / reason` in the verification file.

**Copy:**

- Rejection error for an order with no live members: `No units left`.
- Resume hover status line: `Right-click: resume`.
- Label suffix on a building with no builder attached: ` paused`.
- Online rejection status line: `Rejected: <error>`.

**Out of scope:** no new dependencies, no fog, no turrets, no moods, no map change.

## Review Focus

1. **A dead unit in the selection when the order becomes due online.** It dies during the 4-tick delay. Expected: the live members still move. Task 4, `test_due_tick_death_skips_member`.
2. **A human guard next to an enemy that kites at the edge of weapon range.** Expected: it fires while in range, never moves, and takes the target again when it comes back. Task 2, `test_human_guard_holds_against_kiting`.
3. **Retaliation pulls defenders into the enemy army.** Expected: they stop at the leash, walk back home, and end in `guard` at `home`. Task 5, `test_retaliate_leash_and_return`.
4. **A retaliating unit's target dies in the same tick a new hit lands on it.** Expected: no stale target and no crash. It either restarts against the new attacker or returns home. Task 5, `test_retaliate_same_tick_cases`.
5. **The click hint while the online sim is stalled** (waiting for the peer). Expected: the hint is visible, then expires 40 ticks after the click once ticks advance again. It never piles up. Task 6, `test_click_hint_lifetime`.

### Task 5: Retaliation

**Task:** a hit on a human-owned object sends idle armed units of that player nearby after the attacker, on a leash, and then back home.
**Owns:** `combat.gd` (new `_retaliate_trigger`, `_plan_retaliate`, constants, called from `fire` and `plan`), `simulation.gd` (counter), `test_combat.gd`.
**Invariant:** an AI-owned victim never triggers; units that are moving, attacking or chasing do not join; any player command replaces `retaliate`.
**Boundary:** the attacker at exactly 8.0 cells edge-to-edge triggers; at 8.01 it does not.

**Interfaces:**

- Produces combat mode `"retaliate"`. `goal` is `home` (`[x, y]`); `target_id` is the attacker, or `null` while returning; `until` is the tick the chase gives up.
- Trigger point: in `fire`, after hp is applied and before dead objects are removed. Process the shots in their existing order. Victims with `hp == 0` cannot join.
- Joiner radius from the victim's centre: `4.8` for units (tests use float32-exact 4.75 in, 4.9 out). For buildings, `4.8 + 0.5 * footprint.length()`, measured from the footprint centre.
- Leash, checked each plan tick while chasing:
  - `|unit − home| > vision × 1.8`, or
  - `|attacker − home| > vision × 4.0`, or
  - `tick >= until`, or
  - the target is gone.
  - On any of these: `target_id = null`, and `_assign_move` to `home`.
- Returning:
  - Every `RETURN_SCAN_TICKS`, the nearest enemy unit (not a building, not a collector) within `vision × 1.8` of `home` becomes the new target, with `until = tick + 300`.
  - A hit on the returning unit itself makes the attacker the target, with `until = tick + 300`.
  - On arrival (not moving, no target), the unit switches to `guard` with `goal = null`.
- Chasing reuses `_approach` and `_firing_cell`.
- Produces `Simulation.retaliations() -> int`: the number of joiners sent this step, reset per step like `scan_chases`. Task 8 consumes it.

Tests:

- [ ] Red `test_retaliate_trigger_distance`: 8.0 cells triggers, 8.01 does not; an AI-owned victim never triggers; a killing hit triggers for its neighbours.
- [ ] Red `test_retaliate_joiners`: the victim joins; an idle armed unit at 4.8 cells joins, one at 4.9 does not; a moving unit, an attacking unit and a builder do not join; a building victim uses the footprint radius.
- [ ] Red `test_retaliate_leash_and_return`. Rifle home (5.5, 5.5), attacker retreating.
  - The rifle stops chasing when it is more than 7.2 cells from home, then walks home and ends in `guard` at home.
  - Variant: the attacker is more than 16 cells from home. Variant: 300 ticks pass with the attacker kept in reach.
- [ ] Red `test_retaliate_return_scan_and_rehit`: an enemy unit within 7.2 cells of home during the return becomes the target; an enemy building there does not; a hit during the return restarts the chase with `until` refreshed.
- [ ] Red `test_retaliate_same_tick_cases`. In the trigger tick and during the chase, each of `move`, `stop`, `attack`, `attack_move`, `gather` (on a collector, no effect), `build` and `resume_build` (on a builder, not a joiner) is applied. Also: removal of the attacker, removal of the joiner, and the target dying in the same tick a new hit lands. A command applied after the trigger tick replaces `retaliate` (orders apply before `fire`, so a `stop` due in the trigger tick leaves an idle guard that joins). Also: `retaliate` unit given `attack` on a dead enemy (`_apply_orders` clears `destination` before the validity check, `simulation.gd:264-292`): `_plan_retaliate` must handle `destination = null`. Expected: no stale `target_id`, no crash.
- [ ] Suite green. Commit `Add Zero Hour retaliation for human players`. **Stop gate: review, restart.**

### Task 6: Presentation

**Task:** click hint, selection pruning, online rejection line and resume hint.
**Owns:** `main.gd` (`_submit`, `_refresh`), `base_main.gd` (hover, resume status), `online_main.gd` (rejection line), `world_view.gd` (hints, resume outline, `paused` label), `test_skirmish_scene.gd`, `test_base_scene.gd`, `test_online_scene.gd`, `test_view.gd`.
**Invariant:** the view never changes the snapshot (existing checks); `base.tscn` and `main.tscn` keep their behaviour apart from the hint.
**Boundary:** the hovered building finishes or loses its builder while hovered; the hint updates on the next refresh.

**Interfaces:**

- Produces `WorldView.add_hint(point: Vector2, tick: int) -> void` and `WorldView.hints() -> Array`. `hints()` returns the active hints, those with `state.tick < tick + 40`, and expired ones are pruned.
- `main._submit` adds a hint for payload types `move`, `attack_move` and `set_rally` (at `target`) and `resume_build` (at the building footprint centre). It adds the hint before the result is known, so a rejection still shows the click.
- `main._refresh` drops from `selected_ids` the ids that are missing in the snapshot.
- `online_main`: after `advance`, a new entry in `lockstep.rejections()` sets `_error = "Rejected: " + error`.
- Produces `WorldView.building_label(building: Dictionary) -> String`. `_draw` uses it. Today's text, plus ` paused` for an unfinished building with `builder_id == null`.
- Produces `WorldView.resume_candidate() -> int`: the hovered own unfinished building with `builder_id == null`, only when exactly one own builder is selected, else `-1`. `base_main` shows `Right-click: resume` while it is not `-1`.
