# Rat Ownership and Debug Reliability — Decision Log

Historical record of agreed design. Sprint closed on **2026-10-12** after
maintainer visual confirmation. Earlier pending-status notes describe the review

[closeout](06-rat-ownership-and-debug-reliability.md). Explicitly deferred ideas

- Error handling follows request validation, calculation on detached data, complete result validation, application, and completion notification. Reject invalid updates before mutating live state; preserve the rat's previous values and emit no completion notification for a rejected update.
- Debug controllers validate submitted text and provide field feedback. Managers validate requests and required dependencies. Systems validate configuration and calculate from valid inputs. Rats validate incoming state and enforce bounds through their setters.
- Expected gameplay outcomes use normal results. Invalid user input receives visible feedback. Valid numbers outside stat bounds are clamped. Broken contracts use `push_error()` and reject the operation. Required configuration is checked once during setup; invalid configuration disables affected operations. Use `push_warning()` only when a safe fallback has been designed. Assertions check internal developer assumptions, not release-required validation.
- Use Godot's native `Error` return values where callers need to distinguish acceptance from rejection. Keep ordinary getters and calculations returning their usual values.
- The layer detecting a failure reports it once, with the operation and relevant IDs or dependency names. Callers handle the rejection without duplicate logging; setup failures must not produce errors every tick.
- Keep error handling within existing owners. Extract shared validation only for genuinely repeated rules; no error-manager node is planned.
- Rat announces a settled state after a completed operation, using one public `state_changed` signal. Central change processing delegates to mutation handlers and emits only when state changed. Handlers return whether they changed values and do not emit that signal themselves; acceptance/error feedback remains distinct from change detection. RatManager will forward the rat ID. Arrival and a subsequent employment request are separate operations. Draft application and central processing are implemented; other operations and debug forwarding remain pending.
- NeedSystem and StressSystem expose matching `apply_tick_effects()` functions that modify their own properties in `RatStateUpdateDraft`. RatManager coordinates needs, then stress, then Rat acceptance. StressSystem retains tier/rate getters for debug display. Renamed StressEvaluator with its UID preserved. Checks passed all seven tiers with and without work, manager ticks, rejection, and one completed notification only for changed drafts.
- Organize Rat into collapsible regions before extracting helper classes or child-node components. Review responsibilities and ownership first; avoid spreading unsettled update boundaries across files.
- **Typed debug display data** — Debug decoupling refactor — `RatDebugDisplayData extends RefCounted` combines a detached RatState snapshot with the assigned-job title and prepared stress breakdown for one panel update. The controller prepares data; `display_rat_debug_data()` updates controls. Alternatives considered: separate panel calls and loosely typed arguments/dictionaries. It retains the already detached snapshot without copying it again. Location: `debug/data/rat_debug_display_data.gd`; controller/panel integration is pending.
- ~~Enter submits an individual field edit while other readouts remain live.~~ First text edit pauses simulation and creates a private panel draft from the selected rat's captured RatState. Typing changes this draft only; Enter does not submit. Play validates visible input and submits the complete draft through RatManager for immediate Rat acceptance before resuming. The next scheduled calculations use those accepted values; no tick is skipped or replaced. Invalid input/rejection preserves the draft and pause. Discard edits releases the draft, restores accepted display values, and leaves simulation paused. Switching rats discards unfinished edits. This flow is agreed; connected implementation remains pending.
- DebugController owns selected running speed and paused state. Buttons emit requests and display the controller's state; choosing speed while paused changes only the resume speed. Shared draft singletons, write locks, field tracking, and tick-delivery queues were considered and deferred; the private paused draft is sufficient for this sprint.
- Public Rat API uses `get_*` for reads, `is_*` for boolean queries, and `request_*` for actions Rat accepts or rejects. This convention applies only to public methods; private helpers keep an underscore and descriptive implementation names. Initialization remains a setup operation. Renamed snapshot capture to `get_state_snapshot()`.
- ~~Initialize `RatSimulationState` from a broader `RatStateSnapshot`, keeping two separate capture/working types.~~ Centralize complete live values in a private `RatState`. Inspection receives a detached copy of that same type; a separate snapshot class is unnecessary. Copies are mutable, with isolation from live values. Simulation receives a narrow `RatStateUpdateDraft` populated directly from the rat's current values; it contains only rat ID, copied needs, stress, and effective average urgency. Rat checks ownership and complete validation before application, then emits one `state_changed` only when applied live values changed. Draft construction, validation, runtime integration, and changed-only completion notification are implemented; complete live-state storage and snapshot retirement remain pending.
- ~~Use RefCounted for RatState with explicit field-by-field copying and retained Location references.~~ Use a Resource for complete state, Inspector exports for its data, and native `duplicate(true)` for detached inspection copies. Each rat creates its own instance; Resource inheritance does not imply sharing. Keep `RatStateUpdateDraft` as a narrow RefCounted working update. Complete live-storage/capture integration remains pending.

Alternatives considered: RefCounted with explicit copying, Dictionary, and Node. Runtime Inspector edits bypass Rat request/completion handling; debug panel edits continue through requests. Location: `entities/rat/data/state/rat_state.gd`. Native-copy independence and seven group definitions passed headless checks; live integration remains pending.
- **Stored script property introspection** — Rat state replacement — `RatState.is_equal_to()` uses `get_property_list()` with storage and script-variable flags to compare current state data, recursively comparing nested scripted attribute Resources and treating two uncalculated urgency values as equal. Headless checks passed independent unchanged copies, initial/calculated urgency, scalar and all nested attribute-group changes, and ignored Resource-name metadata. Replacement integration remains pending.
- **StringName location identity** — Rat ownership refactor — `Location.location_id` and RatState location IDs identify authored locations independently of labels and scene paths. LocationManager resolves IDs to live Nodes and validates nonempty unique IDs once at startup. StringName communicates identifier intent; alternatives considered: String, array indices, and direct Node references. Empty IDs represent no location. - Simplify field inheritance before continuing tick integration. Remove `BaseStatGroup` and merge single-use personality/status/camaraderie field wrappers into their concrete classes. Replace `NeedFields` with `NeedValues`, declaring shared numeric fields and assignment hooks; concrete classes own constraints and notifications. `NeedRates` preserves combined rates without clamping, and normalization belongs to `LocationPull`. - Retire the broad `field_groups` and rat `stats` layout as classes migrate. Shared numeric need types belong in `shared/needs/`; rat value types belong in `entities/rat/data/attributes/`, separated from working update state in `entities/rat/data/simulation/`. Rat configuration belongs under `entities/rat/config/needs/` and `config/generation/`. Keep location/job concrete types with their owners. The folder separation communicates different roles rather than implying that every data class is interchangeable. These moves are agreed, pending reviewed implementation.
- Clamp initial relationship values in `Camaraderie.add_relationship()` to `-100..100`, including replacement of an existing relationship. Previously only updates clamped values. This approved behavior change accompanies the standalone Resource migration.
- ~~Encode arrival intention in separate travel-to-work and travel-to-location states.~~ Use one `TRAVELLING` state. Rat delegates movement from `_process()`, records its reached location and clears its destination before signaling arrival. RatManager checks current employment context and requests `WORKING` or `IDLE`; Rat owns acceptance. Initially accept valid requests. Future disagreements/refusals are deferred, with acceptance feedback supported at the request boundary. Stationary activity is also reconsidered when assignments change. This replaces the old stored-intention transition and is planned, pending reviewed implementation.
- ~~Use a generic manager request to set `WORKING` or `IDLE` on arrival.~~ Rat instead defaults to `IDLE` on arrival. RatManager requests employment through `request_start_employment() -> bool` only if the current assignment matches the reached location; otherwise no request is made. Rat owns acceptance, and future refusal leaves it idle. Ending employment that becomes invalid is a separate operation. This refines the preceding arrival decision and is planned, pending reviewed implementation.
