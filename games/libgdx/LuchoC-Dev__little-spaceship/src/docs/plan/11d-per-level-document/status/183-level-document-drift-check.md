# #183 — A hand-edited level document fails the build

**Branch:** `ci/level-document-drift` · **Closes:** [#183](https://github.com/LuchoC-Dev/little-spaceship/issues/183) · **Written:** 31/08/2026

Task 3 of phase 11d. It is the mechanism the phase exists for: without it the generator from
[#182](https://github.com/LuchoC-Dev/little-spaceship/issues/182) is a convenience a tired agent skips
at the end of a long phase, which is the failure mode
[`../../10a-honest-documentation/mechanism.md`](../../10a-honest-documentation/mechanism.md) is about.

## Completed

`.github/workflows/ci.yml` gains one step, first in the job and before the JDK: it runs
`tools/build-level-docs.js` and fails if `git status --porcelain docs/levels/` is not empty. About a
second, and it needs nothing installed — Node is already on `ubuntu-latest` and the generator has no
dependency, deliberately.

**Regenerate-and-diff rather than the generator's own `--check`**, for two reasons. It is the
acceptance criterion as the plan words it — *"regenerate in CI and fail if the working tree changes"* —
and `git status` also catches a stray file in `docs/levels/` that no generator writes, which `--check`
cannot see. `--check` stays for local use, where not writing is the point.

## Evidence — the run that failed

**Green with the step, on `a8b9a97`:** [run 33411681535](https://github.com/LuchoC-Dev/little-spaceship/actions/runs/33411681535), `the generated level documents match assets/data/`.

**Then the demonstration the acceptance criterion asks for.** One line of the generated document was
edited by hand, with nothing under `assets/data/` touched — `the boss enters at 302.0 s` changed to
`180.0 s` — and committed as `bed1b07`:

[**run 33411807522 failed**](https://github.com/LuchoC-Dev/little-spaceship/actions/runs/33411807522), with:

```
The level documents do not match assets/data/.

docs/levels/ is generated by tools/build-level-docs.js and must never be edited
by hand. Either the content changed without the documents being regenerated, or a
document was edited directly. Run:

    node tools/build-level-docs.js

and commit the result. What differs:

 M docs/levels/level-01.md
diff --git a/docs/levels/level-01.md b/docs/levels/level-01.md
@@ -32,7 +32,7 @@
 | the waves end at | 298.0 s |
-| the boss enters at | 180.0 s (3.0 min) |
+| the boss enters at | 302.0 s (5.0 min) |
 | gap between them | 4.0 s |
##[error]Process completed with exit code 1.
```

The edit was reverted in the next commit by regenerating. **Both commits are on this branch on
purpose** — the run that failed is the evidence, and deleting the commit that caused it would delete
the thing being claimed.

The failure names the file, says the command to run, and prints the diff. That was the criterion the
issue set beyond the check merely existing: *"the failure says what to do about it, not just that a
file differs."*

## Decided, which the plan did not specify

- **The step runs first, before the JDK setup and the Gradle build.** It is a second of work and the
  fastest possible signal; a drift check that reports after a five-minute build teaches people to stop
  reading it.
- **It runs on `push` as well as on a pull request**, because `ci.yml` already does, and because the
  drift this catches arrives by commit rather than by review.

## Open

- **The check cannot see the generator's quoted `core/` constants going stale.** Regenerating produces
  identical text whether or not the Java still says what the `CODE` table at the top of
  `tools/build-level-docs.js` claims, so this mechanism is blind to exactly that class of rot. It is
  recorded in [#182](https://github.com/LuchoC-Dev/little-spaceship/issues/182)'s fragment and in the
  contract, and it is the strongest argument for
  [#56](https://github.com/LuchoC-Dev/little-spaceship/issues/56) — which task 5 decides.
