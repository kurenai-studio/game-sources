Decision rule (proposed; ratios only, so it holds on any later tree). Measure four technology ratios on Deck Firefox, each from runs on one tree in one session:
- K, language gain: GDScript time for the slice's work divided by Rust time for the same work with the same algorithm, both as WASM (Rust time = replacement path minus pass-through).
- H, hand-off: pass-through time per tick, reported per entity (microseconds and bytes) and as a fraction of the GDScript slice time.
- E, effective gain: GDScript slice time divided by the whole replacement path (packing + call + native work + conversion back + synchronisation). This is the quantity the old 5x line meant.
- T, template tax: unchanged GDScript whole-tick time on the extension-enabled template divided by the same on today's template, minus 1.
Read two game numbers at decision time, from the tree as it then is, not from this spike's base:
- s: the share of the tick that the candidate slices cover (`sh tools/run_profile.sh`).
- Q, the need: the worst simulation row's p95 on Deck Firefox divided by its 10 ms budget (2026-11-08: hordes300, 14.54 / 10 = 1.45).
Project two paths (estimates, always labelled as such; the gain G is also roughly "how many times more units fit in a tick"):
- Hot loops: G_inc = 1 / ((1 + T) x (1 - s) + s / E). Its ceiling is 1 / ((1 + T) x (1 - s)) however fast the native code is.
- Whole port: G_port = 1 / (1 / K + p), where p is the presentation hand-off as a fraction of today's tick (per-entity H times entities). K from one slice standing in for the whole simulation is the weakest assumption in this rule; say so next to the number.
Decide by comparing with Q times a headroom factor (proposed 1.5: the simulation keeps growing with avoidance, fog and bots, and a toolchain that only just passes is not worth its permanent cost; this factor is the one chosen number and it is the user's to change):
- G_inc reaches it for a share s that real slices can cover: pursue incremental extraction.
- Only G_port reaches it: hot loops are a dead end and the choice is whole port or nothing; the next step is then the golden scenarios, not more Rust.
- Neither reaches it: no performance case. The portability case is reported separately and does not rescue it.
Two floors that follow from the arithmetic rather than from taste: a slice is only a net gain if s x (1 - 1/E) is larger than T x (1 - s), and only counts if the measured gain is larger than the A/A spread. Where the slice is big enough, also report the measured whole-tick p95 before and after in the two shipped-style configurations; a measured number outranks the projection.
