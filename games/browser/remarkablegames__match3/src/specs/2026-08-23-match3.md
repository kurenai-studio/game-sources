# Match-3 Game Plan (Vanilla TypeScript + Canvas)

Build a Candy Crush-like match-3 game in the existing Vite + TypeScript repo, drawing the board and emojis on a `<canvas>` element.

## Scope

- Single-page game with canvas rendering.
- 8x8 grid by default; tile size responsive to canvas dimensions.
- 6 distinct candy/rainbow/unicorn emojis (e.g., 🍭, 🌈, 🦄, ⭐, 💎, 🍬).
- Mouse/touch input to select and swap adjacent tiles, plus keyboard support (arrow keys to move a cursor, Enter/Space to select and confirm a swap, Esc to cancel).
- Match detection (horizontal/vertical, 3+), cascading combos, gravity refill.
- Score, combo multipliers, and move/goal tracking.
- Multiple modes:
  - **Levels**: reach a target score within a move limit; reset on win/loss.
  - **Time Attack**: score as much as possible before a timer runs out.
  - **Endless**: no move or time limit; play until no valid moves remain, with shuffle.
- Synthesized sound effects via Web Audio API (select, swap, match, invalid move, win/lose) with no external audio assets.
- Lightweight canvas animations: hover highlight, selection pulse, sliding swaps, match shrink/fade, gravity fall, cascading delays, and floating score text.
- Optional juice effects: rainbow particle burst on matches.
- A small UI overlay for score, moves/time, target, and mode selection.

## Design

- Aesthetic: light, cheerful, and colorful to match the **Unicorns and Rainbows** theme.
- Background: soft pastel gradient (pink/lavender/sky blue) or a subtle rainbow wash.
- Board: rounded tile cells with light backgrounds and faint candy-colored borders.
- UI: rounded panels, playful system font stack (`'Comic Sans MS', 'Chalkboard SE', 'Trebuchet MS', sans-serif`), semi-transparent white overlays.
- Effects: rainbow particle bursts on big combos.

## Files to Add/Modify

- `src/main.ts` — bootstrap the game, mount canvas and UI.
- `src/game.ts` — core game engine (grid state, matches, swap, gravity, scoring).
- `src/renderer.ts` — canvas drawing (board, emojis, selections, animations).
- `src/input.ts` — pointer/touch event handling.
- `src/audio.ts` — synthesized sound effects via Web Audio API (no external assets).
- `src/types.ts` — shared TypeScript interfaces and types.
- `src/constants.ts` — shared game constants and mode configuration.
- `src/style.css` — minimal reset and centering.
- `index.html` — keep the existing shell; point to `src/main.ts`.
- Tests for pure logic functions in `src/game.test.ts` and `src/main.test.ts` updates.

## Technical Notes

- Use plain TypeScript modules; no external runtime libraries.
- Keep bundle size small for js13kGames (emoji characters instead of image assets); do not sacrifice readability for premature minification since the build step handles that.
- Remove the existing `counter.ts` example, its test, and unused assets (e.g., SVG logos) once the game files are in place.
- Maintain strict TypeScript and the existing lint/testing setup.

## Build Size

- Add a Node script (`scripts/check-size.mjs`) that zips `dist/` and checks the archive size against the 13 KB limit.
- Add a CI step in `build.yml` that runs the script and fails the build if it exceeds 13 KB.
- Expose it as `npm run check:size` for local checks.

## Verification

- `npm start` runs the dev server and the game renders on canvas.
- `npm run lint:tsc` passes.
- `npm run test:ci` passes with 100% coverage on logic files.
- `npm run build` produces a minified bundle.
- `npm run check:size` verifies the zipped build stays under 13 KB.
