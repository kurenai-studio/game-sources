# FungiParty 菌子派对 — 设计文档

日期：2026-10-17
状态：v1 / v2 / v3 已实现

## 1. 这是什么

一个在安卓上跑的单机 3D 小游戏：可爱的圆润几何风格，玩家是一朵蘑菇，在一片森林里自由走动；森林中央有个菌子村，村里有建筑和 NPC，玩家通过玩各种小游戏赚蘑菇币，买皮肤、吃饭回体力。

为什么做：自己玩、身边朋友玩。不上架商店，不做在线，不做付费。

对标：蛋仔派对的「大厅 + 小游戏」结构，拆成单机版。

## 2. 目标 / 非目标 / 反目标

**目标**
- 手机上能跑、能摸到手里玩的完整体验。
- 一个让人愿意反复走一走的小世界，而不是一条走廊。
- 小游戏「一分钟能讲清规则，输了想再来一局」。

**非目标（这一版不做）**
- 联机。同屏多人留接口，但不实现第二个玩家。
- 商店上架、账号、云存档、内购。
- 手 K 动画、手绘贴图、高模。
- 剧情、对话系统。

**反目标（做成了算失败）**
- 走路手感黏、相机打架、帧数掉到 30 以下。
- 森林大而空，走两分钟没有任何可看的东西。
- 小游戏判定随机，玩家输了不服气。
- 系统先于内容：体力、货币、时间循环全做好了，但只有一个能玩的东西。

## 3. 约束

- 引擎 Godot 4.x 最新稳定版，MIT，免费，无版税。
- 目标平台 Android，只做横屏或只做竖屏二选一（待定，见第 11 节）。
- 单机、离线、本地存档。
- 开发环境是 Windows + 命令行，Godot 目前未安装。JDK 17 + Android SDK + adb 已就绪。
- 有一台可插线调试的真机，每期都以「APK 装在手机上跑」收尾。Mobile 渲染器需要 Vulkan；phase 0 用 `adb shell pm list features` 确认，不支持则整体退到 Compatibility 渲染器。
- 美术全部程序化生成，不依赖外部建模工具；音频允许用无版权风险的 CC0 素材。
- 一人开发 + AI 写代码：人不写 GDScript，负责试玩和判断。所以计划必须拆成自带验证命令的小单元，重依赖无头测试。
- `AGENTS.md` / `CLAUDE.md` 各自控制在 50 行内，格式参照 wee-count（项目概述 / 开发命令 / 技术约束）。

## 4. 已经定下的决定

### 4.1 技术栈

Godot 4.x。

排除过 Tauri：它在安卓上只是系统 WebView 外壳，3D 渲染全压给 WebView 的 WebGL，没有 GPU 性能分析工具、版本碎片化，而它的 Rust 端对游戏毫无用处——多一层壳，换不到任何东西。

Godot 之后做同屏多人不需要换引擎：一个场景多个 Player 节点，分屏用 SubViewport、同屏共享相机即可。将来要联机，Godot 4 内置 ENet + MultiplayerSpawner/MultiplayerSynchronizer，导出一个 headless 服务端就能跑；房间、匹配、反作弊要自己写，但那是「做在线」的成本，不影响现在。

渲染器统一用 **Mobile**，开发和导出都用它，从第一天就在真实渲染路径上。

### 4.2 美术方向

**圆润几何 + 卡通描边 + 强弹动**，由代码生成，可接受为最终风格（先做第一版看效果，效果不行再换）。

角色按 2D 概念稿（`refs/Creation_Image_1792213174285_1.png`，参考图不入库）还原：
- 红色伞盖压扁成球，带白色斑点（斑点用几何体或 shader 生成，不画贴图）。
- 米色小身子，胶囊/水滴形，肚子上有白色椭圆和黑色的 ×。
- 两侧各一只扁平的小手（像短胖的鳍，是手不是翅膀）。
- 脸在伞盖上（不是身子上）：两个圆点眼 + 一条弧线嘴。

「可爱」的八成来自弹动（走路上下颠、吃东西拉伸挤压、跳跃蓄力），代码就能给。这也是这套风格在没美术的情况下能达到 80 分的原因。

**菌子不止蘑菇。**后期会有木耳、松露、牛肝菌等不同菌子角色（设计稿还在做）。角色从一开始就按「部件」搭：菌盖（可换形状）+ 身体 + 手 + 脸。

不过现在只做一张菌盖，**不做通用的部件装配系统**——那东西是给五个角色用的，现在只有一个。只保证两件事：菌盖是独立 mesh，尺寸/扇度/斑点密度都是参数；角色逻辑（移动、动画、状态机）不碰任何 mesh。逻辑一定可复用，能不能只换参数就换出木耳和松露，等设计稿来了再说。

### 4.3 分期

分期原则：每一步都能玩，都能改。系统跟着内容走，不提前做。

- **v1**：森林 + 蘑菇角色 + 走跑跳 + 昼夜光照 + 手机触屏操作。无任何系统。
- **v2**：上课偷吃大赛（单人 vs 3 个人机）+ 蘑菇币 + **一个摊位**（不是村子，最多一个 NPC 老板）+ 一个皮肤。菌子村整体扩建仍排在 v3 之后。
- **v3**：体力 + 一天 = 一次游玩预算 + 饭店（需要至少 3 个小游戏才谈得上预算）。
- **之后**：菌子村扩建、更多 NPC、更多小游戏、同屏多人。

## 5. v1 详细：森林自由探索

### 5.1 世界

- 一片有边界的森林地形，第三人称视角下走完一圈 3~5 分钟。
- 地形用 Godot 的 `HeightMapShape3D`/网格手工或程序化生成的低起伏丘陵，不做复杂地形系统。
- 树、灌木、石头、草丛用几何体拼，`MultiMeshInstance3D` 批量画同一棵树，控制 draw call。
- 光照：一个 `DirectionalLight3D` + `WorldEnvironment`，不开实时 GI，不开 SSAO/SSR（安卓上吃帧），阴影分辨率压到够用就行。
- 天空用 `ProceduralSkyMaterial`。

### 5.2 角色

- 一个独立 scene（`player/mushroom.tscn`），内含角色 mesh、碰撞体、`AnimationPlayer`、脚本。
- 移动用 `CharacterBody3D` + `move_and_slide()`，参数：走/跑速度、加速度、贴地力、跳跃高度、空中控制。
- 程序动画：走路上下颠 + 左右微倾，速度快时幅度加大；起跳时拉伸、落地时压扁（squash & stretch），落地有 0.1 秒的缓冲。
- 面部朝向固定（脸在伞盖正面），不做骨骼动画。

### 5.3 相机与操作

- 第三人称：`SpringArm3D` 挂在角色上方，防止穿墙；鼠标/触屏拖动转视角，缩放固定或两档。
- 手机操作：左下角虚拟摇杆移动，右下角一个跳跃按钮。虚拟摇杆用 Godot 的 `Control` + 触摸事件自己实现，不引第三方插件。
- 桌面端（开发调试用）WASD + 空格，鼠标拖动转视角。

### 5.4 昼夜

- 一个方向光沿天空转，颜色随高度变化（正午白、黄昏橙、夜晚蓝），环境光同步变化。
- 一个全局时间管理器，暴露 `time_of_day`（0~1）和一个可调的时间流速。
- v1 里昼夜只影响光照和氛围，不影响任何玩法。

### 5.5 v1 明确不做

- 采集、拾取、可收集物 —— 第一版的核心动词就是「走、跑、跳、看」。不做物品、不做计数器。
- NPC、建筑、村庄。
- UI 除了摇杆和跳跃按钮之外的东西。（连主菜单都可以先不做，启动直接进森林。）

## 6. v2：上课偷吃大赛

### 6.1 规则（一句话）

四张课桌，一位老师。老师视线有预警地扫视；视线不在你身上时按住吃东西，视线来了就松手装样子。被看到 → 罚站 3 秒，累计 3 次出局。先吃满 N 口的人赢，时间到则进度最高者赢。

### 6.2 判定

- 老师视线必须有**可读的预警**（头先转 0.3 秒 / 视线锥先出现 / 音效先响），不能无故瞬移。整个游戏的技巧是「读视线 + 反应」，随机判定会让玩家觉得在掷骰子。
- 被看到的判定：玩家处于「吃东西」状态 **且** 玩家在老师视线内，持续超过一个极小宽限（约 0.1 秒，避免误触）。
- 被抓惩罚：罚站 3 秒（不能吃、只能装样子），累计 3 次出局。

### 6.3 人机 AI

不做「聪明」AI。每个 NPC：一个「胆量」参数 + 一个反应延迟分布。视线离开就开吃，视线来了延迟 X 秒停下，胆量越大延迟越长、被抓概率越高。目标是观感上有活人味，不是真的难打。

### 6.4 输入

单指操作：**按住 = 吃，松手 = 装样子**。进度条长在角色身上，老师视线在同一屏内，两个信息一眼能扫到。手机上不允许同屏需要两根手指以上的操作。

### 6.5 观感与反馈

- 吃东西时角色弹动、腮帮鼓起、食物变小。
- 老师看向玩家瞬间：屏幕边缘轻微暗角 / 音效变调。
- 被抓：定格 0.3 秒 + 老师表情变化，然后罚站。

### 6.6 IP

不复制多邻国「多儿」的具体形象。保留梗的内核——一只执拗的、会一直催你学习的猫头鹰式老师——用自己的形象，可以有相似的斜视眼神，但不是那只绿鸟。

### 6.7 起手数值（全部待调）

| 参数 | 起手值 |
|---|---|
| 局时长 | 90 秒 |
| 吃满获胜所需口数 N | 20 |
| 老师视线预警 | 0.3 秒 |
| 被看到判定宽限 | 0.1 秒 |
| 罚站时长 | 3 秒 |
| 出局阈值 | 3 次 |
| 老师扫视周期 | 随机 2~5 秒 |
| NPC 反应延迟 | 0.15~0.6 秒，按胆量分布 |

## 7. v3：体力与一天

### 7.1 结构

- 游戏内一天 = 一段真实时间（起手 10~15 分钟）。
- 每天开始恢复满体力。
- 小游戏有难度分层，越难花体力越多、给的蘑菇币越多。
- 体力归零 → 自动「太累了」过场到第二天早上；床只是加速睡觉的地方，不强制徒步回去。

### 7.2 数值方法（先定目标再反推，不要两个旋钮同时拧）

「日体力高 + 消耗低」是同一个旋钮拧两下，结果只是让体力永不成为瓶颈。正确顺序：

1. 先定「一天能玩几个小游戏」（起手 5~7 局）。
2. 一局 1~2 分钟 → 一天真实时长 10~15 分钟。
3. 日体力 = 该局数 × 平均花费。示例：日体力 100，易 5 / 中 12 / 难 25。
4. 蘑菇币定价一律换算成「几天能买到」：皮肤 = 3 天 / 1 周，而不是拍一个数字。

### 7.3 风险

单机没有内购，体力唯一作用是「强制你等」或者「塑造一天的生活节奏」。必须靠上面的预算调得刚好，否则它就是纯摩擦。v3 上线后要能用一句话回答「体力到底给玩家带来了什么」。

## 8. 数值怎么调

v2/v3 的所有可调数字集中在一个 `const` 文件或 `Resource`（.tres）里，不散落在代码中，方便一屏内对比调参。

## 9. 性能与目标设备

- 目标：中端安卓机稳定 60 FPS，低端机不低于 30。
- 预算：屏幕上可见三角面 < 60k，材质种类尽量少（减少状态切换），同屏 draw call < 150。
- 植被用 MultiMesh，阴影只开一个方向光。
- 禁止：实时 GI、SSAO、SSR、体积雾、每帧实例化节点。

## 11. 皮肤与 IP 元素

皮肤做成**数据**而不是代码：每个皮肤 = 一组颜色 + 菌盖形状 + 图案（`.tres` 资源）。

引入其他 IP 形象（小新、海绵宝宝、多儿之类）的规则。设计上是「像小新的菌子」而不是「变成小新」：本体始终是菌子，只拿配色、服饰元素、眼神/表情这些特征。

- 私人范围内玩，实际风险接近零。法律上这仍算改编（二创），但真正决定风险的是**可辨识度**和**暴露面**，不是法律定义。只拿元素的版本，被认出来和被告的概率都远低于直接搬角色的版本。
- 风险从三件事开始上升：把截图/视频发到公开平台、安装包在群里或网盘扩散、有人愿意为它花钱。国内平台对版权方投诉响应很快，真出事的形式是删内容/封号，不是打官司。
- 因此 IP 皮肤放 `skins/local/`，`.gitignore` 掉，永不进仓库、不进对外分发的包。自己手机上什么都能有，分享出去的包是干净的。
- 要公开发布时把特征再退一步：只留颜色印象，去掉服饰和原角色的脸。

## 13. 我的判断（标记为我的 call，可以推翻）

- 渲染器用 Mobile，从第一天就用真实路径；真机不支持 Vulkan 则整体退到 Compatibility。
- 虚拟摇杆自己实现，不引插件。
- v1 不加任何可采集物，先只有走跑跳看。
- 角色封成独立 scene，拆成「菌盖 + 身体 + 手 + 脸」四组，但只做蘑菇一张菌盖，不先做通用装配系统。
- 菌盖参数化（半径/扇度/斑点密度），不写死到 mesh 里。
- 参数集中管理，调手感不翻代码。
- **横屏**。探索视野和四人同屏课桌都更自然。
- 森林边界用**天然障碍**（水、悬崖、密林），不摆隐形墙。
