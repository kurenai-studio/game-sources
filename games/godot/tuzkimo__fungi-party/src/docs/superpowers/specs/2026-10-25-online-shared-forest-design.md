# 联机（v7）设计：共享森林 + 服务器权威

## 要解决什么

现在这个游戏是一朵蘑菇在自己手机上过日子：存档在本机，四款小游戏全是单机（同一台手机上顶多两人同屏）。
目标是有账号、有共享世界的联机：每个玩家一个账号，币、皮肤、保底计数都是自己的；登录后进入**同一座森林**，
能看见别的人在里面走；想和谁一起玩就邀请，对方同意就在同一局里玩，不同意（或没人可邀）就让现有的 人机顶上。

单机模式（含同屏双人）不退化，继续能离线玩。

## 目标 / 非目标 / 反目标

- 目标
  - 账号登录；钱包、已拥有皮肤、体力、保底计数、角色体型都在服务器上，掉线换设备也还在。
  - 共享森林：同一座森林里能看见其他玩家走动。
  - 四款小游戏（教室 / 传炸弹 / 猫头鹰 / 赛跑）由服务器判定，可邀请真人进场，空座位人机补齐。
  - 服务器是自己那台云服务器（x86_64 Linux，有 root）。部署一条命令就能更新。
- 非目标（本期不做）
  - 陌生人匹配、公开大厅、排行榜、交易、聊天、语音、好友列表、公会。
  - 多世界分线：一期一座森林，上限 8 人，满了就拒绝登录。
  - 超过 8 人的世界、距离裁剪、分线——都等到真的需要再说（见「带宽预算」）。
  - 一台手机两个账号（联机 + 本地 2P 时，2P 不是账号，只是主机上的第二个身体）。
  - iOS、离线缓存、断线续玩一局（断线即回登录）。
- 反目标（做到就算失败）
  - 任何客户端能决定自己的币、抽卡结果或局内名次。
  - 为了联机把单机模式砍掉或改差。
  - 客户端版本和服务器不一致还能静默连进去、跑出诡异状态。
  - 服务器重启或崩溃丢玩家数据。

## 硬约束（现状决定的）

| 现状 | 对设计的约束 |
| --- | --- |
| 代码已经是两层：`bomb_round` / `race_field` / `race_racer` / `owl_round` / `gaze` / `npc_seat` / `steal_eat` / `*_score` 是纯逻辑类（`RefCounted`，不碰节点）；`*_ui` / `*_arena` / `*_visual` / `seat_visual` 是表现 | 服务器只跑逻辑层，一份规则不写两遍。这是选方案 B 的根本理由 |
| **例外：赛跑的真人 `RacePlayer` 是 `CharacterBody3D`**，位置、撞击（`get_slide_collision`）、`hits`、`finish_time` 全来自 `move_and_slide()` 物理 | 服务器无法无头跑物理又要本地即时手感 → 真人也要改成纯数学模型（见决定表），离线模式一起改 |
| 各小游戏的**阶段机不在纯层**：猫头鹰的三关推进（`owl.gd` 的 `Phase.BREAK`）、四款的倒数与 `_settle` 结算都在编排脚本里，且直接写 `Save` | 阶段机和结算要一起上移到服务器会话里；这是可预料的搬迁量，不是未知 |
| 森林生成是确定性的（`ForestGen.seed_value = 1`，地形固定，POI 固定） | 地形不需要联网同步，客户端各自画各自的一样森林 |
| 小游戏都是 `change_scene_to_file` 的独立自包含场景 | 「一局」= 服务器上的一次会话，客户端只是租了张画面 |
| 存档是单份 `ConfigFile`（`Save` 全是静态函数） | 服务器上改成「一个账号一条记录」；`Save` 变成在线/离线两个实现共用同一个字典形状 |
| 触屏是自绘 `Control`（`TouchControls` / `EatInput`），按屏幕左右半分人 | 联机时客户端全屏只控制座位 0，上送的就是「座位 0 的输入」 |
| 规则：体力派生天色（`Day.day_time`），全项目只有一套公式 | 共享世界里天色必须所有人一致 → 天色改由**服务器世界时钟**驱动，体力只决定能不能开局 |
| Godot 锁 4.7.2 | 服务端必须与客户端同版本同构建，握手校验版本号 |
| Android 导出预设没有 INTERNET 权限，也没有 Linux 服务端预设 | 第一期就要建这两个预设，先打通再写业务 |
| 存档里体型/皮肤走 `SkinCatalog` / `BodyCatalog` 校验 | 服务器也是同一份校验，客户端传来的 id 一律 `normalize` |

## 方案与选择

- **A：服务器只转发字节，森林由一台手机当房主。** 服务器代码最少，但房主退出要「迁都」（世界状态交接），
  房主手机还要算全员移动，延迟不公平。省下的服务端代码会在客户端用三倍还回去。
- **B：Godot 无头服务器跑同一份工程，森林和局都由服务器权威（采用）。** 一份逻辑两端跑；
  服务器永远是房主，没有迁都；钱包和抽卡天然防作弊；手机只渲染，帧率反而更好。
  代价：要学 Linux 服务端导出 / systemd / 服务端日志；世界是常驻进程，改版本要踢人重启。
- **C：森林在服务器、小游戏点对点直连。** 省服务器 CPU，但 Android 家庭网络打洞成功率差，还得回落到中继。

选 B。唯一理由：这是唯一不需要把四款小游戏规则写第二遍的方案。

## 关键决定

| 决定 | 理由 |
| --- | --- |
| 服务端 = 同一工程的 Linux headless 导出，跑逻辑层 | 复用 `*_round` / `*_field` 等纯逻辑；不引第二语言 |
| 钱包 / 抽卡 / 体力 / 局内名次全部服务器计算 | 客户端只发「我要抽一抽」「我要扔左边」，不发结果 |
| 同步用手写 RPC 快照：森林 15 Hz、局内 20 Hz | 比 `MultiplayerSynchronizer` 的节点树对齐少踩坑；数据量小，好查 |
| 自己的人物本地立即动（客户端预演，不回滚）；远端实体插值 | 不回滚的复杂度只有插值那几十行，手感也够 |
| 座位规则不变：真人占 `0..n-1`，人机从 `n` 往后 | 现有「座位号 = 数组下标」的假设全部不动，`Party` 的语义变成「本局的 roster」 |
| 局的 roster 由服务器定，开始前下发 | 客户端不需要知道谁是人机，只照着 roster 画 |
| 邀请是服务器的配对：森林里选中某人 → 服务器转发邀请 → 同意则两人进同一局 | 不做好友列表和大厅，一次一条邀请，拒绝就人机顶上 |
| 账号：昵称 + 密码，走 challenge-response | 密码不过网：服务器发 nonce，客户端回 `hash(派生密钥 + nonce)`；服务器存加盐迭代哈希。不需要 TLS / nginx |
| 在线时存档只在服务器，单机模式用本地 `user://save.cfg` | 不做双向合并，避免两处真相打架 |
| 首次登录且账号为空时，可一次性并入本机存档 | 老玩家不丢已经抽到的皮肤 |
| 天色由服务器世界时钟驱动，体力只决定能不能开局 | 共享世界里天色必须唯一；这条**要同步改 `AGENTS.md` 的「体力派生天色」规矩** |
| 世界时钟按真实时间走：一天 = 真实 4 小时（服务器配置） | 常驻世界没有「玩家自己的夜晚」；4 小时是「一天玩两三轮」的凭感觉值，可调 |
| 睡觉一天一次（`day` 字段仍归账号，日序号来自世界时钟） | 天色收归服务器之后，不设限的话连睡连玩，体力门槛直接作废 |
| 赛跑的真人改成和 `RaceRacer` 同一套纯数学模型：前进是纵向速度、左右是横向位移、跳跃只是「y 够高就跨过矮栏」的一个判定；离线模式一起换 | 一份代码两端跑；不做物理也就没有回弹补偿和权威判定冲突。代价：赛跑手感要拿 `RACE_*` 重调一次 |
| 森林里服务器不跑物理 | 玩家之间本来就不碰撞，8 个人的森林跑物理毫无意义。服务器只管在线表、位置广播（带速度上限校验）、POI 开局合法性（自己算距离）、邀请配对、世界时钟 |
| 局里有人断线，该座位立刻换人机接着打 | 局不中断、结算照记在他的账号上；比「等人回来」和「收局」都便宜，也不坑同局的人 |
| 谁玩谁付体力：被邀请者付自己的，付不起就别进（邀请方看到「对方太累了」） | 钱包和体力都是账号的，代付要新账，不做 |
| **同屏双人也能联机**：本地 2P 是「这台手机上多出来的那个人」，占 1 号座位，走会话状态（`Party`），不占账号、不写盘 | 一个人拉着朋友玩，不想让他为了一次性陪玩去注册 |
| 本地 2P 不额外扣体力、打出来的币进主机账号 | 一台手机一份钱包，和现在单机双人完全一致；要分开算就是两本账，不做 |
| 一局的座位顺序：本地座位先占（0 = 主机，1 = 本地 2P），远端按接受邀请的顺序往后排，剩下的填人机 | 沿用「真人占 0..n-1」的老规矩，人机永远在末尾 |
| 远端玩家不参与物理碰撞 | 单机里两人互相顶开的行为不能跨机器同步，否则两端物理分歧；本地玩家照旧撞地形和树 |
| 服务端存储：一个账号一个 JSON，写临时文件再 rename | 几十个人不需要数据库；rename 防半截文件 |
| 服务端**只跑 RefCounted 规则模型，绝不实例化 3D 场景** | 实测一个 Godot 无头进程常驻 94 MB，跟在线人数无关（30 人在线只多 0.4 MB）；但一个 Node3D 小游戏场景就是几十 MB，2 个房间就吃掉整台机器 |
| 目标机器按 2 核 2G、和别的项目混部来定 | 实测 30 人森林约 0.4 个核；这台机器只够「森林 + 1 个小游戏房」 |
| 部署：systemd 接管 + 自动重启，日志走 journald，版本号在启动日志里打一行 | 一个人维护，出问题靠 journalctl 一眼看 |
| 服务器重启不持久化世界 | 森林是确定性的、局是短会话，重建世界比持久化便宜得多；账号数据是另一回事，必须落盘 |

## 各场景怎么改

- **启动**（现在开机直接进森林）：加一层「单机 / 联机」入口；联机先登录（昵称 + 密码 + 服务器地址）。
- **森林 `main.tscn`**：本地玩家照旧（移动、镜头、POI 触发）。远端玩家是只显示不碰撞的替身，
  体型/皮肤来自快照，不读本地存档。POI 面板加「邀请」入口：列出森林里的其他玩家，选中发出邀请。
  同屏双人的 `Party`/`leader` 逻辑只在单机模式生效。
- **四款小游戏**：逻辑类搬到服务器 tick 循环里跑；客户端编排脚本从「自己算 + 读本地输入」改成
  「读快照 + 上送座位 0 的输入」，`*_ui` / `*_arena` / `*_visual` 基本不动。局结束由服务器发结算，
  客户端只放演出。体力扣除从各场景 `_ready` 移到服务器开局前。
  阶段机（倒数、猫头鹰三关之间的 `BREAK`、`_settle`）跟着上移；客户端不知道「现在是第几关」，只照着快照画。
- **赛跑**：`RacePlayer` 换成一个 `RefCounted` 的纯数学模型（和 `RaceRacer` 共用撞击判定与赛道数据），
  跳跃退化成「高度 > 矮栏高度就不算撞」。离线模式也走这一套，`RACE_*` 参数要重调一遍。
- **帐篷 / 睡觉**：世界时钟取代「体力派生天色」；睡觉改成「今天还没睡过才让睡」，只重置自己的体力，
  不改天色、不影响别人。`DayLoop` 从「睡觉推进一天」变成「读服务器时钟推天色」，单机模式下保留原来的行为。
- **森林服务器侧**：只维护在线表、世界时钟、位置广播与校验、POI 开局请求、邀请配对；不加载地形、不跑物理。
- **摊位 / 饭店 / 帐篷**：币、皮肤、体力都改成请求-应答；抽卡由服务器掷，客户端只播放结果演出。

## 分期（每期结束都能真机玩）

1. **骨架**：Linux 服务端预设 + 无头构建 + systemd 部署脚本；账号注册/登录/challenge-response；
   存档搬服务器（含本地存档一次性导入）；单机模式原样保留；启动菜单区分两种模式。
   这一期结束时联机还只能看到自己一个人，也没有小游戏可连。
2. **四款小游戏上服务器**：一次一局，roster 由服务器定，空位人机；结算回森林。
   单人开局先跑通，再接通「邀请 → 接受 → 同场」。顺序是 教室 → 传炸弹 → 猫头鹰 → 赛跑：
   前三款吃掉「逻辑上移到服务器」的通用部分，赛跑额外要做物理体换纯模型 + 手感重调，放最后。
3. **共享森林**：位置广播、他人替身、在森林里看见别人走动、从森林里邀请、服务器世界时钟的天色。

## 风险

- **反应类小游戏的手感**：猫头鹰接糖、传炸弹、赛跑都吃反应，跨网 100~150 ms 会比同屏难受。
  备选是把输入延迟做齐（所有人齐 3 帧），但那是第二期实测之后再决定的事。
- **赛跑手感要重调一次**：把物理体换成纯模型是这份设计里唯一一处「离线模式也跟着变」的改动，
  `docs/perf-log.md` 之外还需要一份手感对照（起跳时机、撞墙反馈、冲刺节奏）。
- **第一次打通部署链路之前不写任何业务代码**：Linux 模板、预设、systemd、防火墙都是新东西，
  卡住的地方通常不在这份设计里。
- **断网/切网**：一期只做「断线回登录」，不做无缝重连；WiFi 和 4G 切换必定掉线。
- **带宽是这台机器真正的天花板（实测数据，别信感觉）**：5 Mbps 出口、实际上线 3~4 人。
  现在的做法是「每 0.1 秒把所有人的位置发给所有人」，实测：4 人 0.3 Mbps、8 人 1.1 Mbps、16 人 4.1 Mbps、32 人 16 Mbps。
  所以森林硬上限 **8 人**（1.1 Mbps，留 4 Mbps 给小游戏和别的事情）。超过 8 人要先做距离裁剪或降频，那是另一个决定。
- **单包上限**：8 人一份世界快照约 1.7 KB，离 `NetProtocol.MAX_PACKET`（8 KB）很远；
  但超长包现在会被静默丢掉，已经在 `_send` 里改成报错，别让它变成「服务器突然不广播」。
- **账号安全按朋友范围设计**：没有找回密码（忘了找服主重置），没有封禁，没有限流以外的东西。

## 一期不做、但要说清楚的事

- 没有找回密码：忘了登录邮箱也没用，找服主在服务器上重置。
- 没有好友列表：邀请只对「此刻在同一座森林里的人」有效。
- 没有断线重连：掉线回登录界面，重登即重新进森林（局里的座位已经换人机了）。

## 留给建的人

- 网络代码的目录与命名（建议 `game/net/`，服务端入口一个 `server_main.gd`）。
- 快照的字段、插值系数、丢失快照的容忍。
- 重连退避的具体参数。
- 端口、tick、人数上限这些数字放 `Config` 还是服务端自己的配置文件。
- 每一款小游戏「逻辑上移」的具体切法：哪些字段进快照、哪些纯表现留在客户端。
