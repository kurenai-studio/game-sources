# Utopian pixel-art integration

This project contains the complete artwork under `assets/utopia` and loads it
through `core/src/main/java/com/dungeonrpg/UtopiaAssets.java`.

## Runtime mapping

- `MenuScreen`, `MultiplayerMenuScreen`, `ClassSelectScreen`, and
  `GameOverScreen` use `backgrounds/menu_rooftop_1280x720.png` and the shared
  white/grey, red, and blue UI palette.
- `DungeonScreen` replaces geometric cells with the 64x64 atlas. It selects
  wall edges from neighbouring walkable cells, varies clean floor panels
  deterministically, and draws the matching stairs and chest tiles.
- The wall family uses a dark graphite and cool steel-grey palette. Floors,
  props, red/blue accents, wall topology, and collision behavior are unchanged.
- `DungeonScreen` selects four-direction idle/walk frames for the chosen hero
  and idle frames for visible enemies.
- `CombatScreen` uses the atrium background, class battle sheet, and enemy
  battle sheet. Attack, skill, guard, hurt, and defeat poses follow the
  resolved turn without changing combat calculations.
- `PvPCombatScreen` uses the same arena and human class sheets on both sides.
  The right-hand player uses mirrored regions created once during asset load;
  host authority and the LAN message format remain unchanged.

## Frame layouts

Playable top-down sheets use 64x96 frames, six columns, and four rows:
`Down`, `Left`, `Right`, `Up`. Columns 0-1 are idle and columns 2-5 are walk.

Playable battle sheets use 128x192 frames with these rows:
`Idle`, `Attack`, `Skill`, `Guard`, `Hurt`, `Defeat`.

Enemy top-down sheets use 64x96 frames, four columns, and four direction rows.
Enemy battle sheets use `Idle`, `Attack`, `Hurt`, and `Defeat` rows.

## Sci-fi player roster

The legacy enum and asset identifiers remain unchanged so existing saves and
sprite paths continue to work. Every user-facing name, description, HUD label,
combat log, and class-selection screen uses the new operative identity.

| Compatibility ID | Display name | Combat role | Tech skill |
| --- | --- | --- | --- |
| `WARRIOR` | Sentinel | Armored frontline defense | Breach Pulse |
| `MAGE` | Hacker | High-energy system attacks | System Overload |
| `THIEF` | Sniper | Fast precision critical strikes | Deadeye Shot |
| `GRAPPLER` | Enforcer | Heavy close-range damage | Kinetic Slam |
| `CLERIC` | Bio-Medic | Balanced combat support | Nano Disruptor |

## Sci-fi enemy roster

The legacy enum and file identifiers remain unchanged for save compatibility,
but their display names and artwork now map to the following utopian designs:

| Compatibility ID | Display name | Visual design |
| --- | --- | --- |
| `CAVE_SLIME` | Recon Drone | Compact hovering combat drone with a white shell, blue optic, and red fins |
| `BONE_SENTINEL` | Aegis Robot | Human-sized security automaton with segmented armor and a forearm emitter |
| `ABYSS_MAGE` | Helix Cyborg | Human operative with a visible face, augmented eye, mechanical arm, and projector |
| `FLOOR_WARDEN` | Enhanced Warden | Enhanced human boss with exposed skin, implants, heavy armor, and an energy blade |

The engine-ready sheets are generated by `tools/generate_sci_fi_enemies.py`.
Its output preserves all original sheet dimensions, row order, frame counts,
transparency, and nearest-neighbour pixel filtering.

## Packaging

Development runs resolve paths from the project root. The `lwjgl3:dist` task
also embeds the complete `assets` folder in `PROJECT-Enigma.jar`, so the textures
remain available when the jar is moved elsewhere.

All textures use nearest-neighbour filtering and are shared for the lifetime
of the game. `ProjectEnigmaGame.dispose()` releases them exactly once.
