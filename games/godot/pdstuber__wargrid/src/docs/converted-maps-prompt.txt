Decided (user, 2026-11-08; the brainstorm builds on these, it does not reopen them):
- Online map agreement: the relay changes and is redeployed (deploy still needs my approval). Protocol goes to 2, so old clients and relays refuse each other with "protocol mismatch". The host picks the map, the joiner follows (Join has no map picker). The host's `hello` carries an opaque `settings` JSON object; the relay stores it exactly as sent and copies it into `start` without reading it (precedent: Recoil forwards its start script, and its dedicated server needs no map). This task puts `map` and `map_hash` in it. Expected, not decided (M9 planning confirms): M9 puts its chosen starts, teams and bot slots there without a relay change, and a later replay check can use the stored copy. The relay adds a `seed` to `start`, outside the blob, so a tampered host cannot steer random starts; offline uses a local random seed.
- Mismatch: the joiner hashes its own map file and refuses with a clear message before the simulation exists (like Zero Hour's map CRC, GameInfo.cpp:618-656, and OpenRA's map UID). Dev builds share one version string, so `hello.build` alone does not guarantee the same map files. A `start` without `settings` is a protocol error, never a fallback to skirmish.json.
- Start spots: Zero Hour's rule (GameLogic.cpp:944-1027, the live `#else` branch): chosen spots are taken first (none in this task), the first random slot gets a random start from the seed, each later one the free start with the largest summed straight-line distance to the taken ones, teammates the free start closest to their team. On Ashfall a 1v1 gets a random diagonal pair. One code path offline and online; it takes the taken spots as input so M9's chosen starts drop in.
