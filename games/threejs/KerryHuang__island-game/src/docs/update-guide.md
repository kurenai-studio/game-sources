# 議題更新守則

`data/issues.json` 的每一次更新，不論人工更新或例行任務，都照這份守則做。

`data/issues.json` 是今日群島唯一會隨時事變動的檔案。城市是虛構的，議題取材自近期台灣的真實新聞。

## 不能做的事

- **不能看起來替某一方背書。**
  - `views` 要並列至少兩種不同立場，篇幅和語氣對等。
  - 不用帶有評價的形容詞，例如「荒謬」「德政」「爭議性」。
- **不寫真實人名。** 政治人物、記者、網紅一律不寫，立場只用角色描述，例如家長團體、市府、業者、學者、通勤族、議員。
  - 新聞裡的政黨名稱也不寫，改成「執政方」「在野方」。
- **不捏造。**
  - 每則議題都要有實際讀過的報導當來源。
  - 文字裡的數字一定要出自來源，並寫成「報導指出…」。
  - 讀不到原文、只看到標題的報導不收。
- **沒把握就不改。** 寧可少一則，也不收一則來源不穩的議題。

## 欄位

| 欄位 | 規則 |
|---|---|
| `id` | `<島縮寫>-<YYYY-MM>-<slug>`，建立後不再改 |
| `name` | 12 個字以內的名詞片語 |
| `en` | 英文名稱，5 個字以內 |
| `model` | 現有 15 種模型之一 |
| `status` | `new`／`debating`／`progress`／`settled` |
| `heat` | 0 到 3 的整數，全城 heat 3 最多 6 則 |
| `what` | 一到兩句 |
| `why` | 一句 |
| `views` | 2 到 3 筆 `{ who, says }` |
| `sources` | 1 到 3 筆 `{ title, outlet, url, date }` |
| `updated` | 這次寫入的日期 |

下面幾點補充表格放不下的規則：

- **`model`** 只能從這 15 種選，挑外型最貼切的：
  - `house`：住家、社區
  - `hall`：機關、大型設施
  - `booth`：攤位、服務點
  - `classroom`：學校
  - `clinic`：醫療、照顧
  - `busstop`：公車、大眾運輸
  - `bikes`：單車、步行
  - `court`：運動場
  - `farm`：農業、食物
  - `river`：水、河岸、道路
  - `stage`：表演、活動
  - `book`：圖書、出版
  - `coin`：錢、補助、價格
  - `clock`：時間、時段、期限
  - `globe`：數位、國際
- **`status`** 怎麼判斷：
  - `new`：剛被提出。
  - `debating`：各方在吵。
  - `progress`：有預算、法案、試辦或時程。
  - `settled`：已經通過或上路。
- **`heat`** 怎麼給：
  - 3：近 7 天多家媒體報導。
  - 2：有持續報導。
  - 1：一週以上沒有新報導。
  - 0：已經沉寂，下次移除。
- **`what`** 寫發生了什麼，不加評論。
- **`why`** 寫這件事怎麼碰到一般人的日常，用「你」開頭也可以。
- **`sources`** 至少一筆的日期要在 `updated` 之前 14 天內。網址必須是 https，而且要用 WebFetch 讀得到內文。

## 每座島收哪類新聞

| 島 | 新聞分類 |
|---|---|
| `traffic` 交通 | 大眾運輸、道路安全、停車、通勤 |
| `care` 托育 | 托嬰、幼兒園、育兒補助、生育 |
| `edu` 教育 | 中小學、課綱、校園、升學、教師 |
| `elder` 長照 | 長照服務、高齡、照顧者、失智 |
| `sport` 運動 | 運動場館、全民運動、賽事、體育政策 |
| `green` 綠地 | 公園、行道樹、都市綠化、氣候調適 |
| `culture` 文化 | 圖書館、藝文、文資保存、出版 |
| `youth` 青年 | 就業、居住、租屋、創業、薪資 |
| `digital` 數位 | 數位政府、資安、AI、網路服務 |
| `safety` 安全 | 防災、治安、消防、詐騙 |
| `eco` 環保 | 垃圾、回收、空汙、能源、食農 |
| `tour` 觀光 | 觀光、夜市、旅宿、國際旅客 |

全國性的新聞也可以收。城市是虛構的，議題只要一般城市居民會碰到就可以。

## 每次更新的步驟

1. 讀現有的 `data/issues.json`。
2. 依上表搜尋近 7 天的新聞。
3. 決定改動：新增議題，更新 `status`、`heat`、`views`、`sources`，移除 heat 0 的議題。**每次最多改 8 則。**
4. 沒有新報導的舊議題，heat 降 1。
5. 跑 `node scripts/validate.mjs`，必須輸出 `ok`。
6. 跑 `node --test tests/*.test.mjs` 與 `sh build.sh`。

## 改動表格式

例行任務直接推 main 時放在 commit 訊息內文，開 PR 時放在 PR 內文。

```
## 議題更新 YYYY-MM-DD

| 島 | 議題 | 改動 | 來源 |
|---|---|---|---|
| 交通 | 捷運尖峰加班車 | 新增 | [某報 10/28](https://…) |
| 托育 | … | heat 3→2 | — |

驗證：validate ok N issues；tests pass；build ok
```

沒有值得改的就不提交。
