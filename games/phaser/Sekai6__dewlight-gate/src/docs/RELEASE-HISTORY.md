# 晨露之门 · DEWLIGHT / GATE

## Boss 战斗大修

- **攻击有回应**：战斗中按住 J 连击，普通命中削 1 点生命；疲惫或藤蔓束缚时削 2 点，显示伤害数字、不同音高与命中停顿。近战命中范围更宽，命中补回 5 点光能。
- **两种招式**：红色箭纹标出冲锋路径和停止位置，预警后不再追踪；金色地纹预告向两侧扩散的根浪，可空格跳过。每次攻击后有 2 秒疲惫窗口。所有预警同时使用形状、动作与文字。
- **束缚是战术选择**：K 打断冲锋或根浪，清除已发出的根浪，打开 2.1 秒破绽。施放后 5.5 秒可再次束缚，头顶小环显示恢复，失败提示解释剩余时间；不用束缚也能通关。
- **看清双方**：战斗镜头容纳整座空地，血条与招式提示固定在场地上方；战斗时收起主线横幅和箭头，主角绘制在 Boss 前方。
- **动作与重试**：Boss 有后仰蓄力、冲锋步态、举臂踏地、疲惫下沉与受击闪光。战斗中按 R 回空地入口，清掉危险与输入，恢复资源并保留四点微光。

实机键盘录像：[Boss 对决](artifacts/boss-rework/duel.webm)。`node scripts/boss-playability.mjs` 检查不用束缚、使用束缚及不躲避三种策略；`node scripts/boss-rework-capture.mjs` 生成键盘战斗录像。两个脚本都定位初始遭遇，之后通过正常战斗控制推进；完整 GATE 到结尾的验证仍由引导路线提供。模拟和自动键盘控制的熟练速度不代表首次玩家时长，也不能替代个人体验评价。

## 第一关重构 · 露冠守卫

第一关改为单向短路线：**GATE → 三个矮台与四点微光 → 露冠守卫 → 晨露碑 → 晨光之门**。去掉原先高、中、低三层反复横穿的必经路线；蕨叶浅溪保留为可选庭院。第一关主线平台从多层长廊收缩为地面与三个矮台，首次灯环在出生点右侧可见。

- 四点微光接通后，空地中的露冠守卫苏醒。进入战斗时补满生命与光能；地面无深坑。
- 守卫先以红色冠冕和地面箭纹预告冲锋，方向在预警时锁定。跳过或冲到身后。普通攻击持续有效，冲锋后的疲惫窗口造成双倍伤害。
- K 可打断动作并束缚 2.1 秒，施放后 5.5 秒可再次束缚；脚边金色根纹预告第二种根浪攻击，用空格跳过。
- 削尽 36 点生命后，守卫恢复平静并开放晨露碑，恢复玩家资源。剧情记录到日志，奖励只计一次。
- 战败从空地前重试，保留四点微光；刷新时未完成的战斗重新开始，已击败结果永久保存。已通第一关的旧存档直接保留通关状态。
- 唤醒晨露碑后，到右侧发光门按 E 进入玻璃阶地。进入下一地区后也可按 E 回访第一关与可选浅溪。

主线共 20 枚灯环，可选浅溪另有 4 枚，不再要求全部收集才能前往第二关。完整引导控制验证见 `artifacts/guidance/route-report.json`；第一关定位画面与录像见 `artifacts/first-chapter`，可用 `node scripts/first-chapter-capture.mjs` 重现。

以下旧版本美术和性能记录用于保留迭代历史；当前关卡节奏以本节与最新路线报告为准。

## 本轮体验打磨

- 主角慢走与跑动使用贴地支撑、抬脚回收和双腿错相，膝关节按髋部与脚踝连接；跑步有更高抬腿、更明显前倾。动作序列见 `artifacts/experience/hero-actions.png`。
- 战斗命中加入短暂菱晶闪光和散开的玻璃碎片，与挥剑光弧、方向火花分层；减少动态时关闭新增闪光和碎片。
- 冲刺支持 0.12 秒提前输入；暂停会同时清理按键、技能缓冲与底层事件队列，防止恢复时意外出招。
- 刷新后从最近有效安全落脚处继续。标题显示位置、灯环进度与用时；旧存档兼容，非法位置退回检查点。
- 暂停页可回到检查点，恢复生命与光能并保留收集；已唤醒石碑可反复按 E 休憩。
- 附近同层玻璃珠轻柔吸附，连续收集显示简短回执。低生命、光能不足时显示状态提醒。
- 音量、静音、减少动态、引导、镜头震动与清晰界面独立保存；音量为零时不产生音效。

运行与构建命令见下文。新增实机画面可运行 `node scripts/experience-capture.mjs` 生成；截图中的动作排列与收集场景是专项展示，不作为通关证据。

一段青绿、奶白与浅金色的横版冒险。提着玻璃灯走出 GATE，在晨露庭院、玻璃阶地与藤冠高台唤醒三座石碑。

## 本地运行

需要 Node.js 22.12+（或 20.19+）。在本目录运行：

```sh
npm install
npm run dev
```

打开终端显示的地址，默认 http://127.0.0.1:5173 。Windows PowerShell 若阻止 npm.ps1，请使用 `npm.cmd install` 和 `npm.cmd run dev`。

```sh
npm run build
npm run preview
```

生产文件位于 `dist/`，可部署到静态服务器。不要直接双击 HTML 文件。首次安装需要网络，游戏运行不访问外部 API、不加载网络字体和图片。

## 操作

| 按键 | 动作 |
| --- | --- |
| A / D、← / → | 左右跑动，按住 C 慢行 |
| 空格 | 跳跃，支持离地宽限与输入缓冲 |
| S / ↓ + 空格 | 从当前平台向下穿过；地面不会穿透 |
| J | 近战攻击 |
| Shift | 冲刺，冷却 1.1 秒，短暂伤害保护 |
| K | 前方藤蔓：25 光能，敌人定身 3 秒 / 叶片平台固定 5 秒 |
| E | 调整棱镜、唤醒石碑、读取记忆 |
| Tab | 打开旅程、日志、背包和操作说明 |
| Esc | 暂停 / 返回 |

旅程分为三个地区、六座花园。第一关采用前述单向短路线。后续花园有高处树冠、中层溪流和低处根脉，沿四盏灯环探索后前往光门。HUD 会随进度提示下一盏灯的位置，Tab 可查看地图。

晨露庭院前半段没有敌人或深坑，学会移动、跳跃与交互后，后半段引入露冠守卫。第二地区引入地面苔影、间隙和浮动平台，第三地区再加入飞行敌人。第一关守卫后有晨露碑；之后每两庭末尾有一座石碑。

四种灯环有不同的引光方式：

- 普通灯环：靠近后按 E。
- 折光灯环：按 E 旋转明亮指针，与外圈金色刻痕重合后接通。
- 叶片灯环：靠近脚下带叶片的浮台，先按 K 固定，再按 E。
- 守卫灯环：先用 K 暂时束缚守卫，或用 J 击败它，再按 E。

玻璃珠是永久收集记录，无需花费。敌人攻击有暖红色圆环预警。光能会恢复，无需寻找补给；冲刺可以帮助跨越间隙。叶片平台和守卫束缚可反复触发，不会因失败耗尽机会。

5 格生命，坠落扣一格并回最近安全落脚处；倒下恢复到最近激活石碑，生命和光能回满，收集与石碑进度不丢失。三碑激活后进入结尾，可继续收集或重新开始。

## 存档与设置

进度保存在本机浏览器 `localStorage`，约每三秒及关键事件自动保存。刷新后从标题页继续，在有效安全落脚处或石碑检查点恢复。清理浏览器数据会清空存档。存储被禁用时可继续当前游戏，但无法保存。

重做关卡使用独立的 `dewlight.save.v2` 存档，保留旧版 `dewlight.save.v1` 数据但不加载旧地图进度，以免旧坐标或机关 ID 导致无法继续。

旅程菜单与浏览器切换标签时暂停世界。标题 / 暂停菜单提供静音、音量和减少动态效果；音量和减少动态设置会保存在本机，画质选择会保存在本机。音效由 Web Audio 合成，首次操作后启用。

## 实现与限制

TypeScript + Vite + Phaser 3；游戏画面为程序绘图，菜单使用 HTML/CSS。没有后端、账号、分析跟踪或付费依赖。暂未发布 GitHub。

首版面向桌面键盘，推荐 1280×800 或更大窗口，不提供触屏按键。主线已缩短，实际时间随探索、冲刺频率和熟练度变化。包含第一关小 Boss 露冠守卫；没有商店、装备或技能树；存档不保存敌人生命和精确站位，重新载入后敌人恢复，已获得的掉落不会重复计数。

## 本轮画面与性能

三地区分别使用暖色晨雾、玻璃尖塔和藤冠巨藤；角色、敌人、石碑与动作特效均在本地生成。旅程页有花园插画与当前位置。可运行 `node scripts/motion-capture.mjs` 录制短动作演示，或运行 `node scripts/performance.mjs` 查看当前机器的帧时间（保持开发服务器在线）。

基础画面使用 Phaser Canvas，另提供真实 WebGPU 后处理合成。生命周期测试覆盖浏览器焦点变化；自动化浏览器的后台标签可见性有限制，详见 AUDIT.md。

### 主角动作改进

主角采用 180 帧自制程序绘图，区分呼吸待机、慢行、跑动、起跳与下落、挥刃、藤蔓施法、冲刺及受伤。按住 C 可慢行，移动具有短暂起步与制动；攻击约 85 毫秒蓄势后判定命中，单次挥刃只扣一次生命。动作总览位于 `artifacts/motion/animation-sheet.png`，运行 `node scripts/animation-sheet.mjs` 可从开发服务器重新导出。

### 苔影与战斗

- 地面「苔甲」披着苔藓背壳和玻璃芽，空中「璃翅」有四片叶脉玻璃翅和种灯腹部。两者具有巡逻、蓄势、扑击、恢复、受伤、束缚与消散动作；美术均本地生成。
- 敌人蓄势时锁定方向，暖金色方向区与收紧圆环提示扑击路线。可以退开、跳跃、冲刺穿过，或用 K 打断。束缚解除后会重新预警；扑击不会越过所在平台边缘。
- 连续按 J 可交替使出下劈和上挑，冷却结束前 140 毫秒的攻击输入会缓存。命中会打断敌人并产生约 45 毫秒停顿、碎光和小幅后退；「减少动态效果」关闭命中震动与停顿。
- 步频跟随实际移动距离；石台更新为圆润层岩与垂根。
- 动作图集：`artifacts/motion/creature-sheet.png`；两类敌人的键盘战斗演示：`artifacts/combat/mossback.webm`、`artifacts/combat/glasswing.webm`。运行 `node scripts/creature-sheet.mjs` 与 `node scripts/combat-capture.mjs` 可重新生成，需先启动开发服务器。定位演示不作为整段通关证据。


## 六花园美术与 WebGPU 画质

打开[六花园画面巡览](artifacts/art-tour/index.html)，可切换普通绮梦与 WebGPU 截图，并查看场景录像。截图为定位美术评审，不作为完整通关证据。

- 晨露庭院：晨雾、月环、浮岛花瀑、露水花与自然洞门。
- 玻璃阶地：彩玻璃天体、晶体柱廊、观测台与悬钟温室。
- 藤冠高台：古树、种灯、巨根圣所和蔓生花冠。
- 六花园各有独立地标；三座石碑分别使用露滴、晶体和花叶纹样。增加前景遮叶、分层雾、飘瓣和悬饰。
- 挥刃增加折光刀带，命中产生玻璃碎片、露珠与叶片；冲刺带流光，唤醒石碑出现上升光柱。

在标题或暂停页的「画质」中选择：

| 档位 | 实现 |
| --- | --- |
| 轻盈 · 兼容 | Canvas，减少动态装饰数量 |
| 绮梦 · 推荐 | Canvas，完整场景与氛围层，默认档 |
| 绮梦 · WebGPU | Canvas 场景上传 GPU，执行线性高光提取、双尺度横纵模糊、散射合成与 GPU 实例粒子绘制，加入辉光、折射、光束与细微焦散 |

WebGPU 是独立的真实 GPU 合成器，并非 Phaser 原生 WebGPU 渲染器。中间辉光纹理使用 rgba16float，最终输出仍为 SDR；输出最高 2560×1440。需要支持 WebGPU 的浏览器以及 localhost / 127.0.0.1 或 HTTPS。不可用、初始化失败或设备丢失时自动回退普通绮梦，不丢失旅程。减少动态效果会抑制额外动态。

本机 AMD Radeon 8060S、完整 Chromium 已验证真实 GPU 提交、跨地区、DPR 2 缩放与设备丢失回退。默认 Playwright headless-shell 无适配器；原生测试使用完整 Chromium。1440×900、DPR 1、每档独立采样 180 个浏览器动画帧，三档中位约 10ms、P95 约 10.1ms；这是本机 rAF 间隔，不是 GPU 耗时或通用帧率保证。记录见 artifacts/motion/*-isolated-timing.json。

WebGPU 键盘战斗录像：artifacts/combat-webgpu/mossback.webm、glasswing.webm；两次冲刺避开扑击后生命均为 5，并完成束缚和攻击，无页面错误。属于局部定位演示。复现：PowerShell 设置 `$env:COMBAT_GPU='1'`，运行 `node scripts/combat-capture.mjs`。


### 镜头与动作的继续优化

镜头使用双向前视与平滑跟随，跳跃时保留垂直缓冲，下坠时提前展示落脚区域。冲刺轻微拉远、挥刃轻微推近；减少动态效果关闭动作变焦。镜头跟随有效游玩时钟，暂停时保持构图。

主角增加独立起跳和落地恢复动作，总计 180 帧；受伤与冲刺能及时接管尚未结束的挥刀姿态。披风、面具和胸口纹饰进一步细化，奔跑脚下按地区产生叶屑或晶光。命中特效使用定向碎光，落地光环贴合地面，藤蔓施法增加花叶纹样。场景雾层降低亮度，前景植物在角色靠近画面下角时淡化，以保留角色轮廓。


### 石碑空间与唤醒取景

三座石碑增加自制拱架、环形刻痕和阶台。唤醒时镜头短暂拉远并抬高取景，随后平滑回到探索；离开石碑 320 单位会取消取景，减少动态模式关闭这段变化。第三碑结尾只推进最多 2.2 秒视觉演出，不推进世界与旅程时间。唤醒粒子数量与尺寸已收敛，避免遮住碑文。

实际 E 交互截图位于 `artifacts/ceremony/stone-1-awaken.png`、`stone-2-awaken.png`、`stone-3-awaken.png`，报告为 `artifacts/ceremony/report.json`。这些是定位后的真实交互演示，不是完整通关证明。复现命令：`node scripts/ceremony-capture.mjs`。


### 新一轮画质优化

WebGPU 增加 768 个由顶点着色器计算的露光/散景实例，按游戏时钟漂移并随镜头呈现视差；减少动态时大幅隐藏实例。粒子在角色附近以及暗色岩体上衰减。亮度遮挡是屏幕空间近似，没有真实深度缓冲。

辉光升级为两种尺度的 rgba16float 中间纹理：1/4 分辨率保留细小光点，1/12 分辨率生成较宽扩散。六个合成阶段后另有一遍实例粒子绘制，共七个渲染阶段。辉光在线性空间累积，仍输出 SDR，不代表显示器 HDR。额外加入十二点采样的屏幕空间散射和细密焦散。

场景补充平台下的细光瀑、露杯小花，以及玻璃气泡、釉光和光谱接缝。美术巡览已刷新，覆盖三地区、六座花园。


中景新增莲叶种泉、彩玻璃拱廊与树根种灯廊架，包含叶脉、镶嵌窗格、种灯肋线及反射水盆。WebGPU 实例还包含扑翼微光与菱形晶片，按地区变化；角色周围加入提灯暖色边光、冲刺尾光和目标处束缚扩散。提灯边光来自源画面亮度梯度，是风格化近似，没有真实几何法线或光追。

原生 GPU 检查确认每帧七个渲染阶段及 draw(6,768) 实例绘制；暂停时 GPU 画布截图保持完全一致。新一轮 WebGPU 在本机 1440×900 / DPR 1 的璃翅遭遇采样中，180 个 rAF 中位约 10ms / P95 10.1ms（浏览器帧间隔，非 GPU 耗时保证）。

### 移动攻击与三档战斗复核

主角新增移动下劈与移动上挑，共 180 帧，奔跑挥刃时继续迈步；静止攻击保留支撑站姿。怪物蓄势时收拢轮廓，扑击时伸展，束缚时缓慢呼吸。三档共享这些造型和动作。

战斗录像脚本支持 `$env:COMBAT_QUALITY='soft'` / `'dream'` / `'webgpu'`，明确选择并核对画质后记录实际 GPU 画布状态。旧版脚本只按环境变量标注 GPU，未实际切换，旧报告不能作为 WebGPU 战斗证据；以更新后的报告为准。独立原生 GPU 浏览器检查不受此脚本问题影响。


WebGPU 进一步增加附近怪物的蓄势光环与受击局部光，受束缚时关闭蓄势增光；普通档和轻盈档保留全部预警、受击碎光与束缚时长环。GPU 关闭时跳过 GPU 专用目标筛选。

## 风与玻璃风花

六座花园各有两处风场，共 12 处；GATE 附近保留平静开场。风场作为探索捷径，原有路线仍可完整通过。

- **蒲苇上升风**：见到向上风纹后，跳入风柱即可持续借升力登高；保留正常跳跃初速度。
- **花信风**：腾空时顺风跳得更远，逆风时需调整方向；地面不会被强制推走。
- **抵风下降**：按住 S 或 ↓ 抵住风力；S / ↓ + 空格仍可穿下平台。
- **转向机关**：靠近横风中央的玻璃风花按 E，反转风向 8 秒；再次按 E 可提前复原，可重复触发，不消耗光能或玻璃珠。临时风向在刷新或重开后复原。
- **美术提示**：蒲苇、旋转玻璃风花、定向风纹与飘叶共同标记风区；风向箭头和倒计时同步变化。首次进入风场会将教程写入日志。
- 菜单与浏览器失焦暂停风场、风花和反转倒计时。减少动态效果会固定风纹与风花动画，保留方向提示和全部机制。

预览截图：`artifacts/wind/updraft.png`、`tailwind.png`、`reversed.png`。复现命令：`node scripts/wind-capture.mjs`。这些截图通过定位展示风场；完整路线验证由 `e2e/route.spec.ts` 执行。

### 风景随动与气流美术升级

风场周围新增固定根部、逐段弯折的草甸；两条丝带以不同相位起伏；枝架上悬挂三枚有切面高光的玻璃风铃，铃下细带与叶片随风偏转。反转风花后，草叶倾斜、飘带展开方向、风铃偏向与横向种子流一起响应。晨露、玻璃与藤冠地区分别采用浅金绿、青蓝与淡紫配色。植物与旗杆按实际地面放置，避免扎在缺口中。

风流加入宽幅低透明光带、细亮风丝、上升螺旋风环和蒲公英种子，强化气流体积与方向。所有随动使用游戏时钟；暂停冻结，减少动态时固定装饰姿态。三档共享这些美术，按镜头范围绘制附近风场。

动态预览：`artifacts/wind/wind-showcase.webm`；三地区截图：`updraft.png`、`glasswind.png`、`canopywind.png`，位于同一目录。运行 `node scripts/wind-capture.mjs` 可重新生成。

## 循光引导与花园邀约

- **梦幻顶端横幅**：玻璃菱晶、细金叶饰与半透明底纹展示当前主线目标、机关按键和本庭四枚灯环进度。新目标展开 6 秒后自动收拢，不使用全屏遮挡；按 **H** 隐藏或恢复横幅与光箭头。
- **可达平台箭头**：按当前落脚平台规划下一步，提示沿路、跃上、跨隙或 S + 空格穿层。腾空时保持落点，落地后重新规划；在上升风中需要下降时会提示收身。近处已有机关交互提示时不再叠加箭头文字。
- **机关状态提示**：叶台固定后改为 E 引光；守卫安静后改为 E；光能不足时提示等待恢复或用近战击退。折光提示同步显示当前朝向与目标刻痕。
- **旅程页**：Tab 查看当前目标、下一步操作、六花园地图和可选邀约；背包显示风语玻璃签。
- **可选风之邀约**：每座花园借上升风升高一段（160 世界像素），并 E 转动横风风花，可获得该庭的风语玻璃签，共 6 枚。不设时限，不阻挡主线；子任务与奖励均保存，重复操作不会重复计奖。旧存档自动补齐邀约进度字段。

引导动态展示：`artifacts/guidance/journey-guide.webm`；开场、收拢横幅、旅程页与折光截图也在该目录。复现：`node scripts/guidance-capture.mjs`。

完整引导路线验证（PowerShell）：

```powershell
$env:GUIDE_FULL = "1"
node scripts/guidance-route.mjs
```

这个自动角色根据实时引导落点控制移动、跳跃和穿层，在接近目标时使用 E / K / J；不读取预写的 routeGoals 路线。输出 `artifacts/guidance/route-report.json`，包含主线 20 枚灯环、三碑进度、守卫结果与物理模拟时长。截图脚本中的机关定位展示不作为通关证据。
