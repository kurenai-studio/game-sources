## 一颗靠走路点亮的小星球

你背着一个比头还大的线轴，在一颗铅笔速写般的小星球上散步。脚下走过的每一步，都会留下一根毛线。

把线从发电机牵向灯塔，从山顶泉眼引到水车，或者在老街两根灯柱之间拉起一串灯。接通的那一刻，色彩从落点像水彩一样晕染开来，沉睡的小镇也跟着一点点醒过来。

![接通前是黑白铅笔速写，接通后水彩般的色彩晕染开来](https://raw.githubusercontent.com/makerjackie/yarn-planet/main/docs/media/sketch-to-color.jpg)

![背着大线轴走过山坡，把水线一路铺到水车旁](https://raw.githubusercontent.com/makerjackie/yarn-planet/main/docs/media/lay-thread.jpg)

游戏里没导入任何一张图片或一段录音。无论是房子、角色、灯塔，还是起伏的海浪与耳边的音效，全部由代码生成。

## 3.6 小时做出第一版

动手之前，我和 Claude 已经有一套自己写的底子。那是为了学习小星球游戏的做法，复刻 abeto 的 Messenger（学习用途，注明了出处）时留下的引擎：支持球面行走与碰撞、自动避墙的相机、描边渲染、本地存档和五种语言。这次，我们决定在它的基础上做一部原创作品。

这次，我们先把主题聊透。Claude 一开始给的方案依然是「送信」，我追问了一句：这在全球真的能有共鸣吗？几番推敲后，我们收敛成一个不需要文字也能看懂的动作——你走过的路，就是那根线。

方向定好后，协作流程很清晰：

1. Opus 5.5 先写设计文档：包含一句话介绍、设计支柱、色板、各区域在球面上的经纬度、九根线的流程，以及九个角色。
2. 接着写一份「模块契约」，把代码按目录拆成世界、角色、牵线玩法、画面特效、界面文字和声音。
3. 五个 Sonnet 子代理在各自的 git 分支里同时动工。
4. Opus 负责合并与调参，再跑单元测试、截图，并派一个只按 WASD 和 E 的自动试玩脚本从头跑到尾，确认真能通关。

从最初讨论到第一章上线，大约花了 3.6 小时。全程我没有写一行代码，只负责定方向、试玩、提反馈和做决定。

## 把所有人的路留在同一颗星球上

第一版跑通后，我们想让这颗星球多一点连接感。Claude 提了个主意：让每个玩家走过的路，都留在同一颗星球上。

一个人走过只是一条路；许多人走过，这些线就会把整颗星球轻轻缠绕起来。下面这张图是用模拟路线渲染出的效果，也是宣传片的开场画面：

![当许多人的路线交织在一起，整颗星球被彩线缠绕（模拟效果）](https://raw.githubusercontent.com/makerjackie/yarn-planet/main/docs/media/woven-planet.jpg)

如今打开线上的标题画面，上面亮着的，已经是真实玩家们一步步走出来的线。

多人联机也保持了同样的克制：基于 Cloudflare 的一个 Durable Object，同一个房间里能看到彼此散步的身影，相遇时只能发送四句预设的招呼，不开放打字聊天。

## 宣传片、发布与开源

宣传片直接从游戏实机画面录制。录制脚本接管了游戏时钟，每截一帧画面只把时间往前推 1/60 秒，录出来的 4K 画面帧帧清晰；随后用 ffmpeg 按时间线剪辑、配字幕、混入音乐。发布文案由 Gemini 起草，再通过「蚁小二」命令行工具一键分发到抖音、B站、小红书、视频号和 YouTube，每个平台都如实标注了 AI 生成内容与模拟画面。

最后，项目源码以 MIT 协议开源。公开之前，我们专门做了一次代码审计：和参考过的项目逐段比对，清理掉参考资料，并完整列出了第三方许可。

## 想做一颗自己的星球？

我把这套跑通的做法整理成了一段提示词。把 `【】` 里的内容换成你的点子，发给 Claude Code、Codex 或 Cursor 这类能读写文件、执行命令的 AI 编程工具即可开工：

```text
你是一名资深游戏开发者兼技术负责人。我们要做一个原创的「小星球」网页游戏：玩家在一颗能绕着走一圈的小星球上自由漫游，低多边形卡通画风，电脑和手机浏览器打开就能玩。

## 我的想法
- 核心动作（玩家反复做的那一件事）：【例：背着线轴走路，走过的路会变成一根彩线】
- 一眼能看懂的画面钩子：【例：没接通的地方是铅笔速写，接通后颜色像水彩一样晕开】
- 世界和情绪：【例：安静、温暖、带点幽默的海边小镇】
- 第一章规模：一颗小星球、3 个区域、8–10 个目标
- 语言：【例：简体中文、English】
- 喜欢的作品：【写几个你喜欢的游戏】。只借鉴感觉，不复制任何素材、代码、角色或剧情。

## 工作方式
1. 先不写代码。和我讨论主题：它是不是别的游戏换了个皮？不靠文字，各国玩家能不能一眼看懂？给我 2–3 个方向和你的推荐，等我确认。
2. 写 docs/DESIGN.md：一句话介绍、设计支柱、色板（写成色值）、星球布局（关键物件用经纬度给坐标）、玩法规则、第一章流程、角色表。写完给我看。
3. 写 src/contracts.ts 定义模块边界，按目录拆成并行工作流（世界、角色、核心玩法、画面特效、界面/文字/声音）。能开子代理就让每个子代理在独立的 git worktree 里负责一个目录，你负责整合。
4. 先做出能从头玩到尾的第一章，再打磨。每轮给我截图、测试结果和你不确定的地方。

## 技术要求
- TypeScript + Vite + three.js，碰撞用 three-mesh-bvh 加速，可部署到 Cloudflare Workers。
- 星球中心固定在 (0,0,0)，重力指向球心。玩家是胶囊体，和完整碰撞网格做真正的 3D 碰撞；固定步长物理，渲染时插值，物理姿态和渲染姿态分开。
- 朝向在球面上做平行移动，走一圈也不会拧歪。跟随相机能拖动、缩放，撞墙时缩短，遇到矮杂物先抬高，对话时能看清对方的脸。
- 所有模型用代码由基本几何体拼出，不导入模型和贴图；卡通光照 + 描边 + 统一色板。重复物件用 InstancedMesh。桌面 < 250 draw calls、< 50 万三角形。
- 声音用 Web Audio 实时合成。所有文字放进语言表。存档用 localStorage。支持键盘、鼠标和手机触控。

## 验证
- npm test 和 npm run build 必须通过；用 Playwright 截图检查桌面和手机画面。
- 写一个只用普通按键通关的自动试玩脚本。调试用的瞬移只能用来看画面，不能当作「能玩通」的证据。

## 原创与合规
- 不使用其他游戏的素材和代码；第三方代码只用 MIT 这类宽松许可，并记录下来。在制作信息里写明灵感来源。
```

等第一章能顺畅跑通，还可以继续让它加上联机（用一个 Durable Object 同步位置与预设招呼）和宣传片录制（虚拟时钟逐帧截图 + ffmpeg 合成）。

回顾这次开发，有几条实在的体会：

1. **先聊透主题再动手。** 多问一句「这真的好吗」，往往能把换皮的点子逼成真正的原创。
2. **一个核心动作，配一个一眼能懂的画面。** 它既是核心玩法，也是宣传片里最直观的镜头。
3. **全部用代码生成。** 省去了素材版权的顾虑，整体视觉风格也天然统一。
4. **人把控品味，AI 落实细节。** 我只描述哪里不对劲、想要什么感觉，具体怎么实现交给 AI。
5. **逐帧看真实画面，坦诚做好标注。** 测试全绿不代表画面真的在动；属于模拟效果的画面，就大方写明是模拟效果。
