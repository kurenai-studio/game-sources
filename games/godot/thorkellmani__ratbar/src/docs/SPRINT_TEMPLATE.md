# Sprint Template

Keep one active sprint. Resolve open design questions before writing its task list. Finish every required test and the retrospective before closing it. At closeout, fold completed work, test results, findings, and later considerations into the backlog; close the relevant backlog items; update historical logs; then delete `docs/CURRENT_SPRINT.md`. Create the next sprint only when its scope is chosen. Keep decision logs as historical records: use bullets and strike through decisions that a later decision replaces.

## Current sprint format

```markdown
# Current Sprint

## [Descriptive name or working title]

[One or two sentences describing the feature and its goal.]

### Decisions made

- [Brief summary of a settled decision.]

### Tasks

- [ ] [One concrete task.]
  **Test scenario:** [Observable result required before checking this task off.]

- [ ] [Next concrete task.]
  **Test scenario:** [Observable result required before checking this task off.]

### Retrospective

#### Findings

- [What the sprint revealed in the running game or implementation.]

#### Notes for later sprints

- [Follow-up work or tuning to revisit later.]
```

Keep the current sprint short. Add retrospective findings as they emerge; put detailed rationale and superseded decisions in the historical decision log.
