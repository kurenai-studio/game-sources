# v3：体力、一天、帐篷与饭店（附：能看见的天）

日期：2026-10-18
状态：待实现
父文档：`docs/superpowers/specs/2026-10-17-fungi-party-design.md`（第 7 节）

## 1. 这是什么

三款小游戏已经做完，森林里有四个去处。这一版加上**一天的节奏**：

- 每天有一份**体力**，玩小游戏按局扣。
- **天色由体力派生**——太阳在东边还是快落山，就是你今天还剩多少局的可视化。
- 体力用完了天就黑，走过去**帐篷里睡一觉**，第二天早上满血。
- 摊位旁边开一家**饭店**，花蘑菇币吃饭回体力，一天限三份。
- 帐篷里能**换衣服**，摊位只管卖、不管穿。
- 顺手把「看不见天」修掉：能抬头看天，太阳戴墨镜从东边升起来，月亮戴睡帽在晚上出来。

一句话回答设计文档 7.3 节问的「体力到底给玩家带来了什么」：**它把「今天玩了几局」变成一个看得见的东西——你抬头就知道今天过到哪了**。

## 2. 目标 / 非目标 / 反目标

**目标**
- 一次连续游玩自然落在 5~8 局、10~15 分钟，末尾落在「天黑了、走回帐篷睡一觉」上，不是硬截断。
- 蘑菇币有第二个去处：不再只是攒 200 币买帽子，也可以今天多想玩一局。
- 抬头能看到一个会动的天：太阳东升西落，晚上月亮出来。

**非目标（这一版不做）**
- **难度分层**。父文档 7.1 写的「越难花体力越多、给币越多」不做：等于给三款小游戏各加一套难度参数和入口 UI，工作量比体力系统本身大一倍，而三款的难度都还没调到位。每款小游戏一个固定花销。
- 帐篷内部、可进入的室内。帐篷就是一个有床的棚子，站在门口用浮层操作。
- 睡觉的躺姿动画演到底（只做「躺下 → 淡出」两下）。
- 饥饿、饱食度、食物种类、菜谱。饭店只卖一份饭。
- 体力影响手感（跑得慢、跳不高）。体力只是预算，不改操作。
- 天气、云、星星、日出日落的具体时刻表演（除了太阳和月亮本身）。
- 联机、多存档位、设置面板。

**反目标（做成了算失败）**
- 玩家在森林里闲逛被扣体力或催时间——探索必须永远免费。
- 想玩的时候被拦在门外，且看不到「什么时候能再玩」。拦门必须同时给出原因和出路（回帐篷睡觉 / 去饭店吃饭）。
- 太阳在天上倒着走（吃完饭回体力后），或者天色和体力对不上。
- 抬头就穿进地形、相机贴地乱转。
- 太阳和月亮在真机上只有几个像素，或者糊成一团。

## 3. 约束

- Godot 4.7.2、Mobile 渲染器；沿用「纯逻辑模型 + 无头测试」的做法。
- 可调数字全部进 `game/config.gd` 的 `const`。
- 浮层、字体、按钮统一用 `game/ui/ui_style.gd`。
- 美术全部程序化生成（内置 mesh），不加贴图、不加模型文件。
- 森林是 `game/main.tscn`，小游戏各自是自包含单场景；森林侧的跨场景引用每帧惰性 `get_first_node_in_group`。
- 不加 autoload。体力存 `Save`（`user://save.cfg`），森林侧一个节点持有运行期状态。
- 禁止实时 GI / SSAO / SSR，天空只用现有的 `ProceduralSkyMaterial`。

## 4. 已经定下的（不留给 builder 决定）

### 4.1 唯一的发条：体力

- **体力 0~100，只有玩小游戏会扣，只有过夜和吃饭会回。** 走路、跳跃、闲逛一律不扣。探索永远免费。
- **天色是体力的函数，不是第二个时钟。** `time_of_day` 由体力算出来：

  ```
  t = lerp(0.28, 0.80, 1.0 - stamina / 100.0)   # 满体力 = 清晨，体力见底 = 天黑
  ```

  `DayNight` 不再自己按 delta 推进（`DAY_LENGTH_SECONDS` 删掉），由森林侧每帧写入。
- **天色只前进不后退**：`time_of_day = max(time_of_day, t)`。吃完饭回体力，太阳不会倒回去——已经过去的时间就是过去了。所以饭店能延长今天，但不能把今天变回上午。
- 天色与体力对不上是反目标；上式是唯一口径，别的地方不许再算第二套。

### 4.2 数值（先定局数再反推，父文档 7.2 的方法）

| 项 | 起手值 |
|---|---|
| 日体力 | 100 |
| 上课偷吃 | 12 |
| 森林赛跑 | 20 |
| 烫手炸弹 | 25 |
| 一份饭 | 20 币，回 25 体力 |
| 每天能吃几份 | 3 |

- 一天基础 5~8 局（100 体力 ≈ 4~8 局，取决于玩哪款），吃完三份饭再 +75 体力 ≈ 再 3 局。上限 11 局，实际玩家到不了。
- 币的收支：一局 35~70 币，一天 5 局约 200~350 币；三份饭 60 币，占两成。剩下的仍然能攒帽子（200 币 ≈ 一天多）。
- 全是 `const`，一屏内能对比着调。

### 4.3 扣体力的位置

**在小游戏场景自己的 `_ready` 里扣，不在入口面板扣。** 原因是三款小游戏都有「再来一局 / 重新开始」（`race_ui`、`bomb_ui`、`classroom_ui`），它们原地重载场景、绕过森林入口。在入口扣 = 一进场无限免费刷币，预算直接失效；在入口和场内各扣一遍 = 两处逻辑必然走岔。放在 `_ready` 一处，重开自动也扣。

- 每个小游戏 `_ready` 头三行：`Day.spend_cost(cost)`；体力不够 → `change_scene_to_file(Config.FOREST_PATH)` 直接回森林，不出结算。
- 三个入口面板（校门 `DoorPanel`、起跑线 `RacePanel`、蘑菇圈 `BombPanel`）只**显示**「体力 −12 · 剩 88」；体力不够时按钮变灰、文字「太累了，明天再来」，**不进场景、不弹对话、不扣钱**。面板不扣费。
- 结算照旧只写币。- 逻辑抽成静态函数放 `game/systems/day.gd`（`spend_cost` / `can_play` / `day_time` / `rollover` / `meal`），三处只调它，不各写一遍。

### 4.4 帐篷与床：一天在哪儿结束

**体力见底不自动过夜。** 自动过场会把「去吃饭」这条出路关在最需要它的时刻，也让玩家看不出自己是怎么被送走的。一天结束的地方是草地上的帐篷。

- 森林里第六个 POI：一顶帐篷，摆在出生点旁边 `≈ (-8.0, 0.0, 2.0)`，开口朝向出生点。两片斜布 + 两根杆 + 掀开的门帘，里面一张床（床板 + 被褥 + 枕头），玩家站在门口能看见床。写法和 `Stall` 一致：`add_to_group("tent")`，对外只回答 `player_inside`。
- 走到帐篷口的触发区，弹浮层「帐篷」，两个按钮：**「睡到早上」** 和 **「换衣服」**。
- **随时都能睡，没有代价。** 体力满的时候睡一觉只是把今天快进掉——损失为零（体力本来就不会超过 100），所以不存在误触惩罚。想让今天结束、或者就想看看日出，走过去睡。
- 睡觉演一遍：玩家插值到床上（0.4 秒）→ 躺下 → 停 0.3 秒 → 0.5 秒淡入黑 → 写存档（`stamina = 100`、`meals = 0`、`day += 1`、`day_time = 0.28`）→ 0.7 秒淡出，玩家已经站在帐篷门口。全程约 2 秒。
- 睡觉期间锁输入（摇杆、按钮、浮层都不动）。
- 体力见底（< 12）时：太阳 1.2 秒压到落山（`time_of_day` → 0.86）、三个入口继续拦门、饭店打烊、HUD 数字变红并提示「回帐篷睡觉」。**不出现按钮**——出路是走过去，不是点一下。走路免费，这段路就是「今天收工」的仪式。

### 4.5 换衣服搬到帐篷

- **摊位只管卖，不管穿。** `ShopPanel` 去掉「默认红帽 / 蓝莓帽」两个按钮；买下之后价格行显示「已买下 · 到帐篷里换」。
- 帐篷浮层点「换衣服」→ 展开已拥有的皮肤列表（现在两个：默认红帽、蓝莓帽；没拥有的不列）。点一下立刻换，浮层不收，可以来回试。
- `ShopPanel.equip` 是静态函数，直接挪到 `Save.equip(blueberry, path)`（它本来就是在写存档），帐篷面板调它。`game/systems/day.gd` 不掺和这事。
- `tests/test_shop.gd` 里关于换装的用例跟着改到新位置。

### 4.6 饭店

- 森林里第五个 POI：一栋小房子（墙 + 斜顶 + 门 + 一个碗/招牌），摆在摊位旁边 `≈ (8.0, 0.0, 2.0)`，要求「从出生点往摊位走时顺手就能看见」。
- 写法和 `Stall` 完全一致：`add_to_group("restaurant")`，对外只回答 `player_inside`；浮层 `game/ui/meal_panel.gd` 每帧惰性找它。
- 面板内容：今天的体力条、`蘑菇币 N`、`第 X/3 份`、按钮「吃一份（20 币）」。体力满了按钮显示「还饱着」，份数用完显示「今天吃够了」，钱不够显示「还差 N 币」。
- 吃一份：扣 20 币、`meals += 1`、体力 +25（不超过 100）、**放吃饭动画**。
- 体力见底（< 12）时饭店**打烊**：面板还在，按钮显示「打烊了，明天再来」，不能吃。这条是刻意的——「吃不吃」要在太阳还没落山的时候决定，见底之后只剩回家睡觉。
- **吃饭动画演的是玩家本人，没有第二个蘑菇、没有桌子。** 一碗饭浮在玩家面前，玩家原地咬三口，每口 0.35 秒，身子上下弹、伞盖压一下（复用 `Movement.squash_stretch` 那套挤压），咬完碗消失。面板的体力条同步涨上去。动画期间按钮变灰，播完恢复。不加替身角色就不用第二套动画、不用摆相机、不用藏真玩家。
- 动画做成「可以反复看也不腻」的短动画：总长 1.2 秒以内。

**六个 POI 的摆位**（出生点在 `(0, 0, 0)`，围一圈，具体坐标 builder 微调但顺序不许变）：

| POI | 位置 | 进的是什么 |
|---|---|---|
| 校门 | `(0, 0, -14)` | 教室偷吃（12 体力） |
| 摊位 | `(7, 0, -11)` | 买皮肤（只管卖） |
| 起跑线 | `(-7, 0, -11)` | 森林赛跑（20 体力） |
| 饭店 | `(8, 0, 2)` | 吃饭回体力（20 币 / 25 体力 / 一天 3 份） |
| 帐篷 | `(-8, 0, 2)` | 睡觉、换衣服 |
| 蘑菇圈 | `(0, 0, 11)` | 烫手炸弹（25 体力） |

### 4.7 HUD

- 森林左上角常驻一条：圆角体力条（宽 260）+ 文字「体力 88/100」，下面一行「蘑菇币 120」。
- 教室/赛跑/炸弹三个场景里**不加**体力条（进去就扣完了，没有必要）。币也不加——现在的小游戏结算面板已经写了收益。
- 刷新用 0.25 秒的 Timer，不每帧读存档（`Save.read()` 是读文件）。
- 体力见底（< 12）时数字变红，并在下面加一行小字「回帐篷睡觉」。只是提示，不能点。

### 4.8 天：太阳与月亮

**能看到天。** 现在看不到的原因只有一个：相机俯仰上限是 -10°，永远只能往下看。

- `CamRig.PITCH_MAX` 从 -10° 放到 **+22°**（`PITCH_MIN` 不动）。抬头时手臂射线会打到地面、自动缩到 `CAM_MIN_LENGTH`，这是已有行为。
- 天体放在**跟随相机的远平面上**，不是世界原点：每帧 `position = camera.global_position + 方向 * 120.0`，并 `look_at(camera.global_position)` 让脸永远正对玩家。
- 方向由 `DayNight.sun_dir(t)` 给出（纯函数，单测）：太阳在 `+Z` 侧升起、正午到头顶、`-Z` 侧落下；月亮取 `sun_dir(t + 0.5)`。现有 `sun_rotation` 的旋转直接推出方向，不另外定义一套角度。
- 可见性：`dir.y > -0.15` 才显示，太阳和月亮天然互斥。
- 尺寸：太阳球半径 4.5、月亮半径 3.2（120 米处约 4~5° 视角，比真太阳大十倍，是刻意的卡通比例）。数值进 `const`。
- 距离 120 米处雾约 13%，会让天体轻微发灰。这是可接受的色调统一；真机上看着太脏就调 `fog_density` 或把距离压到 90。

**太阳**（程序化，和 `MushroomMesh` 一样用 `_add_part` 拼）：
- 亮黄的球 + 一层微微外扩的半透明光晕球。
- **一副黑墨镜**：两个扁圆片 + 中间一条细桥 + 两条镜腿。
- 一张小弧线嘴（微微上扬），不笑出声。

**月亮**（同样程序化）：
- 淡黄白的球，比太阳小一圈。
- **一顶睡帽**：圆锥 + 帽尖一个小球，浅蓝白，斜扣在头顶。
- 两条闭着的眼睛（细扁条微微倾斜），嘴角一点点。
- 可选：头顶飘三个小球表示 zzz，上下浮动。builder 觉得好看就加。

两者都用 `unshaded` + 自发光，不受方向光影响（否则太阳会自己给自己打光，出现一个月牙形的暗面）。

### 4.9 存档

`Save` 现在三个字段，加四个：

| 字段 | 含义 |
|---|---|
| `stamina` | 0~100，缺省 100 |
| `meals` | 今天已经吃了几份，缺省 0 |
| `day` | 第几天，缺省 1（只用来显示和 debug，玩法不用） |
| `day_time` | 天色水位 0~1，缺省 0.28 |

- `day_time` 必须存。体力是见底的，吃完一顿回 25 体力后由体力重算天色会倒回上午（命中反目标）。做法：森林侧取 `max(存档里的 day_time, 体力算出来的 t)`，每 5 秒、进小游戏前、吃饭后、睡觉时写回。5 秒写一次 `ConfigFile` 是几 KB 的事，不怕。
- 老存档读不到新字段 → 用缺省值，不迁移、不报错。
- 体力**要存**：中途退出游戏回来不该回满。否则退出重进就是无限体力，一天节奏直接失效。
- **`Save.write` 有个现成的坑要先修**：它直接 `new` 一个 `ConfigFile` 就存，不先 `load`，所以整段覆盖——`Save.purchase` 买皮肤会把体力、份数、天数一起抹掉。改成先 `load` 再 set。

## 5. builder check 之后补的

设计文档写完后请一个没参与讨论的 builder 读了一遍，提出四个问题，逐条定如下：

1. **「再来一局」会不会白玩**：会。三款小游戏的结算/暂停面板都是原地重载场景，绕过森林入口。扣费改到小游戏 `_ready`。→ 见 4.3。
2. **体力见底就自动过夜，那饭店在最需要时无法去**：改成不自动过夜；一天结束的地方是帐篷，走过去睡。饭店见底时打烊，让「吃不吃」成为太阳落山前的决策。→ 见 4.4 / 4.6。
3. **天色水位不存就会倒走**：存档加第四个字段 `day_time`。→ 见 4.9。
4. **吃饭动画里的小蘑菇是谁**：就是玩家本人，不加替身、不加桌子。→ 见 4.6。

另：builder 发现 `Save.write` 不 `load` 就保存，是整段覆盖；买皮肤会把新字段抹掉。先修。→ 见 4.9。

（2026-10-18 追加：原文 4.4 是「不做床、不做帐篷，睡觉就是一个按钮」。改成做帐篷和床，顺便把换衣服从摊位搬到帐篷。见 4.4 / 4.5。）

## 6. 留给 builder 决定

- `game/systems/day.gd` 的函数划分与签名（上面 4.3 给的名字只是约定）。
- 森林侧持有运行期状态的那个节点叫什么、挂在谁下面（`DayLoop` / 塞进 `DayNight` / 别的都行）。
- 帐篷和饭店的具体形状、配色、最终坐标，以及六个 POI 的视觉区分度（校门是门、摊位有顶棚、蘑菇圈是火，帐篷和饭店别做成同一个东西）。
- 床、被褥、枕头的做法；睡觉时玩家怎么躺上去（插值 / 直接摆位）。
- 吃饭动画的具体编排（碗怎么出现、咬几口、身体怎么弹）。
- 太阳/月亮的部件尺寸与配色、光晕做法、zzz 要不要。
- 睡觉与过夜的淡出用什么（`ColorRect` + tween / `AnimationPlayer`）。
- 测试怎么拆。

## 7. 验收

- `bash scripts/test.sh` 全绿。新增纯函数测试至少覆盖：
  - `day_time`：体力 100 → 0.28，体力 0 → 0.80，单调递减关系；
  - 天色只前进不后退（吃完饭后水位不回拨）；
  - `spend_cost`：够就扣、不够就拒绝且体力不变；
  - `rollover`：体力回满、`meals` 归零、`day + 1`、水位回 0.28；
  - `meal`：钱不够 / 份数用完 / 满体力 / 已见底打烊，四种都拒绝且不扣钱；
  - `Save.equip`：没买不能穿、买了能来回切；
  - `sun_dir`：`t = 0.25` 近地平线在 `+Z` 侧，`t = 0.5` 接近头顶，`t = 0.75` 落到 `-Z` 侧；
  - 太阳/月亮可见性互补；
  - `Save.write` 只改传入的字段，没传的保留。
- 真机走一遍完整一天：玩到体力见底 → 天黑 → 走到帐篷睡一觉 → 早上满体力；中间吃一份饭，太阳停在原地不倒转、体力条涨而天色不变。
