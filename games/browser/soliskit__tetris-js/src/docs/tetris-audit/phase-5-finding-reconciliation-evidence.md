## F8 (Open - no decision made)

Register row verbatim: "On a Mac, a key let go while Cmd is held may stay held, because macOS sends no release. Cannot be reproduced off a Mac. INP-3 only covers keys pressed with a modifier. If confirmed, fixing it is an Intentional Change to INP-3. Low relevance: the supported platform is the iPhone (APP-4)."

The classification is a factual question first, and the register's own notes are limits, not resolutions. The report describes a key let go while Cmd was held. The register does not state whether that key was pressed with a modifier; on the reading that it was not - grounded in the report and the register's INP-3 note together, not a stated register fact - the reported release falls outside the current INP-3, which covers only keys pressed with a modifier. INP-3 includes, quoted verbatim from REQUIREMENTS.md, "Keys pressed with Cmd, Ctrl or Alt, and the keyboard's own key repeat, are ignored. A key pressed with Cmd, Ctrl or Alt never counts as held, because macOS may not report its release". Fixing it is an Intentional Change to INP-3 if confirmed - the conditional is the register's own wording, and the behavior is reported, not established. Reproduction off a Mac is recorded as not possible, so the register supplies no failed-reproduction result. No requirement settling whether APP-4's platform scope removes a Mac-only report from the applicable requirements is identified in the cited records. If the sources establish that scope factually, section 5.1's Rejected definition applies on its terms; if they do not, the scope question is a real choice. Until the applicability is grounded, this record proposes no word for F8 and claims no decision route for it.
