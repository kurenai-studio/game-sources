# BloomGrid

משחק פאזל בלוקים שכתבתי ב-Godot 4.7.

לוח 8×8, שלושה חלקים במגש. גוררים חלק ללוח. שורה מלאה או עמודה מלאה מתנקה. אם תופסים שורה ועמודה באותו מהלך זה סופרנובה, והניקוד קופץ.

אין סיבוב חופשי כמו בטטריס. יש כפתור Spin, פעמיים לריצה, כדי לצאת מפינה בלי להפוך את זה למשחק סיבובים.

![BloomGrid](store-ops/assets/play/feature-1024x500.png)

עדיין לא בחנות. אפשר לשחק על Windows אם יש Godot 4.7. היעד הוא Android (API 36), אופליין, בלי חשבון. מהטלפון: ראה [docs/MOBILE_PLAY.md](docs/MOBILE_PLAY.md) (APK או ייצוא Web).

יש גם מצב Race: שעון יורד, ניקוי מחזיר שניות. Classic בלי לחץ זמן.

שם שחקן זה רק תווית מקומית ללוח השיאים. אפשר בלי שם, ואפשר אותו שם כמה פעמים.

## איך זה מסודר

הפרדתי בכוונה בין חוקים לבין מה שרואים.

`core/` — לוח, חלקים, ניקוד, מגש, שעון. בלי Node ובלי קלט.  
`game/` — ציור, גרירה, פיצוצים, שמירת שיא.  
`tests/` — טסטים של Godot בלי חלון.  
`tools/test_core.py` — אותם טסטים בפייתון, אם אין Godot בהישג יד.  
`store-ops/` — טיוטות לחנות. לא Publish.

`core/` נשאר `RefCounted` כדי שאפשר להריץ טסט על הנחה/ניקוי/סופרנובה בלי לפתוח את המשחק. אם משהו נשבר בחוקים, זה אמור ליפול שם ולא בציור.

## להריץ

Godot 4.7. לפתוח את התיקייה הזו במנוע, או:

```powershell
godot --path .
```

אצלי המנוע מותקן דרך winget, אז לפעמים זה נראה ככה:

```powershell
godot --headless --path . -s res://tests/run_suite.gd
python tools/test_core.py
```

## מה עובד עכשיו, ומה לא

עובד: משחק מלא בדסקטופ, שני מצבים, שיאים מקומיים, סאונד סינתטי (בלי קבצי wav מהרשת).

לא בפרויקט הזה: פרסומות, תשלום, לידרבורד רשתי, חנות חיה. יש מחסום מפורש ב-`HUMAN_STOP.md` כדי לא ללחוץ Publish בטעות.
