# Code Review Checklist
- [ ] Are variable, function, and class names descriptive? e.g. avoid `data`, or `do_stuff()`.
- [ ] Is the formatting consistent with the project's style? e.g. PascalCase for public class attributes, _camelCase with a leading underscore for private attributes.
- [ ] Are there leftover print statements, commented-out blocks of code, or unused variables?
- [ ] Is there XML documentation for every class, attribute, and method?
- [ ] Are there classes that have too much responsibility?
  - Research the SRP if this point is confusing: https://www.geeksforgeeks.org/system-design/single-responsibility-in-solid-design-principle/
