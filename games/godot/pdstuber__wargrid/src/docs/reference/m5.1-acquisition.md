## Human-controlled units do not chase auto-acquired targets

**Code:**
- The idle scan calls `getNextMoodTarget(true, true)` and then `aiAttackObject(enemy, …, CMD_FROM_AI)` (`GameLogic/AI/AIStates.cpp:1445-1452`).
- For a human-controlled unit with `calledByAI`, the target filter adds `AI::WITHIN_ATTACK_RANGE | AI::UNFOGGED` (`GameLogic/Object/Update/AIUpdate.cpp:4680-4696`). The code comment says the AI "will not allow us to pursue the target … only look for targets that are already within attack range (as opposed to vision range)". The search circle is vision × `GuardOuterModifier` (`AIUpdate.cpp:4636`, `GameLogic/AI/AI.cpp:816-908`).
- `AIAttackApproachTargetState::onEnter` returns `STATE_FAILURE` when `PLAYER_HUMAN && getLastCommandSource()==CMD_FROM_AI && !isAllowedToChase()`. Exceptions: contact weapons and a top-level `AI_GUARD_RETALIATE` (`AIStates.cpp:2612-2625`). `AIAttackPursueTargetState::onEnter` has the same rule (`:2984-2997`).
- Effect: when the target leaves weapon range, the attack fails and the unit returns to `AI_IDLE` in the same tick. It rescans after `ForceIdleMSEC` (3 ticks), then every `MoodAttackCheckRate` (code default 2 s; the first interval is jittered by ±50 %; `AIUpdate.cpp:84`, `:4502-4507`, `:4620-4632`).
- The unit only turns while aiming. It never moves.

AI-controlled units have no such filter and approach freely:
- Search radius is vision × 1.333 (× mood; sleep gives 0).
- `AIAttackState::update` has no distance drop (`AIStates.cpp:5624-5735`).
- After the kill the unit stays where it ended (`AIStates.cpp:720`).

**M4.1 departure being corrected:** the [M4.1 design](../superpowers/specs/2026-11-03-m4.1-playtest-polish-design.md) §1 applied the AI branch to both controllers.

## Attack-move (human)

**Code** (`AIStates.cpp:3611-3698`):
- While marching, the unit calls `getNextMoodTarget(true, false)`: rate-limited, and limited to in-range, unfogged targets for humans.
- On acquire:
  1. `friend_endingMove()`;
  2. `setState(AI_ATTACK_OBJECT)`. This runs the approach `onEnter` synchronously (`Common/StateMachine.cpp:622-650`) while the command source is still the player's, so the first approach is allowed;
  3. only then `friend_setLastCommandSource(CMD_FROM_AI)` (`:3664`).
- When the engagement ends (success or failure), the same tick restores the player's command source and calls `getNextMoodTarget(false, false)` once (`forceRetargetThisFrame`, `:3634-3637`). That call has no rate gate and no in-range or fog filter, and its radius is vision × 2.2.
- If nothing is found, the unit repaths to the goal (`:3676-3680`).
- **Inference:** the chase is unbounded while the target stays within 2.2 × vision of the unit at each re-acquire.

The group order is a plain loop:
- `groupAttackMoveToPosition` gives each member `aiAttackMoveToPosition`, or `aiMoveToPosition` if the member cannot attack (`GameLogic/AI/AIGroup.cpp:2327-2341`; EA `:2284-2298`).
- No formation, no group coupling.
- `privateAttackMoveToPosition` clears the state machine first (`AIUpdate.cpp:3599-3619`).

## Explicit attack, move, production exit

**Code:**
- `privateAttackObject` uses CMD_FROM_PLAYER (`AIUpdate.cpp:3444-3447`). The chase is unbounded.
- `getNextMoodTarget` is called only from idle, attack sub-states, attack-move and attack-follow-path (`AIStates.cpp:1449, 2795, 3124, 3656, 4500`). So plain moves never acquire targets.
- Production exit follows the path and rally point with `aiFollowExitProductionPath(…, CMD_FROM_AI)`, then idles (`GameLogic/Object/Update/ProductionExitUpdate/DefaultProductionExitUpdate.cpp:96-114`).
- Turreted units scan from the turret AI while the body moves (`GameLogic/AI/TurretAI.cpp:880-899`). Wargrid has no turrets; deferred.

## Retaliation

**Trigger** (`GameLogic/Object/Body/ActiveBody.cpp:692-761`). Runs at the end of `attemptDamage`, also for zero-damage hits and the killing hit. It requires:
- the victim's owner is `PLAYER_HUMAN` with retaliation mode on (option default on, `Common/GlobalData.cpp:1064`);
- the attacker is an enemy and not airborne;
- the edge-to-edge 2D distance is ≤ `MaxRetaliationDistance`.

The victim may be a structure.

**Joiners** (`:700-728`, `:765-796`):
- Units of the victim's player or its allies, within 120 + the victim's bounding radius of the victim's centre.
- The victim itself is not excluded.
- Each joiner must be mobile, have AI, be `isIdle()` (only `AIIdleState` counts, `AIUpdate.cpp:3124-3131`), not be using an ability, and be able to attack the attacker.
- Each joiner gets `aiGuardRetaliate(attacker, ownPosition, …, CMD_FROM_AI)` (`AIUpdate.cpp:3474-3484`).

**States** (`GameLogic/AI/AIGuardRetaliate.cpp`). G = vision × GuardInner, O = vision × GuardOuter.

- `ATTACK_AGGRESSOR` (initial state, `:785-840`):
  - Attacks the attacker. The chase is allowed under `AI_GUARD_RETALIATE`.
  - The 300-tick timer is never reset.
  - It ends when the attacker is more than O + G from the guard point (`:817`), the unit is more than G from the guard point (`:158-161`), or the target is dead.
- `RETURN` (`:600-633`):
  - Walks back to the guard point.
  - Scans every 30 ticks (first scan after a random 0–30) for the nearest attackable non-building enemy within G of the guard point (`:244-299`). A hit goes to `INNER`.
  - Retail and EA only: "attacked me and can return fire" goes back to `ATTACK_AGGRESSOR` (`:188`, EA `:192`). The SuperHackers non-retail build drops this transition.
- `IDLE`: one scan, then exit to `AI_IDLE` at the guard point.
- `INNER`: radius 1.5·G. `OUTER`: radius 0.67·(O + G), with a timer that resets while the target stays inside G.

**Numbers for human units:**

| | G (unit leash) | O + G (attacker leash) |
|---|---|---|
| Rifle | 7.2 cells | 16 cells |
| Tank | 10.8 cells | 24 cells |

## Click and resume feedback

**Code:**
- `HintSpy` sends `MSG_DO_MOVETO`, `MSG_DO_ATTACKMOVETO`, `MSG_DO_FORCEMOVETO` and `MSG_ADD_WAYPOINT` to `createMoveHint` (`Core/GameEngine/Source/GameClient/MessageStream/HintSpy.cpp:114-119`). The hint is skipped when the selection is a single immobile unit (`GameClient/InGameUI.cpp:2471-2501`).
- `W3DInGameUI::drawMoveHints` plays the `MoveHintName` model once and hides it after 40 frames (`../../GameEngineDevice/Source/W3DDevice/GameClient/W3DInGameUI.cpp:468-580`). The marker is the same for move and attack-move.
- The attack-move cursor comes from the command button's INI `CursorName`. Not read.
- Resume construction:
  - The `RESUME_CONSTRUCTION` cursor shows while `ActionManager::canResumeConstructionOf` allows it: a dozer is selected, same player, the building is under construction, and no other dozer is actively building it (`Common/RTS/ActionManager.cpp:449`, `GameClient/InGameUI.cpp:2970`).
  - The order plays `VoiceBuildResponse`.
  - `Drawable::drawConstructPercent` shows the percent.
