## 验证边界

- 单项机制测试可以摆放角色，用于隔离验证技能与故障恢复；它们不作为连续通关或时长证据。
- 连续路线测试只注入玩家控制并推进固定步长物理。实际键盘回放使用浏览器按键与现实时间，不修改玩家或存档数据。
- 两种回放都知道路线；可以证明当前关卡能完整通关及所需时间，不能保证每位初次玩家都在相同时间完成。
- 画面风格以源码绘图和实际截图复核，自动化测试不承担审美评分。
- 使用 verification 构建进行长回放，避免 Vite 热更新干扰；最终交付恢复正常生产构建，移除窗口测试入口。

## 已修复的历史问题

原版连续路线仅 22 秒，初次重做也只有约四分钟；原版通关测试传送角色，没有验证路线。现已改为完整六花园旅程及不传送连续验证。

同时修复低帧率时间变慢、平台解除固定时跳位、HUD 重建导致按钮失焦、标题帮助覆盖存档、角色受伤时完全消失、背景缩放不匹配、长菜单隐藏继续按钮等问题。

### 地形节奏、动作与输入

六段平台采用不同宽度序列，宽度 340–470 像素，以宽阔落点与短跳石交替；高低轮廓起伏增加，机关与石碑落点保留。连续物理路线验证通过，最后一轮模拟 692.5 秒、309 次跳跃，全部 24 机关和三碑完成。22 项浏览器检查通过。

角色新增攻击与施法姿态，玻璃珠收小外围光晕。动作录制发现极短按键可能落在两帧之间，新增按下事件缓存，在下次物理更新消费一次，暂停清空。新增 `e2e/input-buffer.spec.ts` 通过浏览器真实短按复现与验证，不依赖手工设置按键标记。

新地形实时键盘通关进程仍在运行，最终结果以 `artifacts/playthrough/report.json` 的更新时间与内容为准；当前尚不能用旧报告证明新版本完成。动作演示位于 `artifacts/motion/`，包含定位演示，不是整段通关录像。并发运行浏览器与录像时帧时间较高，尚未证明在所有桌面达到 60fps。
