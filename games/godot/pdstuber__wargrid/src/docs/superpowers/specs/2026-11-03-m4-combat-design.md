## Combat rules

Definitions: infantry225 credits/150 production ticks/180HP; tank900/300/480HP; barracks600/300/1000HP, power0, no prerequisite, provisional2×2 footprint. Existing economy values unchanged. Ground speeds follow `Locomotor.ini` divided by25 world units per cell (scale inferred from rifle100→4 and tank150→6 range mapping; see [verification plan](../../reference/zero-hour-verification.md)): infantry0.8, tank1.2 cells/s. User directed this speed on2026-11-03, replacing the earlier provisional 3.0; builder (Dozer) becomes1.2, legacy unarmed `vehicle` stays3.0 as the M1/M2 prototype/benchmark unit, not a Humvee mapping. Factory can accept old unarmed `vehicle` for regression scene and new `tank`; M4 HUD and AI offer tank only. Barracks produces infantry. Other health: builder250, collector300, unarmed vehicle240, reactor800, depot/factory2000. All foundations start at full kind HP, retain damage on completion, no construction healing. Health uses integer milliHP.

Rifle5000 milliHP SMALL_ARMS; range4 cells;3 shots per clip;3 ticks between shots,21 after final shot. Tank60000 ARMOR_PIERCING; range6;60 ticks between shots, unlimited clip. Source/config-supported matrix: small arms infantry100%, tank/builder25%, legacy vehicle/buildings50%; AP infantry10%, other ground kinds100%. Collector50% for both but cannot be targeted by either weapon. Neutral supplies cannot be damaged. No random outcomes or new RNG.

Range is inclusive squared distance. Mobile targets use center; buildings/foundations use nearest point on closed footprint rectangle. No visibility/LOS blockage, splash, scatter, physical projectile, friendly fire, crushing, firing while moving, upgrades, veterancy, air combat or repairs. Rendering may flash shots but never applies damage. Collector immunity to this roster is explicit; collectors don't determine victory.

Orders: explicit attack chases selected enemy ground unit/building; guard holds position and auto-fires only in range; attack-move advances to ground point, halts for in-range enemy, resumes when clear; ordinary move suppresses acquisition until arrival, then guards. Stop clears movement/target and guards. Explicit target has priority; auto choice nearest squared range distance then global ID, retaining a legal in-range target. Dead explicit target returns attacker to guard; no automatic map-wide chase. Attack-move acquisition never chases beyond range. Noncombatants continue existing tasks. Both attack and attack-move accept mixed infantry/tank groups; reject the whole command if any selected member is unarmed or the target is illegal.

**Approved change, 2026-11-03 (performance; user approved):**
- A guard or attack-move unit that has no target and finds none waits for its next 15-tick phase, staggered by unit ID, before scanning again.
- It scans immediately on spawn, on any new order, and when its target is lost (dead, removed or out of range).
- A halted attack-move unit keeps its reserved destination while it fights, and resumes by re-pathing to that destination without reallocating.
- Source basis: Zero Hour throttles idle auto-acquire (`MoodAttackCheckRate`, default 2 s), retargets immediately after a target loss, and re-paths attack-move to its existing goal. Wargrid uses 0.5 s with a deterministic stagger instead of random offsets.
- Measured motivation: a 150 v 150 scratch spike went from tick p95 12.5 / 15.3 ms to 1.41 / 1.69 ms ([ledger](../../reference/performance.md)).
- Contract: plan step 4d.

Explicit chase chooses reachable free cell centers within range of target, nearest squared distance from attacker then y/x; excludes ground occupancy/reservations except self. Reuse component cache, path queue and eight-query budget. Reconsider at most every15 ticks, or immediately when first ordered; never enqueue duplicate ID or replace unchanged valid destination. No firing position => hold blocked/retry, no teleport. Range checks occur again after movement. Stop for a tick before firing if any movement happened that tick.

Tick order: clear last events/results; due commands/final intents; capture existing unit IDs and power rates; plan combat movement; existing construction/production/supply; bounded paths/movement; collect all eligible shots from captured surviving stationary units; aggregate damage; remove lethal targets in ID order through existing removal; evaluate match; increment tick. All shooters alive at start of fire phase may fire, allowing mutual kills. Units spawned by production activate next tick. A unit killed this tick may already have worked/moved this tick; none acts on later ticks. Economy phases stay in M3 order.

Commands, health, combat intent/target/ammo/next-fire/repath ticks and last-tick fire/death events are copied in authoritative snapshots. Commands cannot reset cooldown or refill a partial clip; full clip refills on final shot with next-fire delayed21 ticks, as source-informed bookkeeping. Death cleanup reuses removal: routes, docks, bindings, footprints, cargo loss and paid-queue refunds. Pending target orders fail at due tick; surviving attack target references clear immediately after removal. No tombstone store/event bus.

## Mini-match and opponent

New separate `skirmish.tscn`, extends existing base controller; no default-launcher change. One48×32 empty terrain map. Player1 builder(4.5,14.5), player2 builder(43.5,14.5),10000 credits each; finite200-box sources at(5,3) and(40,3). No starting buildings or army. Fixed construction sites for player1: reactor(8,12),depot(8,5),barracks(12,12),factory(12,18); player2 mirrors rectangles about map x=24. Other human placements legal under ordinary rules.

Stateless deterministic opponent reads snapshots and issues normal commands every30 ticks. Build first absent reactor → depot → barracks → factory, one unfinished structure at a time; resume its paused foundation before new construction; fixed blocked site waits/retries. Lowest-ID surviving builder only; no replacement builder/command center. Queue at most one infantry per barracks and one tank per factory when affordable, producer ID order; no balance/cost bypass or hidden spawns. Automatic collectors use M3 behavior. Before tick5400 army guards; from5400 onward idle/arrived combat units attack weakest strategic opponent presence by category: builder, barracks/factory, depot, reactor; nearest then ID within category. Use explicit attack, reassign only idle units, no repeated overriding ongoing attacks. All visible map knowledge is allowed; no difficulty knobs, build planner, blackboard or RNG.

Simulation match metadata opt-in: exactly two registered players; existing scenes have no match and no victory checks. After combat, owner survives if any builder or completed production-capable depot/barracks/factory exists. Incomplete foundations and reactors do not count. No survivors => draw; one => winner; both => ongoing. Queue/cash/remaining army/collector alone cannot prevent defeat. Terminal state freezes subsequent stepping and rejects new orders unchanged; restart creates entirely new simulation/scene controller state, including IDs, queues, selection, preview, sequence, timers and camera. This adopts blueprint's proposed prototype victory rule; not retail fidelity.
