# Setup screen and collection: last slice of version 1

Read `INTENT.md` and `AGENTS.md` first. They win over this document where they disagree. This document describes the last slice of version 1 in `docs/version-plan.md`: "Setup screen with the piece slider from 12 to 400, snapping to valid rows-by-columns splits, and a live preview of the cut lines over the image", "One bundled image collection" and "a repeatable way to install the APK on a phone". The previous slice is `docs/superpowers/specs/2026-11-03-save-resume-design.md`.

## Intent

`INTENT.md` says: "The player picks a picture from a collection, chooses how many pieces to cut it into and what style of pieces", "The slider moves between valid rows-by-columns splits that fit the image's aspect ratio" and "The setup screen shows the cut lines over the actual image as a live preview." Today the app opens straight onto a 400-piece cut of a generated gradient. After this slice it opens on a setup screen, plays real pictures from a bundled collection, and goes back and forth between the two without losing a game.

`INTENT.md` "Content": images are public domain, CC0, the owner's own, or AI-generated, and each collection has a manifest. Open decision 9 (which images) is still open, so this slice ships a placeholder set the owner can replace. Open decision 12 gives the owner's own work CC BY 4.0 by default.

The anti-goal "Stutter or visible lag while dragging pieces" extends here to the slider: moving it must never wait on the cut generator.

## What the slice delivers

1. **A placeholder collection.** Six abstract pictures generated by a deterministic headless script, `tools/make_collection.gd`, committed as WebP with thumbnails and a manifest in `assets/collections/abstract/`. Credit "Aaryash Shakya, generated by tools/make_collection.gd", licence CC BY 4.0, marked `"generated": true`.
2. **A collection loader.** `Collection` (`src/game/collection.gd`) reads and validates a manifest and loads a picture or its thumbnail as a `Texture2D`. A bad entry is skipped with one warning; a bad manifest gives an empty collection with one warning. Nothing crashes.
3. **A setup screen, the new main scene.** Pick a picture from thumbnails, pick Regular or Irregular, pick a count on a slider that only stops on valid counts, see the cut lines over the picture, press Start. A Resume card appears when a resumable save exists.
4. **Navigation.** Setup to board with a new puzzle or the resumed save; board to setup through a Home button in the HUD and through Android back, both saving first. Back on the setup screen quits.
5. **The board takes its puzzle from the caller.** Picture, size, style, count and seed come from the setup screen. The constants stay only as the test puzzle the board tests use. A restore checks the picture against the collection.
6. **A build-and-install script.** `tools/build_apk.sh` exports the debug APK headless to `build/pieceful-debug.apk` and installs it with `adb install -r` when one phone is connected.

## The collection

### Files

```
assets/collections/abstract/
	manifest.json
	ember-rings.webp        thumbs/ember-rings.webp
	stained-glass.webp      thumbs/stained-glass.webp
	...
```

The thumbnail of `<file>` is `thumbs/<file>`, by convention, so the manifest has no thumbnail field. A picture without a thumbnail still works: the loader falls back to the full picture.

### The manifest

```json
{
	"id": "abstract",
	"pictures": [
		{
			"credit": "Aaryash Shakya, generated by tools/make_collection.gd",
			"file": "ember-rings.webp",
			"generated": true,
			"height": 1365,
			"id": "abstract-ember-rings",
			"licence": "CC-BY-4.0",
			"title": "Ember Rings",
			"width": 2048
		}
	],
	"title": "Abstract"
}
```

- **Top level:** `id` and `title` are non-empty strings, `pictures` an array. Any failure here, a missing file or JSON that does not parse gives an empty collection and one `push_warning` starting `Collection: could not use`.
- **Each picture**, checked in this order; the first failure skips the picture with one `push_warning` starting `Collection: skipping picture`, naming its index and the reason:
  - a Dictionary with every key above; extra keys are ignored, so a later version can add fields;
  - `id` a non-empty string, unique in the collection (a second picture with the same id is skipped);
  - `title` and `credit` non-empty strings;
  - `file` a non-empty string that is a plain file name: no `/`, no `\`, no `..`;
  - `width` and `height` integers from `Collection.MIN_SIDE` (64) to `Collection.MAX_SIDE` (4096), accepting integral floats as `SaveGame` does;
  - `licence` one of `Collection.LICENCES`: `"CC0-1.0"`, `"public-domain"`, `"CC-BY-4.0"`;
  - `generated` a bool;
  - `CutGenerator.valid_counts(width, height, 12, 400)` is not empty, so the slider always has a stop;
  - `ResourceLoader.exists(<collection folder>/<file>)`. Not `FileAccess.file_exists`: an exported APK holds only the imported texture, not the source `.webp`.
- **Picture ids** are `<collection id>-<slug>`, so they stay unique when more collections arrive. Saves store this id.
- **Sizes are checked when a texture loads.** `load_texture` returns null with one warning when the loaded texture's size is not the manifest's. The setup screen then drops that picture. Checking every size at startup would load every full picture.

### The pictures

| Slug | Title | Aspect | Size at 2048 | Motif |
|---|---|---|---|---|
| `ember-rings` | Ember Rings | 3:2 | 2048 x 1365 | overlapping sets of concentric rings |
| `stained-glass` | Stained Glass | 2:3 | 1365 x 2048 | Voronoi cells with dark leading between them |
| `tide-stripes` | Tide Stripes | 1:1 | 2048 x 2048 | bands warped by noise, with fine hatching |
| `confetti-field` | Confetti Field | 4:3 | 2048 x 1536 | hundreds of overlapping discs and squares on a two-tone gradient |
| `prism-mosaic` | Prism Mosaic | 16:9 | 2048 x 1152 | a triangle mosaic with colour drifting across it |
| `woven-plaid` | Woven Plaid | 9:16 | 1152 x 2048 | crossing translucent stripes |

The short side is `roundi(2048 * short / long)`. Two portrait and four other shapes, so the slider's split logic is exercised on every shape the phone is likely to see.

**Solvable, not flat.** A jigsaw is hard to solve where regions look alike. Every picture is built from three layers, so no part of it is flat:

1. **Palette:** six colours spread around the hue wheel from the picture's seed, so neighbouring regions differ in hue, not only in brightness.
2. **Structure:** the motif splits the picture into many distinct regions: at least 12 rings, 40 cells, 18 bands, 300 confetti shapes, 200 triangles or 16 plaid bands. Each region takes a palette colour, so every part of the picture has a place it belongs.
3. **Grain:** `FastNoiseLite` fractal noise, with features about 12 px across at 2048, shifts brightness by up to about 8% everywhere, plus a low-frequency tint drift, so even inside one region the surface has texture an edge can be matched by.

The art test checks this on the committed files: colour variety (at least 16 of 64 colour bins each hold 0.5% of sampled pixels, and none holds more than 20%) and no flat areas (in at least 95% of 32 px tiles the sampled luminance has a standard deviation of at least 0.01). The builder tunes the art to pass, not the thresholds.

**Encoding.** Lossy WebP at quality 0.8, which should land each picture at about 300 to 600 KB (`docs/technical-notes.md`). Thumbnails are 256 px on the long edge (Lanczos), also lossy WebP at 0.8. Godot imports the pictures with **compress mode Lossy (quality 0.8) and mipmaps**: the default Lossless mode would store each noisy picture as a lossless image of several megabytes and bloat the APK, and mipmaps keep the scaled-down preview from shimmering. Thumbnails import Lossless with mipmaps. The `.import` files are committed with these settings.

**Deterministic.** All layout randomness comes from `SeededRng` with the picture's fixed seed, and the noise from `FastNoiseLite` with the same seed. Positions and sizes are fractions of the long edge, so a picture rendered at 240 px has the same layout as at 2048 px. The test checks that two renders give **the same raw pixels** (`Image.get_data()`), and that two WebP encodes of one render give the same bytes within one Godot build. It does not compare the committed files byte for byte, since a Godot upgrade may change the WebP encoder.

**The tool.** `godot --headless --script tools/make_collection.gd` writes the six pictures, their thumbnails and the manifest to `assets/collections/abstract/`. Arguments after `--`: `--out <res:// folder>`, `--id <collection id>`, `--title <title>`, `--long-edge <px>`. The same tool writes the test fixture: `-- --out res://tests/fixtures/collection --id fixture --title Fixture --long-edge 240`, with thumbnails at half the long edge (120 px). The tool overwrites what it writes, so once the owner replaces pictures by hand, the tool is not run again on that folder. `tools/` and `tests/` are already excluded from the APK.

## The setup screen

`SetupScreen` (`src/ui/setup_screen.gd`, scene `src/ui/setup_screen.tscn`, the main scene). Built in code like the HUD, themed with `UiTheme.build()`, on the page background colour. Portrait, from the top:

1. **Title** "Pieceful", title style, below the status bar margin (56 px).
2. **Resume card** (a panel), only with a resumable save: the saved picture's thumbnail, the line "`<title>` · `<count>` pieces · `<Regular|Irregular>`", and a "Resume" button.
3. **Preview**: the chosen picture, fitted to the width and capped in height, with the cut lines drawn over it (below).
4. **Picture title** of the chosen picture.
5. **Picture strip**: a horizontally scrolling row of thumbnail tiles, one per usable picture, the chosen one pressed.
6. **Style**: two option tiles, "Regular" and "Irregular". The tab-less grid is not offered.
7. **Count**: "`<n>` pieces" in the title style, "`<columns>` x `<rows>` grid" in muted text, and the slider.
8. **Start** button, full width, at the bottom.

The rows between the title and Start scroll if the screen is short. Colours, fonts and radii come from `docs/visual-design.md` through `UiTheme`: option tiles (style and pictures) use a new `UiTheme.OPTION` button variation, raised surface with a line border when off and the accent with its shadow edge when on, radius 9 px. The slider track is the raised surface, the filled part the accent, the grabber a 44 x 30 accent tile with radius 9, like the prototype.

### The slider

- The slider's value is an **index** into `counts = CutGenerator.valid_counts(width, height, 12, 400)` for the chosen picture, step 1. It cannot stop on a count that is not a valid split, and `CutGenerator.grid_split` gives exactly the count shown.
- **On a picture change** the count becomes the valid count nearest the previous one; a tie goes to the smaller count. So 54 on a 3:2 picture stays 54, and on a square picture (where 54 is not valid) becomes the nearer of its neighbours.
- **First open:** with a resumable save, the save's picture, style and count; otherwise the first picture, Regular, and the count nearest 54.

### The preview

- `CutPreview` (`src/ui/cut_preview.gd`) draws the picture fitted and centred in its rectangle, then every piece outline twice in one `draw_multiline` call each: a dark line (black at 45%, 3 px on screen) under a light one (white at 92%, 1.6 px), as in the prototype. Shared edges are drawn by both pieces; at 400 pieces that is up to about 42,000 segments (104 per piece), one draw call per colour. The picture is drawn with mipmaps.
- **The cut shown is the cut the player gets.** The setup screen draws one seed when it opens, `SeededRng.hash2(unix time in ms, Time.get_ticks_usec())`, and both the preview and Start use it. Every visit to the setup screen draws a new seed.
- **The regeneration rule.** Generating 400 pieces takes about 20 ms on the desktop, so several times that on the phone; it must never run per slider step. So:
  - Moving the slider updates the count and grid labels at once (cheap).
  - The cut is regenerated only when the input **settles**: on slider release, on a style or picture change, and on a slider change that is not a drag (a tap on the track). Each of these (re)starts a one-shot timer of `SetupScreen.PREVIEW_DELAY` (0.15 s); when it fires, the cut is generated once. Several changes within the delay give one generation.
  - While a finger drags the slider, the timer is stopped and nothing is generated. The preview keeps the previous lines until the new ones arrive.
  - A picture change shows the new picture at once with no lines, since the old lines belong to another shape.
  - Opening the screen schedules the first generation through the same timer, so the screen appears before the cut is ready.

### Resume and Start

- **Resumable save:** the file at the save path parses with `SaveGame.from_json`, its picture is in the collection at the saved size, and its style is Regular or Irregular. Only then is the Resume card shown. A save file that exists but is not resumable (corrupt, another version, an unknown picture such as the old `test-gradient`) is moved aside to `current.bad.json` with one warning starting `SetupScreen: could not resume`, as the board does. So Start only ever replaces a game the player could see on the Resume card.
- **Start** builds a board for the chosen picture, style, count and the screen's seed, with `resume = false`. The board starts fresh and saves at once, replacing any save. **There is no confirmation**: the Resume card stays in view above, so starting over is a visible choice. If the owner loses a game this way, a confirmation follows.
- **Resume** builds a board with `resume = true`. Its fallback puzzle is the saved picture, style and count with the screen's new seed: if the board's deeper checks reject the save (a cut that no longer matches, broken clusters), the board sets it aside and starts that fallback, not the test gradient.
- Start and Resume work once: the first press disables both and changes the scene; a second press does nothing.

## Navigation

- **Setup to board:** `SceneTree.change_scene_to_node(board)` with a board instanced from `board.tscn` and its fields set before it enters the tree. The setup screen is freed.
- **Board to setup:** the board emits `home_requested` after `go_home()`; the setup screen connected it when it built the board, and answers by building a new setup screen with the same save path and collection and changing to it. The board does not know about the setup screen, so board tests that send back see only the save.
- **Home button:** "Home", top left of the HUD at the status bar margin, the same size as Tidy. The debug frame-rate counter moves down below the button row. The bottom of the screen stays free for the version 2 slots.
- **Android back on the board:** `NOTIFICATION_WM_GO_BACK_REQUEST` calls `go_home()`. Project setting `application/config/quit_on_go_back=false`, so Godot no longer quits on back anywhere; each screen handles it.
- **`go_home()`** completes a running tidy, force-drops what is held, saves (or deletes the save of a complete puzzle) exactly as the other leave paths do, then emits `home_requested`, once: a second call does nothing.
- **Android back on the setup screen** quits through `SetupScreen.quit_app` (defaults to `get_tree().quit`), a seam so the test does not quit the runner.
- Closing the window, pausing and focus loss behave as before: save, no navigation.

## The board

- New fields, set before the board enters the tree: `collection: Collection` (null in board tests), `start_puzzle: SaveGame.Puzzle` (the new game's identity; null means the test puzzle from the constants), `resume := true` (try the save first).
- **Picture lookup** `picture_texture(image_id, size)`: the test picture `IMAGE_ID` at `IMAGE_SIZE` gives the generated gradient; otherwise the collection's picture with that id and exactly that size, loaded; otherwise null.
- **Start:** with `resume`, restore as today, with the image check replaced: a save whose picture `picture_texture` cannot give is set aside ("unknown image"). With no usable save, or with `resume == false`, start fresh from `start_puzzle` when it is set and its picture resolves, otherwise from the constants (with one warning if a `start_puzzle` was given and could not be used). A fresh start from `start_puzzle` saves at once; a fresh start from the constants does not, so the existing tests keep their meaning.
- **`resume == false` never reads the save,** so Start cannot be blocked by a bad file; the setup screen already set unusable ones aside.
- The texture is any `Texture2D`; `_apply_image_size` resizes it only when it is the generated gradient.
- The save format does not change. `image_id` now holds a collection picture id.

## Build and install

`tools/build_apk.sh` (bash, executable, run from anywhere):

1. `set -euo pipefail`; change to the repository root.
2. `godot` (or `$GODOT`) must be on the PATH, else: "godot not found: install it (docs/dev-setup.md step A) or set GODOT".
3. The Android export templates for the running version must exist in `~/.local/share/godot/export_templates/<major.minor.patch.status>/`, else an error naming the folder and step E.
4. `godot --headless --import`, then `godot --headless --export-debug "Android" build/pieceful-debug.apk`. A missing APK afterwards is an error pointing at the editor's Project, Export, Android dialog.
5. With `--no-install`, stop and print the APK path.
6. `adb` is `$ADB`, else `~/Android/Sdk/platform-tools/adb`, else `adb` on the PATH. Without one, print the APK path and that nothing was installed; exit 0.
7. Devices in state `device`: none prints the APK path, says no phone is connected (and lists any `unauthorized` ones with the hint to accept the prompt); exit 0. More than one without `ANDROID_SERIAL` is an error asking to set it. One: `adb install -r build/pieceful-debug.apk`; a failure exits with adb's code and the hint that a signature mismatch needs `adb uninstall`, which deletes the save.

`build/` is git-ignored. `docs/dev-setup.md` documents the script next to Remote Deploy. The export preset's include filter gains `assets/collections/*/manifest.json`, so the manifest is in the APK.

## Goals

- The app opens on a setup screen that offers only valid counts for the chosen picture and shows the exact cut the player will get.
- Dragging the slider never generates a cut; the preview catches up within about 0.15 s of the finger settling.
- Leaving the board by Home or back always saves, and Resume restores that game exactly.
- One command builds the APK and puts it on the phone.
- The collection is data: the owner replaces pictures by editing a manifest, and a mistake skips one picture with a warning.

## Non-goals for this slice

- The completion screen, timer display, ghost image, slots, settings, the store and downloads, Wild, the daily puzzle, stats (later versions).
- More than one collection, or a collection picker (version 2, open decision 7).
- Remembering setup choices between launches beyond the save.
- Generating the preview on a thread.
- Release signing.

## Anti-goals

- A cut generated per slider step, or any visible wait while the slider moves.
- A slider stop that is not a valid split.
- A preview that shows a different cut from the one Start gives.
- Losing a saved game through Home, back, or a bad file, without the file being set aside.
- Tests that depend on the bundled art for anything except checking that art.
- A network call, a dependency, or images under any licence outside `Collection.LICENCES`.

## Constraints

- Godot 4.7.2, GDScript, Mobile renderer. Android only. Package name `io.github.aaryash_shakya.pieceful`, do not change it.
- No new dependencies, plugins or network calls. No autoloads.
- `src/cut/` stays free of scene code; the setup screen calls `CutGenerator` like the board does.
- Tests are plain headless scripts extending `BaseTest` or `BoardTest`, run with `timeout 300 godot --headless --script tests/<name>.gd`, and never touch `user://save/`.
- Colours, fonts and radii from `docs/visual-design.md`, through `Palette` and `UiTheme`.
- Match the style of the surrounding code. Keep comments sparse and explain why.

## Decisions the owner made

- Images are public domain, CC0, the owner's own, or AI-generated, with credit and licence in a manifest per collection (`INTENT.md`, `AGENTS.md`).
- The slider runs from 12 to 400 and stops only on valid splits for the picture's shape; the setup screen previews the cut over the picture (`INTENT.md`).

## Calls made by Claude, which the owner has not confirmed

The orchestrator was delegated these decisions by the owner. Each one below is Claude's, or the orchestrator's where marked.

- **Scope** (orchestrator): one generated collection of about six abstract pictures (CC BY 4.0, marked generated), the loader, the setup screen as the main scene, Home and back, the board taking its puzzle from the caller, the build script, and the tests listed in the plan.
- **Placeholder art, not chosen art.** Open decision 9 stays open. The six motifs, titles, seeds and palettes are Claude's.
- **Licence values** are SPDX-style strings, `"CC0-1.0"`, `"public-domain"` and `"CC-BY-4.0"`, so a typo is caught. An AI-generated picture is `"generated": true` with its model named in `credit`; there is no separate AI flag.
- **`generated` means made by a program** (this tool or an AI model), as opposed to photographed or drawn by hand.
- **Thumbnails by file-name convention** (`thumbs/<file>`), with the full picture as fallback, so the manifest stays the seven fields asked for and an owner-added picture works without one.
- **Sizes are checked at texture load, not at manifest load**, so the setup screen does not load six full pictures to open.
- **Extra manifest keys are ignored,** unlike the save, which rejects them: the manifest is the owner's hand-edited file, and later versions will add fields.
- **Lossy import with mipmaps** for the pictures, Lossless for thumbnails. The phone check confirms the pictures look clean on the board; if lossy artefacts show at full zoom, the import moves to VRAM compression.
- **Measurable richness** (colour bins and tile contrast) instead of a judgement, so "solvable" has a test. The owner still looks at the pictures.
- **Determinism is checked on raw pixels and on same-build encodes,** not on the committed bytes.
- **The preview uses the game's seed,** drawn when the setup screen opens, so the preview is the real cut.
- **The preview rule:** a 0.15 s settle timer, never during a drag, generation on the main thread. If the phone shows a hitch when the finger lifts at 400 pieces, the generation moves to a `WorkerThreadPool` task in a follow-up.
- **Default count 54**, the prototype's default and the Monday daily.
- **Nearest count on a picture change,** ties to the smaller count.
- **No confirmation before Start replaces a save.** The Resume card is on the same screen. This is the call the owner is most likely to want changed.
- **Start saves at once,** so the Resume card always shows the latest game, even if the app is killed before any lock or leave.
- **Unresumable saves are set aside by the setup screen,** keeping the previous slice's rule that a save the game cannot use is kept, not deleted. The owner's existing `test-gradient` save goes to `current.bad.json` on the first launch of this build.
- **Resume falls back to the same picture, style and count** with a new seed when the board rejects the save.
- **The board resolves the texture itself** from the picture id through the collection, so a texture can never disagree with the saved id. The caller passes the collection, not a texture.
- **Home top left, frame counter below it.** Top right is Tidy, the bottom is for slots. The label "Home" is text, like "Tidy", until there is an icon set.
- **`quit_on_go_back` is off** and back is handled per screen: home on the board, quit on the setup screen.
- **Navigation by `change_scene_to_node`** and a `home_requested` signal, with no autoload or navigator class.
- **`go_home()` runs once** per board, so a double back press cannot build two setup screens.
- **The build script exits 0 when it built the APK but could not install it** (no adb, no phone), since the build is the part that always has to work; it fails only on a real error or several phones.
- **File layout:** `collection.gd` in `src/game/` next to the save modules; `setup_screen.gd`, `setup_screen.tscn` and `cut_preview.gd` in `src/ui/`; the art code in `tools/art_synth.gd` beside `tools/make_collection.gd`, like the sound tool; the fixture in `tests/fixtures/collection/`.

## What happens if it does not work right

The owner checks the screen and the pictures on the phone (the plan's "Owner checks"). If the slider stutters, the label update is the only work left on the drag path, so the cause is elsewhere (the frame counter shows it). If lifting the finger at 400 pieces hitches, the generation moves to a thread. If a picture looks blotchy, its import moves to VRAM compression or a higher lossy quality. If the APK lacks the pictures, the export filters are wrong and the include filter is fixed. If back quits from the board, `quit_on_go_back` did not take and `adb logcat -s godot` shows which notification arrived.
