## Intent

Fix the four notes from the 2026-11-04 friend match so that the game plays closer to Zero Hour:

1. The attack-move click shows nothing.
2. Your own units attack and chase from far away.
3. Attack-move leaves part of a split army standing.
4. Resuming an unfinished building gives no feedback.

User priority: stay close to the real game. Success:
- Your idle units hold position and shoot only what is in range.
- Retaliation answers a raid near your units.
- Every ground click (move, attack-move, set-rally) and every resume order gives visible feedback. As in the source, there is no hint for attack or gather clicks.
- A group order never fails silently.

**Non-goals:** turret fire while moving (Wargrid has no turrets), fog and line of sight, AI moods (M8), new units, M6 map work.

**Anti-goals:** a hand-tuned rule with no source basis, and a benchmark that passes because a budget or an assertion moved.

## Simulation changes (change replay traces)

### S1. Human acquisition rule

**Controller.** Read `players[owner].controller`. A missing player counts as human (as today). AI-controlled units keep the M4.1 rule unchanged.

**Human `guard`:**
- Acquire only enemies within weapon range. Use the existing nearest-target search and ID tie-break; collectors stay excluded.
- Never approach.
- When the target leaves weapon range, drop it and rescan on the next cadence tick.
- The unit never moves on its own.

**Human `attack_move`:**
- While marching, acquire only within weapon range, then halt.
- The first approach to that target is allowed and has no leash.
- If the target leaves weapon range after the unit started firing, drop it.
- When an engagement ends (the target died, was dropped or was removed), rescan once in the same tick. The radius is vision × `GUARD_OUTER_HUMAN`: rifle 8.8 cells, tank 13.2.
  - A target found that way starts a new approach.
  - If nothing is found, the unit repaths to `combat.goal`. On arrival it switches to `guard`.
- This allows an unbounded chase while the target stays inside that circle. That is source parity, not a bug.

Open for the builder: what "dropped" means for an attack-move approach in progress. The source's first approach is not cut off by range. Only a later re-chase fails, and the forced rescan then restarts it.

**Unchanged:**
- Explicit `attack` still chases without limit.
- `move` and rally moves never acquire.
- The opponent's base-defence rule.

**Cadence (user decision).** Keep the staggered `REPATH_TICKS = 8` scan and the M4.1 `stop` phase rule. Recorded departure: the source rescans 3 ticks after going idle, then every 60 ± 30 ticks.

### S2. Retaliation

Values come from retail `AIData.ini`; see the evidence file.

**Trigger.** A unit or building owned by a human player takes a hit from an enemy unit whose edge-to-edge distance is ≤ 8 cells. The killing hit counts too. The trigger fires at damage application in `combat.gd`.

**Joiners.** Units of the victim's player, the victim included, that are:
- within 4.8 cells plus the victim's radius of the victim's centre (a building's radius is half its footprint diagonal, my call);
- in `guard` with no target;
- armed.

**Each joiner:**
- Enters a new mode, `retaliate`, with `home` set to its position at trigger time and the attacker as its target.
- Chases until one of these happens:
  - the unit is more than G = vision × 1.8 from `home` (rifle 7.2 cells, tank 10.8);
  - the attacker is more than vision × 4.0 from `home` (rifle 16 cells, tank 24);
  - 300 ticks have passed since the trigger (the timer is never reset);
  - the target is dead or removed.
- Then walks back to `home`.

**On the way back:**
- Every 30 ticks, scan for the nearest enemy unit (not a building) within G of `home`. A hit restarts the chase against that target, with the same leash and a fresh timer.
- If an attacker the unit can return fire against hits it, restart the chase against that attacker with a fresh timer. This is the retail/EA transition.
- On arrival the unit switches to `guard` at `home`.

**Precedence.** Any player command replaces `retaliate`. AI-owned victims never trigger retaliation.

**Simplification (user decision).** The source's separate INNER and OUTER states fold into "restart the chase under the same leash". Recorded as a departure.

Builder's call: units count as points for the radii. When several shots land in one tick, they trigger in the existing shot order.

### S3. Per-unit group orders

Applies to `move`, `stop`, `attack`, `attack_move` and `gather`, at issue time and at due time.

**Ids:**
- Ids that no longer exist are skipped.
- If none remain, the command is rejected with `No units left`.
- A live id owned by another player still rejects the whole command. That is the trust boundary.

**Unarmed members:**
- In `attack_move`, unarmed members (builder, collector, vehicle) get a plain `move` to the same target. If no member is armed, the whole command is a plain move.
- In `attack`, unarmed members are skipped. The command is rejected only if no member is armed. My call: the source's `groupAttackObject` was not checked.

**Tests.** The M4 tests that assert whole-command rejection change on purpose: V1 "attack_move unarmed" (`test_combat.gd`) and K3 (`test_skirmish_scene.gd`). The walkable-target rule is unchanged.

**Cause check.** Task 1 reproduces the bug before S3 is built. If the reproduction shows a cause other than a dead selected id or an unarmed member (for example allocation or pathing), stop and report.

## Presentation changes (no trace change)

**Click hint:**
- A ground click for move, attack-move or set-rally draws a marker at the click for 40 ticks.
- It comes from client state, so online it shows before the command is due.
- The marker is the same for move and attack-move, as in the source. My call: an expanding ring in the existing order green.

**Selection pruning.** `selected_ids` drops ids that are missing from the snapshot on every refresh.

**Online rejections.** The status line shows the local player's latest lockstep rejection, the way offline already shows `_error`.

**Resume hint:**
- With exactly one own builder selected, hovering an own unfinished building that has no builder attached highlights its outline, and the status line reads `Right-click: resume`.
- Issuing the order draws the click hint on the building.
- The building's label adds `paused` while no builder is attached.
- My call: this stands in for the source's cursor and voice line.

Each HUD change gets a headless layout test (no overlap with the status text).

- `retaliate` against every command, and against removal of the attacker or the joiner.

- `test_combat_navigation.gd`: M1, G2, U1.

**Benchmark:**
- `sh tools/run_benchmark.sh` with unchanged budgets and a new ledger row.
- The combat benchmark keeps human-controlled players. It still asserts chases inside the timed window, which now come from attack-move approaches and retaliation; the assertion is never dropped. It also asserts that retaliation triggers.
- The BM6 work ceiling and floor are re-pinned only to the measured value and with the user's approval. That approval is collected at the same stop as the rendered rerun.

**Other gates:**
- A rendered rerun, since presentation changes.
- CI on Linux and Windows, plus the macOS trace comparison.
- One substantive review and one `/ponytail-review`.
- A user playtest.

**Top risks:**
1. The scripted human may no longer win inside the 5–10 minute gate once its units stop chasing.
2. With human workload players the chase load falls, so the benchmark's chase assertion has to find chases elsewhere, and the BM6 floor (> 20000) likely fails and needs a re-pin.
3. Retaliation adds one radius query per damage event.
