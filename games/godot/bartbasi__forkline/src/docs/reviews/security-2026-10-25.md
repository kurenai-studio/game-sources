# Security review, 2026-10-25: phase 7 at HEAD fdbfec7

Reviewer: security-reviewer. Build: HEAD fdbfec7 (`fdbfec795f94cd946291ea00e4f57016e1102591`). Windows only; the Fold5 was not connected. The uncommitted files under tools/balance/ and docs/balance/ were left out, as asked.

Scale: High, Medium, Low and Note, as the DM asked. Every High gets fixed and reviewed again. Bart decides on Medium, Low and Note.

## Summary

No Critical, High or Medium finding. The baseline in CLAUDE.md and the playbook holds:

- No network code anywhere. No permission in the export preset or in a fresh debug APK built from HEAD.
- Every outbound address is one of three constants, and only src/ui/links.gd hands one to the phone.
- Saves are JSON only, read through the JSON parser after a size cap and an ASCII check, checked field by field, and written atomically with a handled failed rename. Files stay in user://.
- No secret, keystore or Windows account path in the tree or in the git history.
- The only third party files are the GPL text and the Outfit font with its license, all unmodified. Nothing from tools/, tests/, docs/, prototypes/ or scripts/ is in the APK, and every bundled part is credited in NOTICE, README and About.

Hostile testing found no crash, no hang on load and no script error: 4,000 random mutations of real saved games, 1,500 random mutations of the data files, and a set of hand-made hostile files. Genuine play never reached a state its own load check refuses: 20 runs and dailies, 1,816 save round trips, 0 refusals.

Findings: 4 Low and 6 Note. The two Low findings in the sim are about tampered saves, which only someone who can write the app's private files can make.

## Findings

### Low

**L1. A tampered save can schedule work far past the creature ceiling.** Owner: sim-engineer (src/sim/battle.gd). Contract: ARCHITECTURE 5.6.

Where: battle.gd:1949 allows 1,000 releases and battle.gd:1972 allows 200 creatures still to come in each, but nothing limits their product. battle.gd:1842 allows 4,000 live creatures, and any of them may be a boss with a summon (battle.gd:1919), though play never has more than 2 bosses (Double Trouble on a boss level).

Steps:

1. Take a campaign save mid-wave: r1_l2, one tower, 20 ticks into wave 1.
2. Fill `battle.releases` with 1,000 entries, each `{"enemy": "scamp", "wave": <a running wave>, "left": 200, "next": <tick>, "gap": 1, "from": <entrance 1>, "to": <entrance 1>, "progress": 20000}`.
3. Set `battle.lives` and `battle.start_lives` to 1000000.
4. Write it as game_level.json (about 100 KB) and load it with `SaveStore.load_games`. It loads in 64 ms.
5. Step the battle.

Result on the dev PC: 10,001 creatures after 10 ticks, 100,004 after 100 and 179,003 after 200. A tick then takes about 0.6 s. After a long frame BattleClock still runs 5 ticks at 1x, so each frame takes about 3 s in the sim alone, before MapView adds a node for every creature. No script error.

Why it matters: the load ceilings exist to refuse tampered saves before they break the game (playbook section 11). Each field here is in range, but together they allow about 200,000 creatures where play peaks near 240. Making such a file needs write access to the app's private storage: root, or run-as on a debug build. Backup is off and the game imports no files. So the risk is a frozen game of the player's own. The player gets out by starting over in that mode, which replaces the saved game.

Fix: on load, refuse a battle whose live creatures plus creatures still to come from releases pass `MAX_ENEMIES` (4,000), and one with more than a few creatures that summon (for example 8). Play stays far below both: in 20 full runs the peak was 42 live creatures and 1 release.

**L2. A wave save may hold gates that close every road.** Owner: sim-engineer (src/sim/battle.gd). Contract: ARCHITECTURE 5.6.

Where: battle.gd:1706 runs the seal check only in a build phase. Play never makes a sealing wave save: gates are placed only in build phases, where sealing is refused, and during a wave gates only break open or stay.

Steps: take an r1_l2 save right after wave 1 starts (no creature spawned yet). Set the saved level's `gates` to 2, place gates on both sockets ([3, 3] and [6, 5]) and set `gates_in_hand` to 0. It loads in the wave phase with `seals()` true. Creatures then wait at the entrance; the wave ends only if towers reach them, and the next build phase starts sealed. No script error.

Fix: run the same seal check in the wave phase on the closed set (unbroken gates, and none while `gates_open`). Play never fails it, so it costs nothing.

**L3. The security rules test misses some loaders and network classes.** Owner: DM (tests/project/test_security_rules.gd).

Where: the FORBIDDEN list (lines 9 to 17) names the network classes plus `str_to_var`, `bytes_to_var`, `get_var` and `ConfigFile`. It does not name `ResourceLoader`, `load(` outside tests/ and tools/, `dict_to_inst` (it makes an object from a dictionary that names a script), `base64_to_variant`, `UPNP`, `IP.resolve_hostname`, `OS.execute`, `OS.create_process`, `JavaClassWrapper`, `JNISingleton` or `Engine.get_singleton`. It scans only .gd files (line 56), so a GDScript embedded in a .tscn or .tres would pass.

Nothing in src/ uses any of these today (checked by grep), and tests/sim/ and tests/run/ already scan src/sim/ and src/run/ more strictly. This is a gap in the guard, not a hole in the game.

Fix: add these words, allow `load(` only under tests/ and tools/, and also scan .tscn and .tres files for `type="GDScript"`.

**L4. docs/ASSETS.md lost the font's source.** Owner: DM (docs/ASSETS.md).

Where: docs/ASSETS.md:10 says the font was "Copied unmodified from the slice copy below", but that row was removed with the slice on 2026-10-24. The earlier text named the real source: SumUp's src/design/fonts/, originally from the Outfit project (Google Fonts).

Checked: both files are byte for byte the same as SumUp's copies (MD5 `e31a3aa5fce3366bcadb8e9027f26178` for the font, `fc7bcc2f3d37195db3ea982ccfecd531` for OFL.txt).

Fix: restore that source line, ideally with the upstream address. OFL.txt names github.com/Outfitio/Outfit-Fonts.

### Note

**N1. Saved runs are not tied to their picks, and saved levels not to the bundled map.** Owner: sim-engineer (src/save/saved_game.gd) with roguelite-engineer (src/run/run_session.gd). Contract: ARCHITECTURE 5.6.

RunSession.from_data (run_session.gd:190 to 211) checks the seed, day, pool and picks. Battle._load_effects (battle.gd:1720 to 1744) checks each effect. Nothing checks that the kept card effects come from the picks, or that a waiting risk card (`risk`, `wave_risk`) is a card that was picked. For a campaign game, saved_game.gd:80 compares only the level id, so a save can carry a changed map under a real id and earn its stars.

Steps: on a new run's save, set `battle.risk` to seven `count_pct` 1000 effects plus one `reward_gold`. It loads; `risk_card()` is empty; wave 1 previews 80,000,000 Scamps and never finishes spawning. They come one at a time, so it stays cheap (11 live creatures, 0.03 ms a tick).

Impact: cheating in an offline game, and a wave that never ends. No crash. Saving the level was a deliberate contract choice, so that a later data change never breaks a saved game. Bart decides. If wanted: rebuild the kept effects from the picks in pick order and compare, and require a waiting risk card to equal the effects of the last risk card picked.

**N2. `Links.is_ours` accepts any draft to the feedback address.** Owner: ui-engineer (src/ui/links.gd).

links.gd:32 to 35 accept anything that starts with `mailto:bartbasi@gmail.com?`, so an added `&cc=` would pass if a caller ever built such a draft. Today only `feedback_url` builds one, with `uri_encode` on the subject and body, and every caller passes a constant. For defense in depth, accept exactly `feedback_url(version(), device_text())`.

**N3. No suite wide guard on the link opener.** Owner: DM (tests/run_tests.gd or tests/base_test.gd).

The three test files that touch links each install a recorder, so nothing real opens today. A future test that taps the coffee row without one would open a real browser on the PC. Suggestion: before each test file, set `Links.opener` to a recorder that fails the test, and reset it after.

**N4. scripts/check_apk.sh does not check `android:debuggable`.** Owner: release-engineer (scripts/check_apk.sh).

A debug APK is debuggable, as expected, which lets anyone with USB access read and change saves through run-as. Godot's release export is not debuggable and Play refuses debuggable uploads, but a release APK shared directly has no check. Suggestion: a release mode that requires `debuggable` to be absent or false. Also, check_apk.sh:275 still says the About screen "does not exist yet". It exists, and it reads its Android credits from NOTICE.

**N5. Wording for the privacy policy draft.** Owner: release-engineer (docs/store/, phase 9).

The export sets `allowBackup` to false, so there is no cloud or adb backup of saves. Android's documentation for that attribute says that, for apps targeting API 31 or higher, some manufacturers' devices can still move app files in a device to device transfer. So the policy should say the app never sends saves anywhere, rather than that the files can never leave the phone. I could not re-check that page here (no web access).

**N6. build/forkline-debug.apk is stale.** Owner: release-engineer (build output, not committed).

It dates from 2026-10-23 17:11, and scripts/check_apk.sh fails on it (exit 1): 44 data files are missing, namely every level after region 1, the run plan, the cards and the segments. Its permissions, manifest and credits are clean. A fresh export from HEAD passes every check (below). Rebuild before the next install on the phone.

## Checked and clean

Network

- No HTTPRequest, HTTPClient, StreamPeer, TCPServer, PacketPeer, UDPServer, WebSocket, WebRTC, ENet, multiplayer peer, JavaScriptBridge, UPNP, IP lookup, JavaClassWrapper, JNISingleton, `Engine.get_singleton`, `OS.execute`, `OS.create_process` or clipboard use anywhere in src/ or tools/. In tests/ these words appear only in tests/project, which names them on purpose, and in tests/ui/test_real_tree.gd and tests/render/test_frames.gd, which use `OS.execute` to start Godot itself.
- `OS.shell_open` appears only in src/ui/links.gd:28, also enforced by tests/project.
- Both command line exports (the old APK and a fresh one) request no permission. As far as I know, Godot adds INTERNET only to one-click deploys with remote debugging, which never ship.

Outbound buttons

- Three constants, each written once: links.gd:9 to 13. `open()` refuses every other address (links.gd:22 to 28).
- Callers: about_screen.gd:58 (source), about_screen.gd:96 (feedback) and coffee_button.gd:26. The front door, About and Pause all use CoffeeButton.
- `feedback_url` encodes the subject and body, so a model name cannot add a recipient or a header.
- tests/ui/test_links.gd, test_standard_screens.gd and real_tree_checks.gd replace the opener and reset it.

Permissions and the APK

- export_presets.cfg: every permission false, `custom_permissions` empty, `user_data_backup/allow=false`, `retain_data_on_uninstall=false`, no keystore fields.
- A fresh debug APK exported from a clean copy of HEAD passes scripts/check_apk.sh with exit 0: no permissions, arm64-v8a only, LICENSE, NOTICE and OFL.txt inside, all 49 data files inside, none of tools/, tests/, docs/, prototypes/ or scripts/, target API 36, `allowBackup` false, Forkline's own launcher icons, and every bundled part credited in NOTICE and README.
- Manifest components: the FileProvider is not exported; ProfileInstallReceiver is exported but guarded by `android.permission.DUMP`, which only the system holds. No uses-permission element.
- The shipped LICENSE (MD5 `1ebbd3e34237af26da5dc08a4e440464`), NOTICE and OFL.txt match the repo byte for byte. No local path or account name in any unpacked asset.
- About credits: its Godot row shows the engine license, the parts list, every license text (Apache-2.0 is among them) and the NOTICE paragraph that names the Android libraries. So About lists the same parts as NOTICE.
- The font ships as Godot's imported resource with the import option `compress=true`, so the APK stores it compressed. The engine restores the exact bytes: the loaded font data matches the TTF (MD5 `e31a3aa5fce3366bcadb8e9027f26178`). OFL.txt ships beside it as a plain file.

Saves (src/save/, and every place that reads user://)

- Only src/save/json_file.gd opens save files. `JsonFile.read` (lines 20 to 40) refuses a file over its cap before reading it, refuses NUL and bytes of 0x80 or above, and parses with `JSON.new().parse()` only.
- No `str_to_var`, `bytes_to_var`, `get_var`, `ConfigFile`, `ResourceLoader`, `load()`, `dict_to_inst` or `base64_to_variant` anywhere in src/.
- Every field is checked for type, range and shape. Settings, Progress and DailyRecord fall back field by field; SavedGame, Battle and RunSession are all or nothing. Every string is checked by character class after the parser decodes escapes, so `\u` escapes cannot slip in a NUL or a non-ASCII id.
- Writes: `to_text` refuses non-ASCII text; `write_text` writes only under user://, writes the .tmp, flushes, reads it back and compares, backs up only text it knows, and returns the result of the final rename. SaveStore refuses folders outside user:// and any `..`. Loading tries the .tmp, then the file, then the .bak; a locked file or a newer format is left alone; a bad saved game is deleted. The failed rename is covered by test_failed_rename_keeps_the_tmp_with_the_newest_text and test_failed_rename_while_the_file_is_held_open.
- Ceilings are far from play and counters saturate at them. Genuine play peaked at 42 creatures, 1 release, 4,481 gold and tick 9,683.
