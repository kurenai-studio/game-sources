## 1. 快速开始

### 环境

```bash
python 3.10+            # 本项目在 3.13 上开发
pip install pygame-ce   # 或 pip install pygame
```

### 运行

```bash
python main.py            # 图形界面
python main.py --check    # 只校验数据文件（不启动界面）
python main.py --sim 16   # 无界面双 AI 推演 16 回合，用于平衡测试
python main.py --sim 18 --map 1   # 用第 2 张地图推演
```

### 第一局怎么打

**零基础请先走教学**：主菜单点「**快速上手**」（或按 `T`），
进入「新兵训练场」想定，教学条会一步步带你走完核心循环。

正式对局流程：

1. 主菜单选择想定（`草原雷霆` 为陆战、`海峡屏障` 为海空联合），点击「开始作战」。
   - **想定卡片与阵营卡片都要点击才选中**——鼠标滑过只会有边框高亮提示，
     不会改变选择。卡片底部写着「点击选择」，选中后显示「已选中」。
2. 屏幕上会显示你方（蓝方）的单位。**左键**点选一个单位，右侧出现单位面板。
3. **右键**点击地图空地 = 下达机动指令；绿色高亮是可达范围，黄色连线是路径预览。
4. 点击**已探测到的敌方单位**，右侧切换为「交战目标」面板，显示命中率分解与**对手视角**。
5. 在面板里选武器（或按 `1-9`）、选齐射发数，点「确认开火」或按 `Enter`。
6. 打完后按 `空格` 结束回合，红方 AI 行动，然后进入下一回合。
7. 累计**胜负点**高者获胜——胜负点来自控制目标点，每回合结算一次。

> 想直接看效果：按 `F1` 打开规则速查，`F5/F9` 快速存读档，`F10` 系统菜单。

## 2. 界面总览

```
┌───────────────────────────────────────────────────────────────┬──────────────────┐
│ 顶栏：回合 / 相位 │ 胜负点条 │ 在编兵力 │ 卫导完整性 │ 在飞弹药 │ 单位详情 │ 战役态势 │
├───────────────────────────────────────────────────────────────┤ 单位卡            │
│                                                               │ 武器列表          │
│                        战 场 地 图                             │ 交战/设施面板     │
│                     （滚轮缩放 / 中键平移）                      │ 行动按钮          │
│                                             ┌───────────┐     ├──────────────────┤
│                                             │ 缩略图     │     │ 战斗日志          │
└─────────────────────────────────────────────────────────────┴────┴──────────────────┘
```

- **顶栏**：回合数与上限、当前行动方、双方胜负点对比条、在编兵力、卫星导航完整性（影响精确制导弹药）、在飞弹药数量、覆盖层切换、设置、帮助、结束回合。
- **右侧栏**三个标签页：
  - **单位详情**：选中单位的完整数据（耐久、机动、发射次数、备弹、传感器、工事、状态）。
  - **战役态势**：目标点归属、天基资产（可点击敌方卫星发起反卫星打击）、电子战状态。
  - **战斗日志**：按时间倒序的记录，含命中率与伤害明细。
- **地图**：不同地形有独立配色与纹理；海岸线高亮、600 m 等高线、山体阴影。
- **缩略图**：右下角小地图，显示整体态势。
- **教学条**（v1.1）：教学想定中显示在地图上方，列出当前步骤、说明与目标。
- **悬停信息卡**（v1.1）：鼠标停在单位上即弹出，跟随光标并自动避让屏幕边缘。

## 3. 操作速查

| 操作 | 说明 |
|---|---|
| **左键** | 选择己方单位 / 点选敌方目标 / 在可达格上机动 |
| **右键** | 下达机动指令（可直接点远处，自动寻路） |
| **悬停单位** | 弹出信息卡：双方识别状态、弹药、工事、射程环（无需选中） |
| **滚轮** | 以鼠标为中心缩放（6–46 px/格） |
| **中键拖动** | 平移地图 |
| **方向键** | 移动键盘光标（靠近地图边缘时自动滚屏；回车在光标处执行与左键等价的动作） |
| `回车` | 键盘光标处：选择己方单位 / 在可达格机动 / 选定目标，再次回车开火 |
| `空格` | 结束回合；AI 阶段按住可 6 倍快进 |
| `Tab` | 切换到下一个可行动单位 |
| `1`–`9` | 选择第 N 件武器 |
| `R` | 雷达开 / 关（关机可躲反辐射导弹，但失去探测） |
| `J` | 电子干扰开 / 关 |
| `E` | 覆盖层切换：无 / 侦察覆盖 / 敌方防空包线 |
| `Enter` | 确认开火 / 确认设施打击；或键盘光标处选择单位 / 机动 / 选定目标 |
| `Esc` | 取消目标选择 / 取消单位选择 |
| `F1` | 规则与操作说明 |
| `F5` / `F9` | 快速保存 / 快速读取到 1 号槽 |
| `F10` | 系统菜单（5 个存档槽、导出战报、设置、返回主菜单、退出） |

**v1.2 新增操作**（均在单位面板的行动按钮里）：

| 按钮 | 说明 |
|---|---|
| **链 通 / 链 断** | 开关数据链：通信受扰时主动断链，牺牲协同换抗干扰 |
| **预先射击** | 间瞄火力登记射界：点击有情报的格，准备完成后命中 ×1.45、毁伤 ×1.30 |
| **射界 X,Y** | 显示当前射界状态与剩余回合 |
| **指挥 N** | 指挥单位下达指令：点击敌方目标 = 集中火力 |
| `T` | 主菜单：直接进入教学想定 |
| `V` | 主菜单：启动 AI 观战（双方 AI 自动对战，详见 [第 6.7 节](#67-ai-对战观战)） |
| `Tab` | 主菜单：切换蓝/红方（卡片也可点击选择） |

> [第 12 章](#12-设置键位-主题-图标包-音效-语言)。

**同格多单位**：一个机场可停 4 架飞机，点击该格会循环选择其中的单位。

## 4. 回合流程

```
第 N 回合
 ├─ 蓝方行动（玩家）
 │    ├─ 机动（消耗机动点）
 │    ├─ 射击（消耗发射次数与备弹）
 │    └─ 电子战开关 / 投放诱饵
 ├─ 结算在飞弹药（远程弹药飞行 1–3 回合后抵达）
 ├─ 红方行动（AI，同一套规则）
 ├─ 结算在飞弹药
 ├─ 回合推进
 │    ├─ 工事累积 / 诱饵计时
 │    ├─ 全体单位重置（机动点、发射次数、压制）
 │    ├─ 后勤结算（油料、弹药、维修、坠机）
 │    ├─ 卫星过顶侦察（每 3 回合）
 │    ├─ 卫星导航完整性重算
 │    ├─ 目标点计分
 │    └─ 胜负判定
 └─ 第 N+1 回合
```

**关键点**：发射不等于命中。射程 ≥1 格的弹药会进入「在飞」状态，抵达时才做末端结算，且**用发射点而不是载机当前位置**重算射程——目标跑出包线、失去跟踪、载机被击落，都会导致脱靶。

## 5. 核心机制

本章只讲**玩法的物理规律**——命中怎么算、防空怎么拦、电子战怎么生效。
界面操作、编辑器与扩展能力在后续章节。

机制按**战术主题**分为六组：探测与识别、火力与毁伤、防空与反制、
电子战与伪装、指挥与后勤、空天与战场环境。

### 5.1 探测与识别

#### 5.1.1 探测与战争迷雾


每个单位对你只有四种可见状态：

| 等级 | 含义 | 能做什么 |
|---|---|---|
| **未发现** | 地图上完全看不到 | —— |
| **接触** | 知道该格有目标 | 只能作为机动参考 |
| **识别** | 知道兵种与阵营 | 面杀伤火力（火炮/火箭炮）可压制 |
| **跟踪** | 有精确诸元 | 可装订所有武器、查看耐久 |

探测由「传感器 → 目标」逐一判定，取最高等级。实际探测距离是**连乘**的结果：

```
有效距离 = 传感器基础射程
         × 高度优势（机上雷达 ×1.20；地面雷达 ×(1 + min(0.30, 海拔/6000))）
         × 目标高度层（低空 0.62 / 中空 0.85 / 高空 1.18）
         × (1 − 目标隐身 × (1 − 反隐身系数))
         × 地形遮蔽（林地 0.72 / 山地 0.65 / 城区 0.60 …）
         × 工事伪装（1 − 0.14 × 工事等级，最低 0.55）
         × 烟幕（0.35）
         × (1 − 0.85 × 干扰强度)     ← 仅雷达/电侦
         × 1.35                      ← 仅电子侦察（被动侦收距离加成）
```

然后用 `距离 / 有效距离` 的比值分级：

```
跟踪：比值 ≤ 0.35 + 0.30 × 传感器品质
识别：比值 ≤ 0.70 + 0.22 × 传感器品质
接触：比值 ≤ 1.0
```

两条补充规则：

- **近距离自动跟踪**：距离 ≤ **1.6 格**时，只要传感器能发现，就直接给「跟踪」级。否则据守工事的步兵会在贴脸距离上完全无法被直瞄火力打击。
- **雷达开机与开火都会暴露**：开火后直到下个回合结束，敌方对你的探测至少为「识别」级。

**反隐身**：VHF/超视距雷达与预警机带有 `counter_stealth` 系数，可部分抵消隐身设计。歼-20（隐身 0.82）对上空警-500 这类数字阵列雷达时，隐身只剩约 55% 的效果。

#### 5.1.2 侦察—打击链


一条完整的打击链是：

```
探测（跟踪级） → 射程内 → 通视 → 电子对抗 → 敌方拦截 → 命中判定 → 毁伤
```

任何一环断了就打不出去，面板会直接告诉你原因：

- `情报不足（需跟踪，当前识别）`
- `超出射程 4.2 格`
- `无通视条件`
- `目标未辐射（雷达关机），反辐射导弹无法锁定`
- `该武器不具备反卫星能力`
- `不能攻击己方单位`

#### 5.1.3 悬停信息卡


鼠标停在任一单位上即弹出信息卡，**无需先选中**，方便扫视战场时快速判断威胁：

**己方单位**显示：

- 兵种与作战域、血量（带颜色分级）、剩余机动点；
- 空中平台额外显示燃油百分比；
- **逐项弹药余量**（每种武器 ×N）；
- 所在格的工事等级（Lv）与驻守掩体等级；
- 雷达是否开机（开机＝暴露）、干扰机是否工作中。

**敌方单位**按识别等级给出对应深度的信息——这是战争迷雾的延伸：

| 识别等级 | 信息卡内容 |
|---|---|
| 接触 | 仅提示"不知兵种"，不显示任何参数 |
| 识别 | 显示兵种与血量 |
| 跟踪 | 追加弹药总量、防空包线半径、工事等级，并列出**己方哪些单位能直接打击它** |

> 未识别的目标不会泄露任何数据——只有被传感器看到的目标才值得担心。

#### 5.1.4 对手视角：为什么打不到


选中敌方目标后，交战面板底部会显示**「对手视角」**区块。
它不改变任何规则，纯粹是从防守方视角回答一个问题：**这一发子弹会遭遇什么？**

| 项目 | 含义 |
|---|---|
| **拦截** | 综合拦截概率（多层独立拦截取并集），并列出具体是哪个防空单元、拦截概率多少 |
| **反击** | 有几个敌方单位能打到你的发射平台，以及其中最高的单发 Pk |
| **敌方火控** | 对方是否已经「跟踪」到我方——决定开火会不会立刻招来报复 |
| **阻碍** | 具体阻碍条件（疑似诱饵、目标未辐射、情报等级不足、高速弹拦截窗口短等） |

举例：想打 S-400 保护下的目标，「拦截」一栏会直接告诉你拦截概率 43%、
拦你的正是那门 S-400；此时要么换更低的弹道、要么先用反辐射导弹打掉防空、
要么绕开它的包线——**这就是「看得见也未必打得中」的量化答案**。

> 实现：`core/combat.py` 的 `counter_threat_profile()`，纯计算，不消耗任何资源，
> 也不影响结算——真实拦截仍按 `core/adn.py` 的 `resolve_salvo_interception()`
> 逐发判定。（v3.3 起规则层按域拆成九个模块，`core/rules.py` 只做统一导出，
> 模块地图见 [SDK.md 第 10 章](SDK.md#10-核心模块地图)。）

### 5.2 火力与毁伤

#### 5.2.1 命中解算


单发命中概率 = 武器基础 Pk × 各修正因子，最后夹在 2%–97% 之间。

| 因子 | 计算 | 说明 |
|---|---|---|
| **射程包线** | 距离占包线 <75% 时不惩罚；之后线性衰减，最低 0.55 | 越接近射程边缘命中越低 |
| **电子对抗** | `max(0.25, 1 − (目标处干扰×0.55 + 发射处干扰×0.35))` | 仅对雷达/卫星制导弹药生效 |
| **导航精度** | = 己方卫星导航完整性 | 仅 `gps_ins` 制导弹药 |
| **目标规避** | `max(0.30, 1 − 规避系数×0.55)` | 战斗机规避高 |
| **己方被压制** | 0.80 | 上回合被命中的单位 |
| **战损影响** | `0.75 + 0.25 × 当前耐久比例` | 残血单位打不准 |
| **外部引导** | 0.78（无数据链时） | 见 5.8 信火一体 |

**齐射**时每发独立判定，综合命中率 = `1 − (1 − Pk)^n`。

#### 5.2.2 毁伤与兵种相克


```
减伤 = 1 − min(0.88, 装甲×0.85 + 地形掩护 + 工事×(0.10 + 兵种工事加成))
伤害 = 武器伤害 × 减伤 × 相克系数 × 随机抖动(±15%)
```

**相克不是一张固定乘数表**，而是两件事的匹配：这一发靠什么杀伤（破甲还是爆破），
这个目标又怕什么（硬还是软）。所以同一门炮打不同目标的结果是连续的，
中间没有阈值跳变。

- **破甲通道**：打得穿才算数，打穿之后迅速饱和——过穿不增加杀伤。
  没有装甲的目标（散兵、飞机）对这一通道几乎不敏感。
- **爆破通道**：覆盖到才有用，目标越软越有效。无防护人员几乎必伤，
  主战坦克只剩三成多。

典型结果（相对「一名有基本防护的步兵」的倍率）：

| 武器 | 步兵 | 步战车 | 主战坦克 | 自行火炮 |
|---|---|---|---|---|
| 25 mm 机炮 | 0.92 | 1.01 | 1.04 | 0.99 |
| 120 mm 坦克炮 | 0.87 | 1.36 | 1.37 | 1.09 |
| 反坦克导弹 | 0.89 | 1.40 | 1.40 | 1.20 |
| 155 mm 榴弹 | 1.01 | 0.84 | 0.60 | 0.96 |
| 制导火箭弹 | 1.01 | 0.83 | 0.60 | 0.96 |

读法：**坦克炮打坦克是打步兵的 1.6 倍效率，榴弹打坦克只有打步兵的六成**。
交战面板的「伤害」右侧会直接标出 `×1.37 破甲`，告诉你这一发为什么疼或不疼。

口径也参与判断：同为直瞄火炮，25 mm 机炮靠射速与榴弹杀伤人员（偏爆破），
120 mm 坦克炮靠动能穿孔（偏破甲）——用弹重连续插值，不需要为每门炮单独配表。

**地形**不再是一个独立乘数，而是并进目标画像：城区给步兵提供掩蔽
（受弹面积降到野外的四分之三），却让车辆无法疏散、顶部暴露，
反而更吃面杀伤与攻顶火力。

**空中目标**：战斗机、无人机、攻击机被**任何**弹药命中即空中解体（`one_shot_kill`）。轰炸机、预警机结构冗余，改为承受 ×2.2 伤害——通常也是一击重创。

地形掩护加成：林地 0.12 / 丘陵 0.18 / 山地 0.25 / 城区 0.30。

#### 5.2.3 齐射


交战面板可选 1–N 发齐射（N 由武器 `max_salvo`、备弹共同决定）：

- 每发独立判定，综合命中率 `1 − (1 − Pk)^n`
- 成倍消耗备弹
- 适合同一回合确保击杀关键目标（预警机、防空雷达、指挥所）

典型配置：火炮/火箭炮 3 发、空空/防空导弹 2 发、反舰导弹 2 发、反卫星弹 1 发。

#### 5.2.4 远程与特种武器


**隐身巡航导弹**（LRASM、JASSM-ER）

- 武器带 `stealth` 系数（0.75–0.80），在拦截判定中额外降低对方拦截概率：
  `Pk × (1 − 突防 × …) × (1 − 隐身 × 0.7)`
- 实测：同样是伯克级 + 密集阵，非隐身反舰弹被拦截 60%，LRASM 只有 37%

**弹道 / 洲际导弹**（东风-26、东风-41）

- `interceptable: false`：战术防空网无法拦截，只能靠机动疏散或先打掉发射车
- 东风-26：射程 13 格，可打海上机动目标，末段灌顶
- 东风-41：射程 **20 格**（覆盖全图），单发伤害 320，`strategic: true`
  —— 惯性/星光制导，**不受电子干扰影响**，只需「识别」级情报即可装订

**火箭筒**（RPG-7、98 式 120mm）

- 射程 1.0–1.2 格，只能打相邻目标
- 对工事 `anti_fort = 2`，是步兵破障与巷战的主要手段
- 对装甲目标伤害有限，但便宜、备弹多

**近防炮拦截（CIWS）**

拦截不再是单一层，而是**分层取并集**：

```
第 1 层 区域防空：单位 intercept_pk × (1−突防) × (1−干扰×0.6) × (1−隐身×0.7)
第 2 层 近防炮：  武器 Pk × (1−突防×0.55) × (1−隐身×0.6)
                  高超音速目标 ×0.10，超音速目标 ×0.55
总拦截率 = 1 − Π(1 − 各层 Pk)      最多 5 层
```

- 近防炮射程只有 1.2–1.5 格，是最后一道硬杀伤，覆盖的是**目标所在格附近**
- 因此"区域防空在外圈、近防炮在内圈"的分层配置才有效
- 高超音速导弹（匕首、鹰击-21、东风-17）近防炮拦截率降到 1/10

#### 5.2.5 设施打击


选中单位后点击敌方**机场 / 港口 / 后勤枢纽 / 雷达站 / 指挥所 / 城区**，可实施结构打击：

- 需要武器具备 `vs_facility` 能力（巡航导弹、精确制导炸弹、反舰导弹、舰炮、火箭炮等）
- 命中后降低设施结构完整度；低于 **25%** 即失能
- 设施本身不还手，但**周边防空网会拦截**（最多 3 个单位参与）
- 设施尺寸影响命中：机场 1.20、港口 1.15、城区 1.20、指挥所 0.90

### 5.3 防空与反制

#### 5.3.1 防空拦截（逐发结算）


拦截不再是"整齐射一次性判定"，而是**每一发弹药独立走一遍拦截流程**：

```
对每一发来袭弹药：
  依序尝试各拦截层（区域防空 → 近防炮）：
    区域防空：占用 1 条火控通道 + 消耗 1 枚拦截弹
              Pk = intercept_pk ×(1−突防)×(1−干扰×0.6)×(1−隐身×0.7)
              自卫时 ×0.6；空空弹点防御再 ×0.85
              弹道弹 ×0.30（末段突防，窗口很小）
    近防炮  ：消耗 1 组备弹
              Pk = 武器Pk ×(1−突防×0.55)×(1−隐身×0.6)
              超高超音速 ×0.10，超音速 ×0.55，弹道弹 ×0.05
  被拦截即消耗；未被拦截的弹药继续飞向目标
```

**关键含义**

- **饱和攻击真的有用**：4 发齐射可以把一个 PAC-3 连（6 条通道）的火控通道全部占满，
  剩下的弹药直冲目标。实测：6 发反舰弹打伯克级，会打掉 6 枚 SM-6 与 5 组密集阵备弹。
- **防空弹会打光**：区域防空消耗实弹，近防炮消耗备弹；不过现代垂发系统装填极快，
  防空单位每回合自动补充 **2 枚防空弹 + 1 组近防备弹**（不需返回基地）。
- **火控通道有限**：一个单位每回合最多交战 `interceptors` 次，通道用尽后只能靠别的单位拦截。
- **破片命中不等于打碎**（v3.1）：防空导弹是破片杀伤，近炸引信常常只是把弹体打坏。
  每次判定命中后还有 **25%** 概率只是「打残」——那发仍会扑向目标，
  但毁伤按 **45%** 折算。所以防空网再密，也挡不住「带伤落地」的漏网之鱼。
  弹道与高超音速目标不吃这条：那种速度下只有直接碰撞才算命中。
- **只有飞行弹药可被拦截**：枪炮弹、火箭筒、坦克炮不可被拦截；导弹与航弹可以。
- 交战面板会显示"拦截风险"估算值（多层并集）。

#### 5.3.2 多点防空协同


同一阵营的防空单元组成**一体化防空网（IADS）**，与 v1.0 的"各打各的"有本质区别：

- 火控通道由**网统一记账与分配**，而非每个单位各自为战；
- 网按单发拦截概率**择优派工**：多发弹药同时来袭时，不会让每个单位都对着第一发猛打；
- 节点耗尽通道或弹药后自动退出网，下一发改派其他节点。

节点分工：

| 分工 | 判定 |
|---|---|
| 区域防空 | 拦截弹射程 ≥ 7 格（S-400、爱国者、SM-6） |
| 要地防空 | 射程 3–7 格（NASAMS、红旗-17A） |
| 点防御 | 射程 < 3 格（近程防空弹） |
| 自卫拦截 | 被攻击单位自己还击（火控被占用，效率 ×0.6） |
| 末段硬杀伤 | 近防炮（CIWS）——最后一道硬杀伤 |

交战面板的「对手视角」会显示对方防空网的**分工构成与剩余通道数**，
让玩家能判断"这一发该往哪个方向绕"。

#### 5.3.3 中段反导（反弹道）


弹道导弹（伊斯坎德尔、东风-26、匕首）采用**分段飞行**：

| 阶段 | 时机 | 谁能交战 | 效果 |
|---|---|---|---|
| 上升段 | 发射瞬间（仅一次） | 部署在**发射点**附近的中段反导 | 单发 Pk = 武器 Pk × 0.55 × **0.35** |
| 中段 | 飞行途中，最多 **2 轮**窗口 | 部署在**弹道沿线**的中段反导 | 单发 Pk = 武器 Pk × 0.55，命中即摧毁整枚弹 |
| 末段 | 抵达前 | 战术防空网 | 区域防空 Pk ×0.30、近防炮 ×0.05 |
| 洲际弹（东风-41） | 全程 | 仅中段反导 | 战术防空完全无效 |

- **上升段窗口**只对部署到对方发射阵位旁边的反导系统开放——弹头还在助推，
  火控来不及稳定跟踪，命中率只有中段的**三分之一**。这是「前推部署」唯一能拿到的回报
  （拦在发射场上空的弹道，比拦在自家城市上空便宜得多）。
- **中段有多轮窗口**（v3.1）：弹头在飞，防御方可以打第二轮——第一轮的火控通道或备弹耗尽后，
  第二轮换一批发射架继续。两轮都拦不住才进入末段。日志会写明「中段第 N 轮」。
- 反导弹同样消耗备弹，打空就没有第二次机会；两个窗口意味着备弹消耗翻倍。
- 交战面板对洲际弹只显示中段拦截估算（按两轮复合概率计）。

#### 5.3.4 反卫星作战


侦察卫星是真实的可损毁资产（耐久 30、规避 0.55），每 **3 回合**过顶一次，为拥有方提供敌方全区域「识别」级情报。

具备反卫星能力的平台：

| 平台 | 拦截弹 | 射程 | Pk | 备弹 |
|---|---|---|---|---|
| 伯克级驱逐舰 | RIM-161 SM-3 Block IIA | 8.0 | 34% | 1 |
| S-400 防空营 | 77N6-N | 8.0 | 34% | 1 |
| THAAD 反导连 | THAAD 拦截弹 | 7.5 | 38% | 1 |

操作：**战役态势页 → 天基资产 → 点击敌方卫星**，装订后回车发射。

击落效果：

- 对方**过顶侦察中断**
- 对方卫星导航完整性 **−30%**，所有 GPS/惯导弹药命中率同步下降

单发命中约 24%（0.34 × (1−0.55) 附近），是一次性、决定性的赌博。

### 5.4 电子战与伪装

#### 5.4.1 电子战


干扰机开机后：

- 半径内的**敌方雷达与电子侦察**距离 × `(1 − 0.85 × 干扰强度)`
- 敌方**雷达/卫星制导弹药**命中率下降（见 5.3）
- 敌方**卫星导航完整性**每台干扰机 −28%
- 自身成为明显的辐射源，容易被反辐射导弹锁定

**反辐射导弹（ARM）只能攻击正在辐射的目标**。所以雷达兵面临真实取舍：

- 雷达开机 → 看得远，但会被 AGM-88 / Kh-31P 顺着电磁波打掉
- 雷达关机 → 安全，但失去雷达探测能力（红外/光学传感器仍可用）

AI 会在察觉反辐射威胁时主动关机（75% 概率）。

#### 5.4.2 电子战频段对抗


电子干扰按**频段**分别生效，不再是"一刀切"的单一乘数：

| 频段 | 影响对象 | 效果 | 反制手段 |
|---|---|---|---|
| **雷达** | 雷达传感器、雷达/半主动制导弹药 | 探测距离 ×(1 − 干扰×0.85) | 关闭雷达（但失去态势感知） |
| **通信** | 数据链（信火一体） | 协同交战退化为陈旧诸元，命中 ×0.45~0.70 | 主动「链 断」 |
| **导航** | 卫星导航（GPS/北斗制导） | 卫导完好度下降，精确制导弹药退化 | 改用非卫星制导弹药 |

- 干扰机只能干扰它**实际具备**的频段——因此"针对性关闭"才是有效反制：
  面对雷达干扰机就关机，面对通信干扰就断链，面对导航压制就换弹种；
- 不同频段的干扰效能可单独配置（`jam_band_weights`）；
- 武器库现有 6 个电子战单位：雷达干扰连 / 通信干扰连 / 导航压制连 / 宽带干扰站
  （新增）＋ 陆军电子战分队 / 克拉苏哈-4（原有两个，已加频段配置）；
- AI 会按目标特征选择最有价值的干扰频段：目标依赖雷达就压雷达频段，
  目标依赖数据链就压通信频段。

#### 5.4.3 电子诱饵与假目标


诱饵在**敌方态势图上生成一支「疑似某部队」的假目标**。它是真实的单位对象，
会参与探测、瞄准与 AI 判断——敌方看到的就是一支 T-90M 连。

**频段差异**：诱饵只在匹配的传感器上"像真的"，探测距离倍率如下（缺失 = 完全不可见）：

| 诱饵 | 雷达 | 电子侦察 | 红外 | 光学 | 说明 |
|---|---|---|---|---|---|
| **雷达诱饵** | 1.30 | 1.45 | — | — | 角反射器/干扰机，同时模拟辐射源，可诱骗反辐射导弹 |
| **红外诱饵** | — | — | 1.25 | 0.55 | 热源/红外诱饵，只骗热像与部分光学 |
| **目视假目标** | — | — | — | 1.20 | 充气假目标，只骗光学侦察 |
| **多光谱诱饵** | 1.10 | 1.20 | 1.10 | 0.80 | 全面但昂贵（数据预留） |

也就是说：**用热像仪看雷达诱饵，什么也看不到**；反过来，雷达看充气假目标也一片空白。
逼对方用错误的手段去侦察，本身就是一种电子战。

**海陆空差异**：诱饵形态跟随投放平台。

| 投放平台 | 诱饵形态 | 可放置范围 | 存活 |
|---|---|---|---|
| 陆上单位 | 地面假目标（伪装成坦克连/步兵连） | 4 格内陆地 | 3 回合 |
| 舰艇 / 潜艇 | 水面假目标（角反射器、拖曳诱饵） | 5 格内水域 | 4 回合 |
| 航空兵 | 空射诱饵（MALD 式） | 8 格内任意格 | 2 回合 |

其他规则：

- 攻击诱饵会浪费整次射击，日志里会写明「确认为电子诱饵」
- 诱饵无法占领目标点，也不参与后勤结算，到期自动消失
- 玩家操作：选中单位 → 「雷诱 / 红诱 / 假目标」→ 点地图指定位置
- AI 会按敌方传感器构成自动选择频段（雷达多就放雷达诱饵，热像多就放红外诱饵）

#### 5.4.4 烟幕


火炮与火箭炮可对**任意已知坐标**施放烟幕（不需要目标情报，打的是地形）：

- 持续 3 回合，覆盖目标格（火箭炮额外覆盖相邻四格）
- 该格上所有目标的**光电/热像/半主动制导与直瞄火力**命中率 ×0.55
- 该格的**探测距离 ×0.35**（红外、光学最吃亏，雷达次之）
- 不影响卫星制导、惯性制导与面压制火力

AI 会在己方目标点受到地面威胁时自动施放烟幕；玩家点击单位面板「烟幕」后点地图指定位置。

**烟幕会随风漂移**（v3.1）

战场有风：顶栏环境块右上角的箭头指向**烟会飘去的方向**，旁边数字是风力（0–3 级）。
遮蔽团每回合整体下风移动，并按风力决定快慢与消散：

| 风力 | 移动 | 寿命 |
|---|---|---|
| 0 静风 | 不移动，糊在原地 | 3 回合 |
| 1 微风 | 每 2 回合挪 1 格（按回合奇偶） | 3 回合 |
| 2 和风 | 每回合挪 1 格 | 3 回合 |
| 3 强风 | 每回合挪 1 格 | **2 回合**（额外掉一回合） |

天候会修正风力：**雨雪天 +1 级**（烟被吹散得快），**雾天压到 1 级以内**（近地面静稳，
雾天放烟几乎不挪窝，但雾本身已经削弱了光学探测，收益递减）。

实战含义：

- **顺风放烟**才遮得住自己；逆风施放，烟会飘回自己头上，还把自己的通视挡了。
- 强风下烟幕是「一次性遮蔽」：挡完这一回合就散，值不值要算。
- 雾天烟幕几乎不动，适合长时间封锁一条走廊。
- 贴边施放的烟撞到地图边界会停在原地，不会凭空消失。

掉到最后一回合的烟幕会明显变淡（地图上透明度随剩余回合递减），一眼能看出「这团快散了」。

### 5.5 指挥与后勤

#### 5.5.1 信火一体


目标由**友邻雷达、预警机或舰艇**提供跟踪诸元时，即使本平台自身没有锁定也可以发射：

- 具备**数据链**（`datalink`）的平台无惩罚 —— 这就是「A 射 B 导」
- 无数据链的老式装备（步兵、T-90M、铠甲）命中率 ×0.78
- 交战面板会显示 `信火一体：己方传感器网（协同交战）`

实战意义：把预警机放在后方，让战斗机静默接近，靠预警机提供诸元发射远程导弹——这也是对方优先猎杀预警机的原因。

#### 5.5.2 指挥体系


部队分为三个层级：

| 层级 | 单位 | 指挥能力 |
|---|---|---|
| **旅级** | 旅指挥所 | 半径 9 格，可指挥营级 |
| **营级** | 营指挥所、雷达站、电子战连 | 半径 5–6 格，可指挥连级 |
| **连级** | 绝大多数作战单位 | 无指挥能力 |

指令类型：

| 指令 | 效果 | 适用 |
|---|---|---|
| **集中火力** | 下级优先攻击指定目标（AI 目标评分 ×2.2） | 目标在火力协调半径内 |
| **固守** | 下级不再前出，只在原地附近择优机动 | 要点防守 |
| **优先目标** | 下级优先打击某类目标（防空 / 雷达 / 指挥所 / 空中） | 需要先拆掉对方防空 |

- **指令有期限**（2 回合），到期后下属恢复自主决策——指挥链既有价值，
  又不会把 AI 变成只会执行命令的傀儡；
- 指挥者阵亡 → 其全部指令立即撤销；
- 玩家操作：选中指挥单位 → 点「指挥 N」→ 点击敌方目标下达集中火力；
  固守与优先目标通过单位面板的指令按钮下达；
- AI 指挥所会自主选择高价值目标（防空阵地与雷达优先）下达集中火力。

#### 5.5.3 补给线与纵深


补给不再要求部队**站在**枢纽上，而是通过**补给线**：

```
补给有效 = 枢纽完好 且 部队在覆盖半径内 且 枢纽承载力未满
```

| 设施 | 覆盖半径 | 承载力 |
|---|---|---|
| 后勤枢纽 | 10 格 | 12 |
| 港口 | 7 格 | 8 |
| 机场 | 6 格 | 8 |
| 指挥部 | 6 格 | 6 |
| 雷达站 / 防空阵地 | 3 格 | 2 |

- **承载力**：一个枢纽同时能补给有限数量的单位。深入敌后的部队往往落在半径外，
  或者因为近处枢纽承载力已满而**分不到补给**——这就是"纵深"的真实含义。
- **枢纽被打瘫立即断粮**：打击后勤枢纽会让覆盖范围内的部队同时失去补给。

**补给的是三样实数库存，不是三个倍率**：

| 库存 | 消耗 | 补给线每回合补 |
|---|---|---|
| 弹药 | 每发实打实扣 | 1 发/回合（舰艇 2 发；返场航空兵直接挂满） |
| 油料 | 陆上 1%/格、水面 0.4%/格、水下 0.5%/格；航空兵 15%/回合 | +25% |
| 备件 | 修 1 点 HP 消耗 1 点备件 | +6 点（上限为模板 HP 的一半） |

**断粮是分档的，不是开关**：

| 断粮回合 | 状态 | 后果 |
|---|---|---|
| 0 | 充裕 | 正常 |
| 1–2 | 紧张 | **齐射上限压到 1 发**——打不出多发了 |
| ≥3 | 枯竭 | 齐射受限之外，命中率 ×0.88、防空火控通道**减半**、拦截弹不再装填 |

- 断粮当天与枯竭当天各记一条战报，之后不刷屏；恢复补给时也会记一条。
- **油料见底**（≤5%）的陆上/水面单位下回合机动点减半——还能挪，但挪不快。
- 没有备件就修不动血：战损不会凭空恢复。基地/港口能提供一批应急备件，
  但野战部队只能靠补给线。
- 航空兵是例外：油料与挂弹靠**返场**，不吃地面补给线；
  但机场被打瘫时它们无处可返。

地图上以虚线显示补给线；断粮单位标红色叉号；侧栏状态行显示
「补给正常 / 补给紧张 / 补给枯竭」。

分配算法是贪心且稳定的：孤立单位优先占位（避免被近处单位挤掉），
同一态势下每次结算得到相同结果。

#### 5.5.4 火力准备


间瞄火力（火炮 / 火箭炮）的真实打法不是"看见就打"，而是先侦察、登记射界、
等目标进入预设火力诸元覆盖区再开火。本作把它抽象为：

| 阶段 | 说明 |
|---|---|
| **登记** | 消耗 1.5 机动点，选择一个**有情报**的格子（至少"接触"级）作为射界 |
| **准备** | 1 回合后进入"已准备"状态（地图上实线圈） |
| **射击** | 对射界内目标（半径 1.5 格）获得 **命中 ×1.45、毁伤 ×1.30** |
| **失效** | 射界有效期 2 回合，过期自动消失（地图上虚线圈） |

- **必须要有情报**：完全未知的区域无法标定射界——否则"预先射击"就退化成盲打，
  违背了机制的原意；
- 射界只对**间瞄火力**有效，直瞄火力（坦克炮、防空导弹）没有射界概念；
- AI 会主动登记射界并在准备完成后用准备加成射击。

#### 5.5.5 工事、掩体与步兵


游戏里有两种"工事"，注意区分：

| 概念 | 载体 | 获取 | 失去 |
|---|---|---|---|
| **掩体** `entrench` | 单位自身 | 停留不动每回合 +1（步兵上限 Ⅱ，车辆 Ⅰ） | 一旦机动归零 |
| **野战工事** `fort` | 地块（0–3 级） | 工兵/步兵主动构筑 | 被炮火摧毁、被占领、无人维护荒废 |

**构筑工事**

- 需要单位具备 `can_fortify`（步兵、工兵），且机动点 ≥ 1.0
- 每次消耗 1.0 机动点，**投入本回合的施工工时**（不再是一拍即成的等级跳变）
- 升到 Lv1 / Lv2 / Lv3 各需 **1 / 2 / 3 工时**（累计 6 工时）
- 工兵（`fort_power = 2`）一次投 **2 工时**，三次施工就能封顶；步兵要六次
- 在敌方工事上构筑会先清零再重建（换手不继承别人的土方）
- 单位面板会显示施工进度（如「阵地 Lv1 · 施工 1/2」）

**工事的效果**

| 效果 | 数值 |
|---|---|
| 归属方减伤 | 每级 +5%（与掩体、地形掩护叠加，总减伤上限 90%） |
| 归属方隐蔽 | 每级 −7% 被探测距离（最低 0.62 倍） |
| 迟滞敌军 | 敌方陆上单位进入时每级 +0.55 机动点消耗 |
| 雷场伤害 | 敌方陆上单位穿越时每级 4 点伤害（随机 ±15%），并造成压制 |

**摧毁与修复**

- 面杀伤武器（火炮/火箭炮/航弹）自带 `anti_fort = 1`，每命中一发削 1 级
- 火箭筒（98 式）`anti_fort = 2`，专打碉堡与障碍
- 设施打击也会顺带破坏工事
- 己方工兵/步兵**驻守不动**时，每 2 回合折 **1 工时**（走的是同一条施工路径，
  不是白送等级）
- **打塌的工事会留下废墟**：在原地重建要从清障开始，Lv1 多花 1 工时
- 无人维护的工事每 3 回合荒废 1 级（荒废不产生废墟——那是自己烂掉的，不是被打塌的）
- 夺取目标点会清除该格的敌方工事

**步兵**：面杀伤对其 ≈×1.0、直瞄火力 ×0.87；城区里受弹面积只剩野外的四分之三
（机械化部队反而更吃——无法疏散、顶部暴露）。详见 5.2.2。

#### 5.5.6 同格共存


一个格子里可以同时容纳**地面部队与空中支援**——空中单位不占地面空间，
「空中支援地面」是常见战术。

**同格容量表**（按域分别计算，且必须同阵营）：

| 域 | 每格上限 | 说明 |
|---|---|---|
| 地面（land / infra） | 1 | 坦克、步兵、防空阵地、雷达站……两支地面部队仍互斥 |
| 水面（sea） | 1 | 一艘水面舰 |
| 水下（sub） | 2 | 潜艇在水面之下，可与水面舰同格 |
| 空中（air） | 4 | 机场容量；无机场时为临时起降，同样限 4 架 |

**敌方单位同格一律禁止**——否则交战目标与占点判定都会出现歧义：
格子里的敌我单位该算谁的？目标点归谁？

**战术含义**：

- 武装直升机（AH-64D）可以直接降落在地面部队的格子上协同作战；
- 空中单位的**存在不会阻挡地面单位进入**该格；
- 反过来说，一格之内混编了地面与空中单位时，**地面部队仍是该格的主体**
  ——交战目标、占点判定都以它为准（`state.unit_at` 优先返回地面单位）。

**操作**：鼠标点击该格时优先选中**己方**单位；同阵营内地面单位优先。
地图上空中单位会错位画到格子右上角，右上角的「×N」标注的是**同格几架飞机**。

### 5.6 空天与战场环境

#### 5.6.1 航空兵任务剖面


航空兵可在「打击 / 制空巡逻 / 转场」三种剖面间切换（单位面板「剖面」按钮）：

| 剖面 | 效果 |
|---|---|
| **打击**（默认） | 均衡；返场后自动恢复 |
| **制空巡逻** | 雷达探测距离 ×1.15、空空弹命中 ×1.15，但油耗 ×1.3 |
| **转场** | 油耗 ×0.5、机动点 +25%，但**武器保险关闭，无法射击** |

AI 会自动选择：返场途中转场、空优挂载且无交火时巡逻、其余保持打击。

#### 5.6.2 航空兵、基地与后勤


- 航空兵每回合消耗 **15% 燃油**；停在己方完好机场（或航母）上时补满燃油与全部备弹，并每回合修复 12% 战损。
- 燃油耗尽 → **坠毁**（计入战损）。所以出击前要算好返航油量。
- 一个机场停机坪可容纳 **4 架**飞机；机场结构完整度低于 25% 即**失能**，无法再保障出击。
- 地面部队停在后勤枢纽/机场/指挥部时：每回合每种武器 +1 发，修复 7% 战损。
- 舰艇停在己方港口时：每回合每种武器 +2 发。
- 设施在 **2 格内无敌情**时，每回合自动抢修 6%——压制机场必须持续打击。

#### 5.6.3 卫星轨道与过顶窗口


侦察卫星不再是"每 3 回合全图揭示"，而是沿地面轨迹运行：

- 轨道：每回合向东 5 格、向南 3 格，飞出图外后从另一侧再入
- **只有星下点进入战区时才有过顶窗口**，此时提供半径 14 格的区域侦察
- 星下点 7 格内的目标可直接**跟踪级**（可直接锁定打击），其余为识别级
- 「战役态势」页显示每颗卫星"过顶中 / 轨道外"
- 被击落后该侧彻底失去过顶侦察，卫星导航完整性 −30%

这意味着：**卫星不再是全知全能的侦察网**，关键时刻要靠预警机与雷达。

#### 5.6.4 战场天气与时段


战场环境由**时段**与**天候**两个维度构成，直接改变探测矩阵。

**时段**：拂晓 / 白天 / 黄昏 / 夜间。按作战日循环——默认 **6 回合 = 1 个昼夜**
（想定可用 `day_length` 字段调整），因此一个 16–18 回合的想定可覆盖约 3 个昼夜，
夜间机制不会被压缩成"最后一回合"。

**天候**：晴 / 雨 / 雾 / 雪。按想定种子做**确定性伪随机序列**——同一想定每局的天候
完全一致，读档也能精确复现，不会成为"重开一局换个天气重试"的可利用随机源。

探测距离系数：

| 环境 | 光学 | 红外 | 雷达 |
|---|---|---|---|
| 白天·晴 | 1.00 | 0.92 | 1.00 |
| 拂晓·晴 | 0.70 | 1.05 | 1.00 |
| 黄昏·晴 | 0.62 | 1.12 | 0.98 |
| 夜间·晴 | **0.28** | **1.32** | 0.94 |
| 白天·雨 | 0.82 | 0.87 | 0.84 |
| 白天·雾 | 0.42 | 0.83 | **0.62** |
| 白天·雪 | 0.68 | 0.79 | 0.78 |

**战术含义**：

- 夜间光学几乎失效，**红外（热像）是夜战主力**——热像仪短程但夜间能获得
  ×1.32 的加成，配合"贴脸即可跟踪"规则，夜间是地面部队的战场；
- 雨雾对雷达的打击最重（雾天 ×0.62），此时电子侦察（ESM）与天基侦察的价值凸显——
  被动与天基手段**完全不受天候影响**；
- 地图会用色调与天气颗粒表达当前环境：夜间压暗偏蓝、雾天加白纱、雨雪加动态颗粒。

AI 会同步适应：雨雾或夜间主动开机雷达补充态势，晴朗白天反而关机降低暴露。

**风**（v3.1）：与天候同一套种子、但走**另一条哈希流**，所以调天候参数不会连带
改掉全部风向（想定作者改的是什么，就该只影响什么）。共 8 方位、0–3 级风力：

- 晴/雨/雪直接影响风力：**雨雪 +1 级**，**雾天压到 1 级以内**；
- 顶栏环境块右上角的箭头指向**烟幕会飘去的方向**，数字是风力；
- 战报里写的是「西北风 2 级」这种完整说法（方位按**来向**命名，
  烟往反方向飘——北风把烟往南吹）。

想定可指定天候模式：

```jsonc
"weather": "random",     // random（默认）/ cycle / clear / rain / fog / snow
"weather_seed": "abc",   // 可选：指定种子
"day_length": 6          // 可选：几回合 = 1 个昼夜
```

#### 5.6.5 目标点与胜负


- 目标点由**具备占领能力**的单位（步兵、坦克、步战车、舰艇）站上去即夺取。
- 每回合结束时按当前归属结算胜负点：`该点价值 × 1`。
- 回合上限到达后比胜负点；一方单位被全歼则立即判负。
- 目标点一旦夺取会保持归属，除非被敌方重新夺占——但**没有部队驻守的点很容易被反夺**。
- 夺取目标点的同时会清除该格的敌方工事。

## 6. 想定与扩展

想定是**关卡**，扩展是**规则与素材的来源**。本章讲怎么写想定、
怎么让想定自己动起来、以及社区能往里加什么。

#### 6.1 想定脚本事件


想定 JSON 的 `events` 字段可按回合触发剧本——**改 JSON 即可，无需改代码**：

```json
"events": [
  {"turn": 3, "type": "weather", "weather": "fog",
   "message": "海上起雾，能见度骤降"},
  {"turn": 5, "type": "reinforce", "side": "RED", "unit": "bmp3",
   "x": 15, "y": 10, "count": 1, "message": "红方增援一个 BMP-3 连"},
  {"turn": 8, "type": "airstrike", "side": "BLUE", "x": 20, "y": 12,
   "weapon": "atgm", "damage": 40, "message": "我方空袭"}
]
```

| 事件类型 | 必填字段 | 作用 |
|---|---|---|
| `weather` | `weather` | 改变天候：clear / rain / fog / snow |
| `reinforce` | `side` `unit` `x` `y` | 在指定坐标生成增援部队（`count` 决定数量） |
| `airstrike` | `side` `x` `y` | 对指定坐标实施空袭（`weapon` / `damage` 可选） |
| `objective` | `x` `y` `side` | 改变目标点归属 |

- 事件在**对应回合开始时**结算，出现在作战日志里；
- 未触发的事件不影响流程；`repeat: true` 可让事件每回合重复触发；
- 事件类型写错时 `--check` 会报错并指出位置。

#### 6.2 想定元数据


```json
"meta": {
  "author": "hamfreebird",
  "summary": "红方装甲集群沿河谷突贯，蓝方以远程火力迟滞进攻",
  "difficulty": "normal",
  "tags": ["陆战", "防空", "纵深"],
  "recommended_units": ["hq_battalion", "m1a2", "himars"],
  "recommended_side": "BLUE"
}
```

- 主菜单卡片展示作者、难度、标签与推荐兵力，便于浏览社区想定；
- 难度四档：`easy` 入门 / `normal` 标准 / `hard` 困难 / `expert` 专家；
- `recommended_units` 列出建议使用的兵种 ID，`recommended_side` 指定推荐阵营。

#### 6.3 战役模式


多张想定可串联成**战役**：每关胜利后继承幸存部队、累计胜负点，逐关推进。

- 战役定义在 `data/campaigns/*.json`；
- **跨关继承**：通关后幸存部队（按兵种统计）会带入下一关，作为增援部署；
- **胜负点累计**：每关的胜负点累加到战役总分，最终以总分判定战役胜负；
- **进度存档**：战役进度写入用户目录，可随时续玩；
- 结算界面会显示战役进度，并提供「进入下一关」。

#### 6.4 想定深度校验


`python main.py --check` 现在会做深度校验，**报错定位到具体坐标**：

| 检查项 | 级别 | 说明 |
|---|---|---|
| 地形连通性 | 提示 | 目标点是否可从部署位抵达 |
| 目标点可达性 | 提示 | 陆上单位无法占领海域目标点 |
| **目标点火力覆盖** | **报错** | **双方都没有能打击该域的武器——这个点谁也打不到** |
| 目标点距离 | 信息 | 初始部署够不着，但有能力打——提醒作者「需要机动接近」 |
| **制高点分布** | **提示** | 一方掌握超过七成制高点时点名（只统计陆上单位） |
| **防空覆盖** | **提示 / 信息** | 一方完全没有防空，或防空伞没盖住任何目标点 |
| **开局间距** | **提示 / 信息** | 双方最近单位 <2 格（先手优势被放大）或 >地图跨度 3/4（接敌太慢） |
| 兵力配比 | 信息 | 双方造价是否悬殊 |
| 同格冲突 | 报错 | 多个单位挤在同一格 |
| 陆上单位入海 | 报错 | 非两栖单位部署在海域 |
| 航空兵无基地 | 提示 | 无法返场加油，会在空中耗尽燃油 |
| 事件合法性 | 报错 | 事件类型非法或字段缺失 |
| 元数据完整性 | 提示 | 难度标签非法等 |

**「够不着」与「不会打」是两回事**：校验器区分这两种情况——
初始部署时双方射程都不够，只会给一条「需要机动接近」的信息；
只有当**双方都没有能打击该域（陆上 / 海上）的武器**时，才判定为
「这个点谁也打不到」的硬错误。这样大地图想定不会因为部队还在集结就被判失败。

**制高点只统计陆上单位**：两栖登陆的一方开局可能全在海上，
把它们算进来会得出「制高点 100% 归防守方」这种没有意义的结论。

#### 6.5 大型战役想定「海峡对决」


128×128 的大战役想定：架空中美战争，双方在东亚大陆架海峡爆发全面战争。

| 项 | 内容 |
|---|---|
| 尺寸 | 128×128 格，每格 20 km（战场纵深 2560 km） |
| 回合上限 | 20 回合 |
| 地形 | 九种齐全——海域 6417、滩涂 1910、林地 2324、丘陵 1577、平原 1616、山地 1524、城市 370、沼泽 520、荒漠 126 |
| 设施 | 25 处（机场 / 港口 / 雷达站 / 防空阵地），分属双方与中立岛屿 |
| 目标点 | 13 处：岛链要点价值高（9–12 VP），两岸门户 11 VP，本土要点 6–7 VP |
| 工事 | 28 处预设工事 |
| 蓝方（美） | 46 个单位 / **29 种兵种** |
| 红方（中） | 57 个单位 / **32 种兵种** |

**地图结构**（自西向东）：

```
x 0–28    西太平洋开阔海域 —— 蓝方航母编队与远程打击前进基地
x 12–88   岛链基地群 —— 蓝方在西太平洋的落脚点（岛屿上有机场与港口）
x 30–72   中央海峡 —— 双方必争的喇叭口，中段散布岛链屏障
x 74–127  东侧大陆 —— 红方纵深：城市带、山地防线、沿海机场群、内陆导弹基地
```

**胜机在哪**：岛链。谁控制岛链谁掌握制海权——中央岛锚地（12 VP）
与西岸门户（11 VP）是全场价值最高的两点，也是红方岸线防御的重心所在。
红方凭地利与本土纵深天然占优，进攻方需要在 20 回合内撕开口子。

> 该想定由 `tools/make_big_map.py` 程序化生成：值噪声地形 + 岛链 + 城市群落，
> 设施与部署坐标会自动吸附到合法地形。重跑脚本即可复现整张地图。

#### 6.6 对局回放


一局打完，可以把它**完整重演**一遍——不是录像，而是**重新算一遍**。

**原理**：回放 = 想定 + 对局种子 + 命令流。

| 要素 | 作用 |
|---|---|
| **想定** | 战场地形、双方编成、目标点 |
| **对局种子** | 所有随机判定（命中、拦截、伤害浮动、AI 决策）都由它派生 |
| **命令流** | 玩家的每一步操作，记成语义化命令（「3 号单位移到 (10,20)」） |

同一种子 + 同一串命令 = 逐项一致的结果。命令记的是**语义**而不是鼠标坐标，
所以回放不依赖窗口大小、分辨率或任何界面细节。

**怎么用**：

* **导出**：对局中按 `F10` → 系统菜单 →「导出回放」，生成 `.bwrep` 文件
  （放在用户数据目录的 `replays/`）；
* **播放**：主菜单 →「导入回放」→ 选一个文件。

播放时底部有控制条：进度、当前正在执行的操作、播放状态与倍速。
`空格` 暂停 / 继续，`←→` 调速，`End` 快进到结尾，`Esc` 退出。

**回放文件的结构**（纯 JSON，可直接分享）：

```json
{
  "version": 2,
  "kind": "match",
  "scenario": "strait_shield.json",
  "scenario_sha256": "6f1c…",
  "game_version": "3.2.0",
  "seed": 20261102,
  "player_side": "BLUE",
  "note": "",
  "commands": [
    {"kind": "move", "args": {"uid": 3, "x": 10, "y": 20}, "turn": 1},
    {"kind": "fire", "args": {"attacker": 3, "target": 17,
                     "weapon": "gmmlrs", "salvo": 2}, "turn": 1},
    {"kind": "end_turn", "args": {}, "turn": 1}
  ],
  "scenario_data": {"id": "strait_shield", "…": "…"}
}
```

四个 v3.2 新增字段，都是为了**换一台机器也能打开**：

| 字段 | 作用 |
|---|---|
| `kind` | `match`（玩家对局）或 `ai_vs_ai`（观战，只有种子没有命令流） |
| `game_version` | 制作该回放的程序版本，播放时据此提示兼容性 |
| `scenario_sha256` | 想定内容指纹（按规范化 JSON 计算，与键序无关） |
| `scenario_data` | **内嵌的整份想定**——对方没有这张图也能重演 |

播放时的处理顺序是「本地有且内容一致 → 用本地的；本地没有 → 落到用户目录；
同名但内容不同 → 另存为 `名字.指纹前8位.json` 并提示」。
第三种是最容易出问题的场景：两人各自改过同一张图，谁的都不能悄悄覆盖谁的。

> **教学提示不参与回放比对**——回放不跑教学系统，那类日志本就不该出现在回放里。

#### 6.7 AI 对战观战


不想动手，只想看两边 AI 怎么打？主菜单的「**AI 观战**」（或按 `V`）就是干这个的。

**它是什么**：蓝红双方都由 AI 指挥，整局自动推演，你以观察者身份实时观看。
底层复用的就是 v3.0 命令行 `--sim` 的那套双 AI 推演——所以**观战看到的就是
模拟器算的东西**，不是另做一套演示逻辑。

**控制条**（底栏，只覆盖地图区域，不压顶栏和侧栏）：

| 按键 | 作用 |
|---|---|
| `空格` | 暂停 / 继续 |
| `←` `→` | 降速 / 加速（0.5× · 1× · 2× · 4× · 8×，记住上次选择） |
| `N` | 跳到下一回合（把当前回合剩下的动作快进完） |
| `F` | 镜头跟随开 / 关（跟随正在行动的单位） |
| `S` | 把这一局存成观战回放（`.bwrep`，`kind = ai_vs_ai`） |
| `Esc` | 退出观战、回主菜单 |

控制条上同时显示回合数、已演动作数、双方胜负点与进度条。

**两个设计要点**（这也是它可信的前提）：

1. **观战只改「你能看到什么」，不改规则。** 观察者视角下全图单位都显示为
   「已跟踪」，方便你看清态势；但 AI 的决策与射击判定用的仍是它自己的
   **识别状态**——你看得见锅里，不等于锅里的人也看得见你。
2. **同想定 + 同种子 = 同一局。** 观战回放因此**只存种子不存动作**：
   一局几万个动作没必要记，重算一遍就是逐项一致的结果
   （实测同种子重跑三次，动作数逐项一致）。

**每局种子是新取的**，所以每次看到的都不一样；
想复现某一局，按 `S` 存成回放，再从主菜单打开即可。

#### 6.8 分享与版本兼容


想定包与回放都能发给别人，因此都带**版本号**与**完整性校验**。

**想定包（`.bwscn`）v2 的清单**：

```jsonc
{
  "format": 2,
  "name": "海峡 2027",
  "author": "someone",
  "difficulty": "hard",
  "tags": ["现代", "海空"],
  "game_version": "3.2.0",
  "maps": ["strait_2027.json"],
  "files": [
    {"name": "maps/strait_2027.json", "sha256": "6f1c…", "role": "map"}
  ]
}
```

`files` 里逐个登记包内文件的 sha256，导入前逐个核对——
**改坏一个字节都会被指出来**，而不是等你打到一半才发现地形不对。

**版本判定的三条结论**（`core.version.compat_note`）：

| 情况 | 提示 |
|---|---|
| 同版本 | 无提示 |
| 文件由**更新**版本制作 | 「该文件由更新的版本 vX.Y.Z 制作（当前 vA.B.C），内容可能无法完整读取」 |
| 文件由**更早**版本制作 | 「…已按向后兼容方式读取」 |

「更新」和「更旧」是两种完全不同的风险，不能都糊成一句「版本不符」——
前者要你更新程序，后者只是提示，**读还是能读的**。

**两条硬规矩**：

1. **读旧文件必须成功**——v2 之前的包和回放（没有 `files`、没有
   `scenario_data`）照样能导入、能播放，只是少了校验和内嵌想定；
2. **读新文件必须报错**——格式版本高于程序支持的，明确拒绝：
   「想定包格式版本 3 高于当前程序支持的 2，请更新游戏后再导入」。
   悄悄按老格式硬解，只会得到难以排查的错乱数据。

**导入是先校验后落盘**：整包读进内存 → 逐个核对 sha256 → 检查地图能否解析
（有 `size`、有 `deployments`）→ 全部通过才写进用户目录。
坏包在中途就被挡住，不会留下半份装好的想定。

> 内容指纹按**规范化 JSON**（键排序 + 紧凑分隔符）计算——编辑器另存一次
> 只是键序变了，不该被判成「内容不同」。

#### 6.9 模组接口


第三方 Python 模块可以往游戏里加**新武器、新兵种**，并订阅**规则钩子**。

模组放在**用户数据目录的 `mods/`** 下（每个 `.py` 即一个模组），
安装目录的 `data/mods/` 里的模组也会自动加载。

一个模组只需导出 `register(api)`：

```python
def register(api):
    api.add_weapon({
        "id": "orbital_laser",
        "name": "机载激光吊舱",
        "kind": "atgm",
        "range_min": 0.3, "range_max": 3.2,
        "pk": 0.72, "damage": 140, "ammo": 4,
        "guidance": "optical",
        "targets": ["land", "infra", "sea"],
        "speed": 12.0, "max_salvo": 2,
    })
    api.add_unit({
        "id": "concept_laser",
        "name": "概念激光攻击机",
        "class": "uav", "domain": "air",
        "hp": 40, "mp": 7.0, "armor": 0.0,
        "stealth": 0.45, "evasion": 0.12,
        "max_altitude": "low",
        "sensors": ["optical_uav"],
        "weapons": [{"ref": "orbital_laser", "ammo": 6}],
        "cost": 340, "echelon": "squadron",
    })
    api.on("modify_damage", boost_laser)
    api.log("已注册机载激光吊舱")


def boost_laser(state, attacker, target, weapon, damage):
    """返回新的伤害值；返回 None 表示不修改。"""
    if weapon.id != "orbital_laser":
        return None
    return float(damage) * 1.35
```

**可用钩子**：

| 钩子 | 签名 | 用途 |
|---|---|---|
| `before_fire` | `(state, attacker, target, weapon)` | 开火前改状态（装填、撤出等） |
| `after_fire` | `(state, attacker, target, weapon, result)` | 开火后处理结果 |
| `modify_damage` | `(state, attacker, target, weapon, damage)` | 修正伤害（返回新值或 `None`） |
| `turn_start` | `(state, turn)` | 每回合开始时的全局调整 |
| `unit_destroyed` | `(state, unit)` | 单位被摧毁时 |

**错误隔离**：单个模组抛异常只会记录一条错误，不影响游戏启动或其它模组——
社区模组的质量参差不齐，不能让一个坏插件毁掉整局。

**完整示例**见 `examples/mods/example_orbital.py`（复制到用户 `mods/` 目录即可试用）。

> 这是 v3.0「官方模组 SDK」的**原型**：先把注册机制跑通，
> v3.0 再把它固化成有版本号、有文档、有兼容承诺的稳定 API。

#### 6.10 规则钩子系统


想定作者可以用 **JSON 声明规则**，不必写 Python。
一条规则 = **触发器（when）** + **效果（then）**：

```jsonc
"rules": [
  {
    "id": "reinforce_on_loss",
    "name": "伤亡补充",
    "when": {"type": "side_lost_min", "side": "BLUE", "count": 3},
    "then": [
      {"type": "reinforce", "side": "BLUE", "template": "m1a2",
       "x": 12, "y": 44, "count": 1},
      {"type": "message", "text": "预备队填补缺口"}
    ]
  }
]
```

**条件**（12 种）：

| 类型 | 参数 | 含义 |
|---|---|---|
| `always` | — | 恒真 |
| `turn_at_least` / `turn_at_most` / `turn_is` | `turn` | 回合数 |
| `side_controls_min` | `side`, `count` | 某方控制的目标点数 |
| `side_lost_min` | `side`, `count` | 某方损失的单位数 |
| `unit_near_objective` / `enemy_near_objective` | `side`, `template`, `radius` | 某方/敌方有单位在目标点附近 |
| `weather_is` / `time_of_day_is` | `text` | 天候或时段 |
| `victory_points_lead` | `side`, `value` | 某方领先多少胜负点 |
| `all` / `any` / `not` | `conditions` | 组合 |

**效果**（9 种）：`message` `reinforce` `airstrike` `damage` `heal`
`weather` `reveal` `objective` `set_flag`。

**求值时机**：回合结算时统一求值，**放在想定事件之后**——
规则因此能观察到本回合事件的结果（例如「事件增援的部队被击毁后触发补充」）。

**容错**：单条规则出错不影响其它规则，失败会有明确播报。
求值顺序固定，因此**可复现**——同种子重跑结论一致。

> 规则与事件分工明确：**事件是剧本**（第 5 回合对某处空袭），
> **规则是条件**（每当某单位阵亡时，在此处增援）。

#### 6.11 单位图标包


兵种图标从「写死的矢量图形」变成**可替换的资源包**。

**目录结构**：

```
icon_packs/
  my_pack/
    pack.json          清单
    mbt.png            各兵种的图标
    fighter.png
```

**清单格式**：

```jsonc
{
  "id": "my_pack",
  "name": "我的图标包",
  "author": "someone",
  "version": 1,
  "icons": {"mbt": "mbt.png", "fighter": "fighter.png"}
}
```

`icons` 的键是 `UnitClass` 的取值（`mbt` / `fighter` / `sam` / `uav` …）。

**三条约定**：

1. **图标用白色画**——运行时按阵营着色，所以**一套素材能同时用于红蓝双方**，
   换肤也不用重新导出；
2. **不必覆盖全部兵种**——缺失的兵种自动回退到内置矢量图形，
   所以做一个 8 个兵种的包完全没问题；
3. **用户目录优先**——放在用户数据目录的 `icon_packs/` 下即可生效，
   不需要改动安装目录（和语言包的处理方式一致）。

**内置包**：`data/icon_packs/default/` 是把内置矢量图形烘焙成的 PNG，
覆盖全部 25 个兵种，可作为自制包的模板。重新生成：

```bash
python tools/make_icon_pack.py
```

在**设置面板 → 单位图标包**里切换。损坏的包会被跳过，不会影响游戏启动。

#### 6.12 AI 战术库与可达性判断


AI 的目标分配不再只看直线距离，而是看**实际路径成本**——
隔着海的两点直线很近，绕行却可能要走几百格。

配套三条基础机制：

- **保底移动**：单位不该因为部署位置不佳就永远动不了。
  完全无法移动时允许以刚好用尽移动点的代价挤出去。
- **斩首打击**：优先打「打掉之后能让我们多拿分」的目标
  （敌方据点的守卫、能压制我方的防空）。
- **撤退判断**：重伤且孤立时脱离接触——活着回去比拼掉更有价值。

**实测**：128×128 大型想定里，蓝方 AI 20 回合拿下的中立点从 **0 个**变成
**3 个**（含跨海投送拿下胜利点最高的「中央岛锚地」）。

#### 6.13 AI 的五种战术动作

v2.2 的战术库解决「往哪走、打谁」，v3.1 补的是**什么时候改主意、什么时候认输、
几支部队怎么配合**。这五种动作全部走 `AIPlanner(deep=True)`；传 `deep=False`
退回 v2.2 行为，用于 A/B 对照。

**一、目标转移（改派）**

每回合第一次为某支部队规划时，重新评估一次所有目标点：

| 情形 | 动作 |
|---|---|
| 目标点已被己方拿下且守军够 | 摘下来，去更有价值的地方 |
| 目标点已丢失、变得不可达 | 强制改派（否则原地发呆） |
| 别处的得分超过当前 **1.45 倍** | 改派 |
| 己方目标点正被敌军逼近 | **紧急回防**，不受改派冷却限制 |

1.45 倍是迟滞阈值——没有它，AI 会在两个价值接近的点之间来回摇摆，
六个回合改五次主意，一次也没走到。冷却设为 1 回合（每回合复核一次）：
早先设成 3 反而更差，部队三个回合不回话，战场的形状早就变了。

**二、分档撤退**

旧版只有一条「血量 < 28% 且孤立」的硬阈值，把「弹药打光」和「被包围」
混为一谈。现在按五档判据给出结论与去向：

| 档位 | 判据 | 动作 |
|---|---|---|
| 死守 | 目标点需要守军、撤退会丢点 | 不撤 |
| 死战 | 弹药充足、附近有友军、尚能一战 | 不撤 |
| 后撤 | 重伤但仍有火力 | 退到最近补给点方向 |
| 脱离 | 弹药见底且已受伤 | 全速离开接触 |
| 投降式撤退 | 被合围且无法脱身 | 原地固守（撤也是死） |

撤退目的地不是「离敌人最远的地方」，而是**补给点方向**——
退到荒野里苟活的部队，三个回合后还是要死。

**三、集火**

AI 现在有一本**预期毁伤台账**：每决定打一发，就把「这一发预期能造成多少伤害」
记在目标名下。后续单位评估目标时：

- 台账显示**差一口气就能打死** → 接力加成（最高 3.5 倍评分），
  让第二支部队补上最后一击，而不是各打各的
- 台账显示**已经打够了** → 显著降权，避免六支部队把一个目标打成筛子
  而旁边两个目标无人问津

这条同时解决了「不过杀」与「不漏杀」两个相反方向的浪费。

**四、交叉火力**

直瞄武器从**不同方位扇区**压制同一地面目标时，毁伤提升：

| 已占方位扇区 | 加成 |
|---|---|
| 1–2 档 | 无（两条枪打一面不算交叉） |
| 3 档 | ×1.06 |
| 4 档 | ×1.12 |
| 5 档及以上 | ×1.18（封顶） |

方位按 8 个 45° 扇区统计，工事 / 掩体内的目标加成提高一档——
据守在工事里的部队最怕的就是被从两个方向同时打。

只有直瞄武器（坦克炮、反坦克导弹、机炮、舰炮）参与；
火箭炮和身管火炮是间瞄，没有「方位」概念。空中目标不吃这一条——
飞机不会因为地面上有两支枪从不同方向指它就掉得更快。

**五、佯攻**

派一支部队去打次要方向，把守军从主攻方向引开。这是**真部队、真机动、
真能占点**——不是电子诱饵。

关键在于**它只在没别的事可做时才发生**：早先把它放在争点之前，
结果是「把一支本来要去主攻方向的部队抽去做姿态」，40×40 想定实测净亏 10 个
胜负点。现在佯攻是「闲兵的差事」——反正它原本会原地发呆，去敌人必救的方向
晃一圈，只会比站着不动好。

触发门槛：主攻方向确实存在、至少 4 支可占领部队、可占领部队数量比待争目标点
多出 2 支、佯攻点距主攻点 ≥ 6 格且 ≤ 18 格、目标点有敌人「看得见」。
佯攻部队选**最便宜、机动最好、血还满**的那支——就算亏了也不心疼。

**A/B 实测**（`deep=True` 对同一个 `deep=False` 的对手，12 回合）：

| 想定 | 种子 | 深战术 | 浅战术 |
|---|---|---|---|
| 海峡屏障 40×40 | 7 / 11 | −54 | −54 |
| 草原雷霆 44×44 | 3 / 7 | −12 | −36 |

海峡屏障打平（该想定的胜负主要由海上兵力决定，地面战术腾挪空间小），
草原雷霆净胜 24 个胜负点。性能无退化：128×128 上深浅两档都是 3.3–3.7 秒/回合。

引导条固定显示在地图上方，标题 + 说明 + 当前目标，随时可「跳过教学」：

| 步骤 | 目标 | 教什么 |
|---|---|---|
| 1. 认识战场 | 点击任意己方单位 | 右侧单位详情页怎么读 |
| 2. 发现与识别 | 悬停查看敌方目标 | 问号代表什么；传感器越近识别越高 |
| 3. 跟踪与开火 | 跟踪目标并开火 | 没有跟踪就打不着；射程与情报的关系 |
| 4. 看清对面 | 查看一次对手视角 | 拦截、反击、敌方火控三项情报 |
| 5. 构筑工事 | 让步兵构筑工事 | 驻守挖壕收益高，但机动即失效 |
| **6. 空中力量** | **把空中单位往前机动** | **天：空中单位可越过己方阵地前出侦察，且能与地面部队同格** |
| **7. 任务剖面** | **切换一次任务剖面** | **打击 / 制空巡逻 / 转场的取舍** |
| **8. 电子战压制** | **打开干扰机** | **电磁：雷达与通信双频段干扰，切断敌方协同** |
| **9. 诱饵欺骗** | **投放一个诱饵** | **电子战分队的 2 个诱饵，把敌方火力引开** |
| **10. 烟幕遮蔽** | **施放一次烟幕** | **间瞄火力对已知坐标遮蔽 3 回合** |
| **11. 预先射击** | **登记一个射界** | **信火一体：提前标定，准备完成后命中与毁伤显著提高** |
| 12. 结束回合 | 结束第一个回合 | 日志记录了什么；下一回合从哪来 |

#### 7.3 引导是怎么判定的


引导机（`core/tutorial.py`）是**事件驱动**的：主程序在关键动作发生时投递事件，
引导机据此推进。每一步可以声明两类条件：

- **触发事件**：`select_unit` / `hover_enemy` / `fire` / `counter_viewed` /
  `fortify` / `air_move` / `profile` / `jam` / `decoy` / `smoke` / `prepare` /
  `order` / `radar` / `datalink` / `turn_end`；
- **状态条件**：例如第 3 步要求「已开火」**且**「当前存在被跟踪的目标」，
  两者同时成立才算完成——只开火而没跟踪不会误判为过关。

> **教学不会把玩家卡住**：引导机额外记住**所有发生过的事件**。
> 如果你提前做了后面才教的动作（比如第 1 步就把无人机推了出去），
> 走到那一步时会直接跳过，而不是永远等不到那个事件。

#### 7.4 给社区想定配引导


想定 JSON 里加 `tutorial` 字段即可（教学想定本身就是这么写的）：

```jsonc
"tutorial": {
  "steps": [
    {
      "id": "my_step",
      "title": "第 1 步 · 标题",
      "body": "详细说明文字",
      "goal": "一句话目标",
      "trigger": "fire",        // 触发事件名
      "focus": "map"            // 高亮区域：map / sidebar / topbar / log
    }
  ]
}
```

未写 `tutorial` 的想定不会显示引导条。

早期版本把按钮写成 `(18, 26, 36)` 这样的深色常量，切到亮色主题后
这些按钮在浅色背景上变成突兀的黑块（主菜单的「编辑想定」「快速上手」

派生规则：底色始终是「面板色向强调色靠一点」，因此深色主题下按钮
略亮于面板，浅色主题下略深于面板——两套主题下都能看出边界，

浅色 0.10/0.20），免得浅底被染得太艳。

> **给模组作者**：写界面时**不要硬编码颜色**。用 `T.PANEL` / `T.TEXT`
> 等主题色，或 `T.button_fill(accent, hover)` 派生——

#### 9.5 本地化框架


界面文案抽离到语言文件，设置面板 → 界面语言 可在 **8 种语言间即时切换**
（简体中文 / English / 日本語 / 한국어 / Deutsch / Français / Español / Русский）。

- 语言包位于 `data/lang/<代码>.json`；界面文案单独放在
  `data/lang/<代码>_ui.json` **分层包**里，加载时合并进同一种语言——
  改 UI 译文不会覆盖基础词条；**用户数据目录的 `lang/` 优先级更高**，

  → 中文磁盘包 → 键名，**绝不会显示空白或裸内部标识**；查表时会自行装载

- 想定 JSON 里的中文描述属于**想定内容**而非界面文案，不随语言切换——

- 贡献者用 `python tools/lang_check.py` 检查覆盖率、占位符一致性与译文残留，
  `--new <代码>` 生成新语言模板，`--verify <代码>` 校验现有语言包。

#### 9.6 性能优化：分块渲染与增量探测


v2.1 对渲染与探测两条链路做了重构。**加速不得改变规则结论**——
这是整个改动的第一原则，因此每一项优化都配有对应的回归断言。

**分块渲染**：地形原先是整图预渲染成一张大 Surface。256×256 放大到
tile=60 时需要一张 15360×15360 的表面（约 900MB）——不可行。现在改为
16×16 格一块、按需构建、按**字节预算**（64MB）LRU 淘汰，
内存从 O(全图) 降到 O(视口)。

**渲染批处理**：单位棋子底板、矢量兵种图标、天气图案与昼夜色调
全部烘焙成位图缓存；目标点 / 工事 / 设施改用**增量索引**
（靠 `state.map_epoch` 判断是否过期），不再每帧全图扫描。

**增量探测**：探测解算叠了三层加速——

- **空间网格索引**：观测者按格归档，目标只查邻格，而不是遍历全部单位；
- **通视缓存**：地形海拔一局不变，通视结果可以缓存；
- **干扰场缓存**：干扰机态势不变时，整张干扰场只算一次；
- **世代号增量缓存**：每个单位带一个状态指纹，状态一变世代号就变，
  缓存键随之改变，旧结论自动作废。

最后一点尤其重要：**不需要在引擎各处挂失效钩子**。移动、开火、
开关雷达、被压制、工事建成……无论从哪条路径改的状态，都会被指纹捕获。
漏挂一个钩子就会给出**错误的探测结论**——那比慢更糟。

**索引失效不再靠约定**（v3.3.1）：位置索引与地块索引原先要求「改完记得调
`invalidate_pos_index()` / `map_epoch += 1`」。现在 `Unit` 在坐标或存活状态被
写入时、`Tile` 在目标点 / 工事 / 设施的归属与存在被写入时，会递增模块级版本号
（`model.pos_epoch()` / `tile_epoch()`）；索引访问时比对版本号，不一致自己重建。
漏调一次会让战术结论错掉，而且很难复现——所以这条不能靠记性。

代价在克隆：`Tile(**vars(t))` 每个字段都过一次 `__setattr__`，256×256 是
120 万次调用，载入会从 0.23s 涨到 0.52s。所以复制地块改走 `model.clone_tile`
（直接搬 `__dict__`，不触发版本号），克隆本来也不该让任何索引失效。

**实测收益**（128×128 大型想定，103 个单位）：

| 指标 | v2.0 | v2.1 | 提升 |
|---|---|---|---|
| 整帧渲染 | 9.0 ms | 2.1 ms | **4.3 倍** |
| 目标点绘制 | 1.5 ms | 0.1 ms | 15 倍 |
| 探测全量重算 | 4.0 ms | 1.4 ms | 2.9 倍 |

**回归保证**：`tools/test_perf.py` 把优化后的探测结论与**优化前的全量遍历
逐项对比**——206 个「观测者 × 目标」组合必须完全一致，否则测试失败。

**v3.3 的性能余量**：128×128 从来不是上限。`tools/synth_map.py` 能把中型想定
平铺成任意尺寸的**合成大地图**（临时生成，不必往仓库里塞几 MB 地图 JSON），
`python tools/perf.py big256` 即可在 256×256 / 412 个单位上实测：

| 指标 | 128×128（103 单位） | 256×256（412 单位） |
|---|---|---|
| 整帧渲染 | 2.7 ms | 3.2 ms |
| 地形缓存 | 4.9 MB / 48 块 | 6.8 MB / 66 块 |
| 探测全量重算 | 2.1 ms | 10.7 ms |

256×256 原本是 6.5 ms，压到 3.2 ms 靠两处小改动：

- **补给线整层缓存**——虚线是静态的（没有流动动画），只在单位位置、补给分配、
  缩放平移或配色变化时重画，其余帧直接 blit 那张层；
- **特效层空场跳过 + 脏矩形清除**——没有特效时直接返回（省掉一次全屏清空），
  有特效时只擦上一帧真正画过的那几块。一次爆炸只占几十像素，
  擦整屏相当于为了关一盏灯把整栋楼的电闸拉了。

这两处都属于「缓存必须能被正确判废」的那一类：补给线缓存的签名里放了
`id(state.map)` 与主题 id——换图或换肤后坐标与配色都变了，而「谁在哪、
挂在谁名下」可能一模一样，漏掉就会 blit 出一层属于上一局的旧线。

`tools/test_perf.py` 把 256×256 的四条线写成了断言（渲染耗时、缓存字节、
缓存块数、探测耗时），渲染那条要求「< 4ms **或** < 2.2× 中型图」二者其一——
只卡绝对值的测试会随 CI 机器的快慢随机变红。

## 11. 战术指南


### 11.1 开局三件事

1. **看目标点价值**：战役态势页列出每个点的每回合收益。高价值点值得重兵。
2. **确认基地位置**：机场决定航空兵能飞多远；机场被打掉，你的空军就废了。
3. **决定雷达开关**：开局雷达全开很舒服，但一旦对方有反辐射导弹，就是活靶子。

### 11.2 侦察—打击链的正确用法

- **不要用战斗机去搜索**。让预警机/无人机前出提供跟踪诸元，战斗机在后方待命（信火一体）。
- **反辐射导弹打雷达**：对方雷达开机时是固定靶；逼他关机，你就赢了一半态势感知。
- **压制机场而不是打飞机**：飞机停在机场上会被一起打；机场失能后对方航空兵直接失去补给。

### 11.3 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 坦克炮打散兵 | 伤害 ×0.87（过穿） | 用火炮/火箭炮面杀伤（≈×1.0，但省弹药） |
| 战机长时间滞空 | 燃油耗尽坠毁 | 算好返航油量，半箱就回 |
| 雷达全程开机 | 被反辐射导弹点杀 | 打完就关，或让诱饵替你开机 |
| 用昂贵导弹打诱饵 | 浪费弹药 | 先用便宜火力试探 |
| 目标点不驻守 | 被敌方一步反夺 | 留步兵/坦克常驻 |
| 远程导弹打完就不管 | 目标机动出包线 → 脱靶 | 优先打跑不动的目标（机场、防空阵地） |
| 用热像仪去找雷达诱饵 | 什么也看不到 | 雷达诱饵只能用雷达/电侦发现 |
| 在有工事的目标点上硬冲 | 触雷 + 高减伤 | 先用火炮削工事，再让步兵清障 |
| 让工兵去一线当步兵用 | 浪费构筑能力 | 工兵的价值是 2 级/次的工事与修复 |

### 12.3 界面字号与可读性

界面字号统一走 `ui/theme.py` 里的常量，不允许在绘制代码里写裸数字：

| 常量 | 基准值 | 用途 |
|---|---|---|
| `FS_TINY` | 10 | 角标、标签、单位缩写 |
| `FS_SMALL` | 11 | 次要说明、状态行 |
| `FS_BODY` | 12 | 正文 |
| `FS_LABEL` | 13 | 字段名 |
| `FS_TITLE` | 16 | 区块标题 |

**10 号是下限**——冒烟测试会用 AST 扫描所有 `draw_text` 调用，
一旦出现小于 `FS_TINY` 的字号，测试直接失败。这条约束挡住了
「改着改着就把字改小了」的慢性退化。

**等宽字体只用于纯数字 / 纯拉丁文本**。Consolas 之类的等宽字体没有
中文字形，用它渲染中文会出现方框或字距错乱。`T.render_text()` 会自动
检测字符串里的中文字符并降级到中文字体——所以「传感器 5.0」这类
中英混排的表格也不会出问题。

#### 12.3.1 三档字号缩放（v3.1.1）

上表里的值是**基准字号**（标准档）。设置面板 → 字号可在三档间即时切换：

| 档位 | 倍率 | 10 号基准 → 实际 | 适合 |
|---|---|---|---|
| **标准** | 1.00 | 10px | 默认 |
| **大** | 1.15 | 12px | 普通高分屏 / 笔记本 |
| **特大** | 1.30 | 13px | 投影、远距离观看、低视力 |

只放大文字是不够的——字号一变，行高、控件高度、面板宽度全都要跟着变，
否则文字会顶出容器、行与行互相压住。所以界面代码写的仍是**基准值**，
由下面四个函数换算到当前档位：

| 函数 | 作用 |
|---|---|
| `T.px(size)` | 基准字号 → 当前档位像素字号（下限 9px） |
| `T.m(base)` | 基准度量（行高 / 控件高 / 内边距）→ 当前档位 |
| `T.lh(size)` | 一行文字占的高度（含行距），排版累加 `y` 时用它 |
| `T.ellipsize(s, size, w)` | 按**像素**把文字截到给定宽度，超出部分用 `…` 收尾 |

`render_text` / `text_width` / `wrap_text` 内部统一过 `px()`，所以
「量出来多宽」和「画出来多宽」永远不会分叉。标准档下 `px()` 与 `m()`
原样返回，默认玩家的界面与旧版逐像素相同。

> 为什么倍率是 1.15 / 1.30：1.15 刚好让 11 号字落到 13 号（常见的舒适正文），
> 1.30 让 10 号角标过 13 号——再大就会在 1500×920 的窗口里挤不下侧栏。

#### 12.3.2 色盲形状标识

红绿是最容易混淆的一对（红绿色盲约占男性 8%）。色盲主题已经把敌方换成
琥珀 / 金黄，但那仍然是「靠颜色」——灰度截图或更极端的色觉条件下就没了。
形状标识给棋子加两处**不依赖色相**的信息：

| 信息 | 编码方式 | 灰度下怎么看 |
|---|---|---|
| **敌我** | 敌方棋子右上角**切掉一个三角**，我方是完整圆角矩形 | 看轮廓：缺角 = 敌方 |
| **兵种类别** | 左下角 7 种家族角标 | 方块=装甲 / 圆点=步兵 / 上三角=炮兵 / 下三角=防空 / 菱形=航空 / 圆环=舰船 / 十字=支援 |

角标之所以只分 7 个家族而不是 25 个兵种：棋子只有 30 来个像素，
25 种形状分不清。具体是哪一件装备，看棋子中央的兵种图标（它有 25 种
各自不同的图形）。

三档开关：

| 档位 | 行为 |
|---|---|
| **自动**（默认） | 只在色盲主题（蓝黄 / 蓝青）下启用——形状会占掉棋子上紧张的几个像素，普通主题下多数玩家不需要 |
| **开** | 任何主题下都画 |
| **关** | 不画 |

验收方式是可执行的：`tools/test_a11y.py` 直接对棋子表面取像素，
断言敌方右上角 `alpha=0`（真的被切掉）、我方该处不透明、左下角确实画了角标。
配套的 `tools/a11y_shots.py` 会把三档界面连灰度版一起出图到 `.shots/`，
供人工目视复核。

键名采用 pygame 的文本键名（`space` / `f1` / `a` / `1`），**跨平台可读、可手工编辑**。

> 配置文件损坏或字段非法时，游戏会**自动回退到默认键位并在状态栏提示**，不会崩溃也不会阻断启动。
> `prefs.seen_intro` 记录是否看过引导——它只影响主菜单是否高亮「快速上手」，不影响游戏进程。

## 14. 存档与读档


### 槽位

系统菜单（`F10`）提供 5 个槽位；`F5` / `F9` 快存快读 1 号槽。存档位于 `saves/slotN.json`。

### 保存内容

- 想定文件路径与武器库路径
- 全部单位：位置、耐久、机动点、备弹、燃油、雷达/干扰开关、压制、发射次数、工事等级、诱饵数量、诱饵生命周期
- 地块可变状态：归属、设施完整度、烟幕、目标点归属与价值
- **在飞弹药**（武器、发射点、目标、剩余飞行回合、齐射数）
- **对局随机流**（种子 + 已消耗次数 + 随机数发生器内部状态）
- 胜负点、卫星导航完整性、战损统计、日志尾部

### 读档行为

从想定文件重建地形与模板，再套用存档状态。因此**想定被修改后旧档仍可读取**（新增/删除的兵种会被跳过）。存档不保存 AI 中间态，读取时回到玩家回合。

随机流是**整份**保存的，不只是种子——只存种子还原不了「已经消耗了 N 次随机数」之后的序列（不同分布消耗的随机数个数不同）。所以读档后继续打，判定序列与不读档时完全一致。

存档里的任何字段损坏（缺键、类型不对、枚举越界、随机流状态尺寸不符）都只会让**这次读档**失败并在状态栏提示原因，不会让游戏退出。

### 旧存档迁移

存档版本号当前为 6。读到更低版本的档时，程序**逐版升级**（`core/save.py`
的 `MIGRATIONS` 链），升级过什么会写在状态栏和战报里，例如：

```
读取存档：第 3 回合 · 草原雷霆 · 存档从 v5 升级：旧档没有随机流，
读档后从种子重新起流（此前的判定序列无法重现）
```

三条约定：

- **迁移只发生在内存里**，不会擅自改写磁盘上的旧档——你仍然可以拿它去开旧版本程序；
- **链上缺一环就明确拒绝**（「缺少 v5→v6 的迁移」），不猜结构；
- **版本高于当前程序也拒绝**，并提示升级程序。

> 加新版本时：把 `SAVE_VERSION` 加一、在 `@_migration(N)` 下写一节迁移函数即可，
> 不要在 `_restore_game` 里到处写 `d.get(k, 默认值)` 兜底。`tools/test_save.py`
> 有一条「迁移链逐版连续」的断言，忘了写迁移会立刻失败。

### 15.1 导出方式

游戏中按 `F10` → 「**导出战报**」，或用 `core/report.py` 的接口直接调用。

输出目录（各平台用户数据目录）：

|---|---|
| Windows | `%LOCALAPPDATA%\BlockWargame\reports\` |

| Linux | `~/.local/share/blockwargame/reports/` |

文件名形如 `草原雷霆-20261102-153000.md`（想定名 + 时间戳）。

### 15.2 战报结构（Markdown）

| 章节 | 内容 |
|---|---|
| 一、作战结果 | 胜负点、战损、残余兵力、卫导完好度、结论 |
| 二、初始编制 | 双方每个单位的兵种、作战域、装甲、传感器、主要武器 |
| 三、作战统计 | 发射 / 命中 / 击毁 / 被拦截 / 未命中 / 机动 / 探测事件数与命中率 |
| 四、逐回合流水 | 按回合分组，标注行动方与事件类型（情报 / 交战 / 探测 / 电子战 / 机动 / 系统 / 战果） |
| 五、交战明细 | 每次交战的完整经过（表格形式） |

另有纯文本版本（`build_text()`），用于贴进邮件或聊天窗口，带等宽对齐。

### 15.3 用途

- **复盘**：查"那发炮弹为什么没打中"——逐回合流水里有完整的开火、拦截与毁伤记录；
- **想定调参**：导出多局战报对比命中率与拦截率，判断改动是否让某方变强；
- **分享**：Markdown 可直接贴进 GitHub Issue 或论坛。

> 战报只做**统计与整理**，不参与任何规则结算，也不会影响游戏状态。

| L4 | 无 NaN / 负血量 |
| L5 | 在飞弹药最终结算 |
| L6 | 位置合法（陆上单位不入海，两栖单位除外） |
| L7 | 存档往返一致 |
| L8 | 胜负点不减 |
| L9 | 阵亡单位不再行动 |
| L10 | 探测等级合法 |
| L11 | 工事等级合法（0–3，海域不得有工事） |
| L12 | 战报可生成且结构完整 |
| L13 | 对手视角评估不抛异常、概率落在合法区间 |

| L15 | 补给线一致：源可用、在半径内、承载力不超限 |

| L22 | 动画轨道可投递事件（表现层不参与规则） |
| L23 | 战斗统计一致（命中 ≤ 开火、击毁 ≤ 命中） |
| L24 | 胜负点曲线单调不减 |
| L25 | 内置中英词条键集合一致（8 语言磁盘包另由 `tools/lang_check.py` 校验） |

默认检查三张想定：`strait_shield`、`steppe_thunder`、`training_ground`。

### `python tools/test_units.py [--trace]`

**规则层单元测试**（v3.3）。与上面那些「跑一局看结论」的自检互补：
这一层不推进回合、不建战场，只给规则函数喂**刁钻的输入**，断言它按定义回答。

覆盖九类：骰子、几何与视线、电子战、探测、射击剖面、防空网、
设施与后勤、机动规则、寻路。用例用 `@case(group, *targets)` 声明
自己覆盖了「关键纯函数清单」（`TARGETS`）里的哪几项，跑完报告清单覆盖率：

```
关键纯函数覆盖
  core.dice         2/ 2
  core.geo          6/ 6
  ...
  合计 40/40（100.0%）
```

清单里有一项没被任何用例认领，脚本就失败——这比行覆盖率更能反映
「规则层的每个决定点都被人盯过」。新增机制时把新函数加进 `TARGETS`，
否则会立刻提示「有东西没测」。

需要真实行覆盖时加 `--trace`（标准库 `trace`，不依赖 pytest / coverage），
输出 `core/` 各模块被执行的行数占比。

> **三条给测试作者的经验**（都踩过）：
> ① 手造的单位 `uid` 必须互不相同——态势表按 uid 做键，全为 0 会互相顶掉；
> ② 改完地形要 `map_epoch += 1`，否则读到的是改之前的距离场；
> ③ 直接构造 `GameState` 要填全规则函数会读的字段，漏一个就是 `AttributeError`。

### `python tools/test_debt.py`

**技术债守卫**（v3.3.1）。四条原本靠「约定」维持的失效机制，现在都改成了
「写入即留痕」；这个脚本守的就是它们：

| 机制 | 曾经的约定 | 现在 |
|---|---|---|
| 随机流 | 调 `rules.roll` / `jitter` 要记得传 `rng`，忘了就静默退回全局 `random`（不受对局种子控制） | 兜底会计数（`dice.FALLBACK_CALLS`），严格模式直接抛 `RuntimeError`；`diag` 的 L26 要求一局跑完计数仍为 0 |
| 位置索引 | 改 `unit.x/y` 后要记得调 `invalidate_pos_index()` | 坐标或存活状态一被写入，`model.pos_epoch()` 就 +1，`units_at()` 自己重建 |
| 地块索引 | 改目标点 / 工事 / 设施后要记得 `map_epoch += 1` | 相关字段一被写入，`model.tile_epoch()` 就 +1，渲染层索引自己重建 |
| 探测缓存 | 指纹没覆盖模板，模组换雷达后沿用旧结论 | 指纹含模板身份与传感器几何，换模板即作废 |

断言**故意不调用任何失效函数**——那正是被测的东西。谁把机制改回约定，
这里就会红。

### `python tools/perf.py [基准名]`

**性能基准**（口径见 §9.6）。不带参数跑默认场景（128×128 大型想定），
`big256`（也接受 `big` / `256`）则临时合成一张 256×256 地图再跑。
输出整帧渲染、地形缓存占用与探测全量重算三项；
`tools/synth_map.py` 是它背后的合成器，把中型想定平铺成指定尺寸，
所以仓库里不需要存大地图 JSON。

`python tools/test_perf.py` 是同一套指标**带闸门**的版本——超标即 CI 失败，
并要求优化后的探测结论与全量遍历逐项一致。

### `python tools/check_layout.py`

**UI 布局自检**。遍历界面上所有可点击元素，检查三类问题：

| 问题 | 症状 |
|---|---|
| **元素重叠** | 两个按钮叠在一起——后绘制的会拦截点击，导致另一个「点不了」 |
| **越界** | 元素超出窗口边界（最小窗口尺寸下最常见） |
| **遮挡** | 关键按钮被其它元素覆盖，点击无效 |

## 18. 社区想定包与战役


### 18.1 想定包（.bwscn）

一个 `.bwscn` 文件就是一份可分发的想定包——本质是 zip：

```
manifest.json          清单：名称、作者、难度、标签、包含的地图、逐文件 sha256
maps/*.json            想定地图
armory.json            可选：武器库覆盖（仅含包内用到的新兵种）
```

清单自 v3.2 起是**格式 2**：多了 `game_version`（制作版本）与 `files`
（每个文件的 sha256）。导入前逐个核对，改坏一个字节就会被指出来；
版本高低三种情况的提示语见 [第 6.8 节](#68-分享与版本兼容)。
旧格式（没有 `files`）的包照样能导入。

**导出**：两种入口，产物都放进用户数据目录的 `packages/`：
- 对局中按 `F10` 打开系统菜单 →「导出想定包」；
- 编辑器顶栏 →「导出想定包」——会**先自动保存地图**再打包，
  并把编辑后的武器库一并打进包里（别人导入后能直接玩）。

**导入**：**主菜单 →「导入想定」**（在「选择想定」标题右侧）。
弹出的浮层会扫描 `packages/` 目录，列出全部 `.bwscn` 文件，
每条显示包名、作者、想定数量、文件大小与修改时间——
自己挑要装的那个，点击即导入。

> 导入的想定装进**用户数据目录的 `maps/`**，而不是安装目录——
> 冻结版的安装目录可能只写不了。扫描想定时两个目录都会看，
> 同名文件以**用户目录**为准。

**主菜单想定列表**：卡片按网格排列，超出可视高度时可纵向滚动
（滚轮，或 ↑↓ 键移动选中项），右下角显示「当前/总数」，
右侧有滚动条。想定再多也能逐屏翻看。

> 想定包目录位于用户数据目录（Windows 为 `%LOCALAPPDATA%\BlockWargame\packages`，
> Linux/macOS 为 `~/.local/share/BlockWargame/packages`）。

- 导入时按 ID 合并武器库——**已存在的兵种不会被覆盖**，只新增包内独有的；
- 导入的想定直接出现在主菜单的想定列表里，可以立即开始游戏；
- 损坏的包会给出可读报错，不会让程序崩溃。

### 18.2 战役定义（`data/campaigns/*.json`）

```json
{
  "id": "eastern_front",
  "name": "东线连续作战",
  "description": "连续三场陆战，检验部队能否持续作战",
  "author": "hamfreebird",
  "difficulty": "normal",
  "steps": [
    {"map": "steppe_thunder", "title": "第一战 · 草原雷霆",
     "brief": "红方装甲集群正在集结……",
     "objective": "守住河谷要点",
     "difficulty": 1, "carryover": "all"},
    {"map": "training_ground", "title": "第二战 · 训练场",
     "difficulty": 3, "carryover": "veterans"}
  ]
}
```

| 字段 | 说明 |
|---|---|
| `steps` | 关卡列表，每项指定 `map`（想定 ID 或文件名）与标题 |
| `steps[].brief` | 本关开场简报（可省略） |
| `steps[].objective` | 本关任务目标（可省略） |
| `steps[].difficulty` | 本关难度 1–4（v2.1 新增，默认 2）。难度越高红方起始越占优 |
| `steps[].carryover` | 跨关继承策略（v2.1 新增，默认 `all`）：`all` 全部 / `veterans` 只继承精锐 / `none` 不继承 |

战役里的「继承策略」是**逐关**生效的——可以第一关全继承、
第二关只带精锐、第三关完全独立。难度也是逐关的，因此整场战役的
难度曲线可以自由编排（编辑器里有可视化曲线图）。

> 旧战役文件不带 `difficulty` / `carryover` 也能正常加载——
> 会自动回落到默认值（难度 2、全继承）。

**战役玩法**：主菜单 →「战役」按钮选择战役 → 逐关推进。
每关胜利后结算界面会显示战役进度，点击「进入下一关」继续；
幸存部队会作为增援部署到下一关，胜负点累计到战役总分。

战役进度保存在用户数据目录，中途退出可继续。

### 18.3 单位图标包（`data/icon_packs/<id>/`）

图标包是一个目录，含一份清单 `pack.json` 与若干 PNG：

```jsonc
{
  "id": "my_pack",
  "name": "我的图标包",
  "author": "someone",
  "version": 1,
  "icons": {
    "mbt": "mbt.png",
    "ifv": "ifv.png",
    "fighter": "fighter.png"
  }
}
```

| 字段 | 说明 |
|---|---|
| `icons` | 兵种类 → PNG 文件名。键取自 `UnitClass`（`mbt` / `fighter` / `sam` / `uav` …） |
| `name` | 设置面板里显示的名字 |
| `author` | 作者（可选） |

**约定**：

- PNG 用**白色**线条绘制在透明背景上，运行时按阵营着色；
- 建议正方形，程序会按需缩放（推荐 64×64）；
- 没覆盖到的兵种回退到内置矢量图形，因此包不必完整；
- 放在**用户数据目录**的 `icon_packs/` 下即可被识别（优先级高于安装目录）。

内置包 `data/icon_packs/default/` 由 `python tools/make_icon_pack.py`
从矢量图形烘焙生成，可直接复制改名做成自己的包。

## 19. 已知限制


- 卫星轨道为匀速直线地面轨迹，未建模轨道倾角、变轨与真实的过顶几何；反卫星按常数距离交战。
- 诱饵按频段区分（雷达/红外/光学），但未模拟同一诱饵随距离变化的信号衰减差异。
- 工事有等级、迟滞、雷场伤害、摧毁与修复，但未区分堑壕/掩体/雷场的不同构筑时间。
- 中段反导只有一次窗口，未模拟多段拦截、动能拦截与碎片杀伤。
- 航空兵油量是抽象值（不区分任务剖面与副油箱，剖面只影响油耗倍率）。
- 弹道导弹只区分「中段 / 末段」两段，未模拟助推段与再入弹道几何。
- 烟幕为格子级遮蔽，未模拟随风扩散与地形遮蔽的叠加。
- AI 是启发式规划，不做多回合搜索；它在防守关键点与集中火力上仍不如熟练玩家。
- 战役模式目前只支持「胜利后进入下一关」，战败即结束；未实现战役内的分支剧情。
- 设施被占领后立即易主，不建模破坏/修复的中间状态。
- 想定包导入时不校验版本兼容性——社区包若依赖更新的字段可能表现异常。

## 附录：常见问题

**Q：为什么我的坦克打不到斜对角的敌人？**
A：射程判定给了 0.45 格容差，射程 ≥1.0 的武器都能打到 8 个相邻格。如果仍打不到，看面板给出的原因（多半是「情报不足」或「无通视」）。

**Q：为什么飞机刚起飞就坠毁了？**
A：燃油耗尽。检查是否有可用机场（机场失能或被夺占会导致无法补给），以及出击距离是否超过续航。

**Q：为什么反辐射导弹打不出去？**
A：目标雷达关机了。ARM 只能锁定正在辐射的目标——这也是它最有效的用法：逼对方关机。

**Q：为什么打不动据守的步兵？**
A：工事（最高 Ⅱ 级）+ 城区可以提供很高减伤，而且直瞄火力对步兵只有 0.68 倍伤害。换火炮或火箭炮（1.30 倍）。

**Q：为什么胜负点落后却歼敌更多？**
A：胜负点只看目标点控制。歼灭敌军不直接得分，但能削弱对方夺控能力——最终还是要有人站上目标点。

**Q：编辑器改完没生效？**
A：武器库改动需要点「保存武器库」；地图改动需要「保存」并通过「校验」；已开始的对局需要重新开局。
